# Solo-Lab 使用说明

## 插件装好以后是什么样子

在一个项目目录里初始化以后，Claude 桌面应用的侧栏里多出一个以项目命名的分区，里面每个会话是一个角色：顶层是七个序列的 +2，+1 嵌在 +2 下面，+0 嵌在 +1 下面。七个序列（产品、算法、工程、基础设施、质量、项目管理、外联）各有 +2、+1、+0 三级，你是 +3。

你平时只和一个会话说话：项目管理 +2，也就是入口 `PMO-p2-01`。你把信息和指示告诉入口，它按路由决策表把事情分给其余六个序列的 +2，各序列再逐级委托给 +1、+0。特殊情况下你也可以直接点开某个 +2 的会话交代。交接写成三种任务包：需求包、交付包、决策包。书记员把它们登记进飞书项目、上传到飞书文档。

研究的主线是研究任务。一条研究任务回答一个问题，在飞书项目里一步一步往前走，每一步由一个序列负责。有判据、要下结论的走验证流程，你每条签两次字；还没有假设、只为找方向的走试探流程。

你每天做两件事：看决策队列，替 agent 拍板它们超出授权的事；研究任务走到哪一步，就找那一步负责序列的 +2 深谈。

运行方式只有一种，叫会话池：每个角色是侧栏里的一个会话，你能看到每个会话在做什么，委托和交付都是会话之间的消息，留在各自的记录里。它只支持 Claude Desktop（Claude 桌面应用）。终端里的 `claude` 用不了，Codex 暂不支持。

插件只覆盖你和 agent 之间的协作。导师和合作人不用飞书，给他们的材料由外联序列准备，你签字后自己转交。

## 装之前准备好这些

要安装的第三方软件有四样：Claude Desktop、lark-cli、meegle、Python。

| 要准备的 | 说明 |
| --- | --- |
| Claude Desktop | Claude 桌面应用，必须装。会话池用它开会话、发消息，侧栏里的三层排列也靠它；Claude Code 2.1.219 以上。Codex 暂不支持 |
| 飞书账号 | 能登录飞书项目和知识库，能在飞书项目里用模板创建空间。建空间的人就是空间管理员 |
| lark-cli | 1.0.96 以上，配置好应用。用户身份登录失效没关系，初始化时会给你二维码 |
| meegle | 1.0.23 以上。登录失效同样在初始化时扫码；诊断上报建议关闭 |
| Python | 3.12，命令行里要有 `python3.12`（比如 `brew install python@3.12`）。插件的 hook 和脚本命令都写这个名字，不动系统自带的 `python3`；脚本只用标准库 |
| 飞书项目模板 | 不用自己搭。插件的约定文件里记着一个参考模板的链接，初始化时照它创建项目空间 |

## 第一次：安装插件

插件装在用户级，装一次，所有项目都能用。

```bash
claude plugin marketplace add <本仓库的路径或地址>
```

```bash
claude plugin install solo-lab@solo-lab
```

装好后多出八个技能：`solo-lab:setup`、`solo-lab:charter`、`solo-lab:spec`、`solo-lab:packages`、`solo-lab:ledger`、`solo-lab:entry`、`solo-lab:space-read`、`solo-lab:space-bind`。插件本身不带任何 hook：hook 只在初始化过的项目里、写在项目设置里，普通项目不受影响。

## 每个项目一次：初始化

你做一件事：在 Claude 桌面应用里选中项目目录，新开一个会话，模型选 fable（默认配置里入口用 fable，会话的模型不能高于开它的会话，这个会话不是 fable 时入口会被降档），权限模式选 auto，说一句：

```text
用 solo-lab 初始化这个目录
```

最好顺带说项目名和一句话描述，比如“项目名 code-opt，做面向代码的约束优化器”。项目名也是飞书项目空间、知识空间的名字和会话标题的前缀。只说了空间名的，比如“飞书项目空间沿用 ThesisP1”，项目名就是这个空间名。两样都没说，初始化会话先问你一句项目叫什么，不拿目录名代替。

项目目录用空目录。目录里原来就有 `CLAUDE.md` 或 `.claude/settings.json` 的，初始化不覆盖也不合并，要你手工合并，见常见问题。

第二件只在会话池开得比默认大时才有：开池开到一半，它会停下来请你回一句“继续开池”。应用有个上限，你每发一条消息，会话自己最多再开出 10 个会话；默认的会话池这样开出 8 个，一轮开完，不用回话。

这个会话叫初始化会话。它调用 `solo-lab:setup`，按下面的顺序做完。一路顺利的话，中途只在第 6 步停下来一次，等你回那句话：

1. 先告诉你将要新建什么：两个空间的名字、知识库节点数、会话数、项目目录里的文件，还有中途要你做的事。这份清单由脚本照你的设置算出来，它发来的第一条消息应该就是这份清单；没有的话，对它说“把将要新建的清单发给我”。它不等你回复，接着开始计时，做前置检查。
2. 命令行登录失效的，发起登录，把二维码和链接给你。
3. 写任务文件，生成项目文件：21 份角色定义、项目权限和 hook、`CLAUDE.md`、`org/`、`packages/`、`inbox/`、`spec/`，以及插件脚本和规则的副本。
4. 按项目名找飞书项目空间。没有就打开模板链接，用模板创建。
5. 读空间结构，把插件的约定绑定到这个空间；按项目名找知识空间，没有就新建。
6. 开出会话池，默认 15 个会话。初始化会话分 2 批开七个 +2，+2 开 +1，+1 开 +0；产品、算法、外联只开 +2。分批是因为应用限制会话自己开出的会话同时最多 5 个在跑。你每发一条消息，这样开出的会话最多 10 个：任务文件把池开大了（比如五个序列都开 +1 和 +0，共 19 个）就要分两轮，第 1 轮开完它请你回一句“继续开池”，再开剩下的。书记员在入口下面第三层，它在知识空间里建 21 个节点，登记一条最小的研究任务。
7. 在项目目录的 `.env` 里写飞书项目和知识空间的两条链接。
8. 回读飞书，做四层检查：本地配置、飞书、会话、首条研究任务。
9. 结束计时，向你交接。

过程中可能要你动手的只有这几种情况：

- **扫码。** lark-cli 或 meegle 的登录失效时，每个扫一次。会话不接触密码、验证码和令牌。
- **点确认框。** 浏览器的站点许可或电脑控制的应用授权，目录信任，默认权限模式下的命令确认和移动会话的确认。
- **用模板创建空间。** 会话的浏览器工具都用不了时，它把模板链接和空间名给你，请你自己创建。
- **手工开会话。** 初始化会话开不了会话时走回退档：你在项目目录手工建 7 个会话，各粘贴它给的一句话。

它会停下来问你的情况：同名的项目空间或知识空间不止一个；同名的空间已经有了、但和插件的约定对不上；目录里原来就有 `CLAUDE.md` 或 `.claude/settings.json` 这样的同名文件；页面上出现付费、升级或权限申请的弹窗。它只新建，不删除、不覆盖、不改已有的对象。

交接时它告诉你：四层检查的结果，新建和沿用了什么，耗时（飞书操作这一类对照 300 秒的指标，只是指标），和默认不一样的地方，还空着的设置，以及从哪个会话开始。然后请你做两件事：打开 `org/decisions.md`，开头列着插件定下的几处安排，逐条确认或推翻；点一下 `.env` 里的两条链接，看能不能打开。

初始化会话留着别归档，它以后是你自己的会话：重新登录、检查部署、升级插件都在它里面做。

### 默认值

| 项 | 默认值 | 想改 |
| --- | --- | --- |
| 项目名 | 开场那句话里说的名字；只说了空间名就用空间名；都没说，初始化会话先问你 | 开场那句话里说 |
| 飞书项目空间、知识空间的名字 | 等于项目名 | 开场时说，或改任务文件的 `feishu.meegle_space`、`feishu.wiki_space`；知识空间和别的同名时，另写 `feishu.wiki_space_id` 按编号指定 |
| 模板 | 约定文件里的参考模板链接 | 任务文件的 `feishu.template_url` |
| 会话池 | 15 个：七个 +2、路由、书记员，工程、基础设施、质量各一个 +1 和一个 +0。产品、算法、外联只开 +2 | 任务文件的 `pool`。只开了 +2 的序列有活时，它的 +2 会提补位请求，你在它的会话里点一下启动卡，或者说一句“补位” |
| 模型 | 入口（项目管理 +2）用 fable，其余会话都用 opus | 任务文件的 `models`。会话的模型不能高于开它的会话（+2 看初始化会话，+1 看 +2，+0 看 +1），高出的不生效。初始化最后会回读每个会话实际用的模型和窗口，不符的列在交接里 |
| 上下文窗口 | 插件不设，跟账号和模型的默认值 | 在终端里往项目的 `.claude/settings.local.json` 写 `autoCompactWindow`，退出并重开桌面应用后生效 |
| 会话标题 | `[<飞书项目空间名>] <会话名>`，都归入同名的侧栏分区 | 任务文件的 `pool.label` |
| 可写路径、只读路径 | 空着 | 设计阶段定下后写进任务文件的 `editable_paths`、`protected_paths` |

任务文件是项目目录里的 `solo-lab.task.json`，只放脚本和 hook 要用的几项，格式见插件的 `scaffold/task.example.json`。要改设置，改它，再请初始化会话重跑 `init --apply`。`spec/task.json` 是它的副本，不手改。

每一步的命令、输出和失败时的处理写在技能 `solo-lab:setup` 里。

## 研究任务和五类工作项

### 五类工作项

飞书项目里有五类工作项，都走节点流程，每个流程最后一步是书记员确认的“归档”。

| 类型 | 用途 | 流程 | 主文档 |
| --- | --- | --- | --- |
| 研究任务 | 主线。一个空间可以有多条，后一条用“来源工作项”指向前一条 | 验证或试探，新建时选 | 研究任务单 |
| 同序列需求 | 序列内委托和交付，发出方验收 | 开工、执行、验收、归档 | 需求包 |
| 跨序列需求 | 序列之间 +2 对 +2 的请求 | 提出、接单、执行、验收、归档 | 需求包 |
| 决策 | 你拍板和签字 | 决定、归档 | 决策包 |
| 反馈 | 导师和你的反馈 | 解析、归档 | 原话所在的文档 |

一份需求包、决策包或研究任务单对应一条工作项。交付包是对某条需求的答复，挂在那条需求下面，不另建工作项。

节点流程有这几条规矩：

- 每一步有一个负责方，完成时有必填的字段。产出齐了，由这一步的负责方请书记员确认节点。
- 有哪些步骤、每一步谁负责、必填什么，以飞书空间为准，脚本现读。任何会话都能问：`python3.12 -I .claude/solo-lab/bin/ledger.py next <工作项 ID>`。
- 退回就是回滚节点，必须写原因。验收不通过，发出方请书记员回滚到“执行”；跨序列需求不接，承接方回滚到“提出”。
- 阻塞记在工作项的两个字段里：阻塞原因、阻塞开始日期。没有“阻塞”这个状态，走到哪一步和卡没卡住分开记。
- 终止工作项命令行做不了，要你在网页上做。终止以后对入口说一声，它用 `pool.py show --prune` 把这些工作项从会话池的认领表里清掉。

### 研究任务的两个流程

新建研究任务时选流程。下面是参考模板里的两个流程，你的空间以 `org/phases.md` 为准。

**验证流程**用于有判据、要下结论的问题。一条验证任务只回答一个能被一次冻结的评测回答的问题，多个问题开多条。

| 步 | 节点 | 负责 | 配合 | 完成时必填 |
| --- | --- | --- | --- | --- |
| 1 | 确定目标 | 产品 +2 | | 成功标准 |
| 2 | 准备上下文 | 算法 +2 | | 上下文文档 |
| 3 | 准备 PRD 和 Eval Set | 产品 +2 | 质量：建并冻结 Eval Set，写评测协议 | 需求文档、评测集版本 |
| 4 | 确定假设条件 | 算法 +2 | 质量：核对阈值 | 规格、规格版本、总预算、波动估计、假设签字 |
| 5 | 设计实验方案 | 算法 +2 | | 实验方案、实验轮次 |
| 6 | 搭建实验平台 | 基础设施 +2 | | 冒烟运行 ID |
| 7 | 跑 Eval Set | 工程 +2 | 质量：出正式分 | 运行 ID |
| 8 | 得出结论 | 算法 +2 | | 结论、结论文档 |
| 9 | 下一步讨论 | 项目管理 +2 | | 下一步签字 |
| | 归档 | 书记员 | | |

配合方的活，由负责这一步的 +2 发跨序列的需求包去请。结论三选一：成立、不成立、无法判定。

**试探流程**用于还没有假设的时候：读代码、小规模试跑、看错误样例。它有四步：定方向、试探、提出假设、归档，都由开这条任务的那个 +2 负责。它不冻结、不签字、不出正式分，产出是值得验证的假设；要下结论，另开一条验证任务。

### 每条验证任务签两次字

- **第 4 步，花算力之前。** 签的是假设和阈值。签字以后，前四步的产出一起冻结：目标和成功标准、需求文档、评测集版本、含假设和阈值的规格、总预算。
- **第 9 步，定下一步。**

签字走决策：负责那一步的 +2 写决策包进决策队列，你批准后，决策工作项的 ID 填进“假设签字”或“下一步签字”字段。书记员确认节点前，脚本核对这条决策：类型是决策，已经决定，签字结果是批准，属于这条研究任务，并且是在任务走到这一步之后决定的。一条决策只用一次。

冻结以后要改，只有两条路，都要你决定：退回到第 4 步或之前，改完重新签字；或者结束这条任务，另开一条。回退也由你决定：退到哪一步、为什么，写成决策包，你批准后书记员回滚节点。退回重走以后，被退回各步的字段只留新一轮的值，比如“运行 ID”“实验轮次”；上一轮的值在工作项的操作记录里。

### 把关靠测量

没有送审这一环。把关靠管住测量：

- Eval Set 和阈值在出结果之前定下，第 4 步签字后冻结。
- 正式分数只由质量序列在冻结的 Eval Set 上跑出。实验方自己跑的是开发分，用来调试，不写进结论。
- 结论只对照签过字的阈值。“不成立”和“无法判定”都是合法结论。
- 所有运行都进台账，失败的也算。

一个项目的第一条验证任务定为“复现并测量基线”，成功标准写成和公开数字相差多少以内，后面的任务拿它的结果定阈值。

## 日常使用

### 和入口说话

在侧栏分区里点开 `[<分区名>] PMO-p2-01`，这个会话就是入口。

初始化时已经登记了一条最小的研究任务，内容只有项目名和一句话描述。第一件事是把它补全：对入口说“立项”，入口用 `solo-lab:charter` 访谈你，写出修订的研究任务单，请书记员换成这条研究任务的主文档。工作项不变，还停在第一步“确定目标”。以后要开新的研究任务，对入口说“开一条研究任务”，入口问清交给哪个序列，由那个序列的 +2 访谈你。

之后你说的每句话、转来的每条消息，入口都先过路由决策表：

| 你说的 | 入口怎么办 |
| --- | --- |
| 带工作项 ID 或会话名的，比如“#2101 的访谈记录补上了” | 在那个工作项下留评论，交给负责的会话接着做 |
| 没带 ID 的补充信息，比如“导师想看和人工基线的对比” | 交路由对照进行中工作项的名称、字段和状态包找归属；只对上一项就转过去，对上多项或一项也没有，回来问你 |
| 新任务 | 先问你要不要做、交给哪个序列；你拍板后由那个序列的 +2 写需求包 |
| 要你拍板的事 | 建成“待决定”的决策，进决策队列 |
| 导师或你的反馈 | 请书记员登记成反馈，入口解析出类别和处理说明，拆出的事项经你确认后交对应序列。反馈的“所属研究任务”是选填：研究任务都归档了，或者和哪条都无关，就空着 |
| “出本周周报” | 给外联 +2 发跨序列的需求包；材料写好后由你签字 |

说话时带上工作项 ID 或会话名，路由就不用猜。

### 看决策队列

入口只在两个时刻把决策交给你：

- 一条决策登记进决策队列时，入口在那一轮的状态里提一次，写事项、一句话的选项、执行方、要你亲手做的事（包头写了的话）和主文档的飞书链接。紧急程度为“插队”的，入口在登记那一轮还可以直接问你一次。
- 你在入口会话里主动发起讨论时，入口先回答你，再把待决定的决策和等你执行的决策全部附在末尾，每条一行：状态、事项、紧急程度、回复期限、执行方、要你亲手做的事、链接，不管之前提没提过。主动发起是指距你在入口会话的上一条消息 30 分钟以上，或者是第一条。

其余时候不再提：决策改版、临近截止都不提醒，也没有每日汇总；你问起时入口照实回答。

决策包和研究任务单，入口给你的是飞书文档的链接，不是本地文件。你在文档上批注，批完告诉入口；入口把批注读出来转给作者，作者改出下一版，书记员原位修订，文档链接不变。批注只是讨论的一种方式，插件不跟踪哪条处理了没有；文档修订以后，旧段落上的批注不再显示在原来的位置。你想要本地文件，或者想直接在对话里说，说一声就行。

每件决策附选项、代价和建议。你在入口会话里拍板，书记员确认决策的“决定”这一步，再通知受影响的会话。

到期按登记时间算，包头的“回复期限”只作参考，到了不触发任何动作。可逆的决策登记满到期时长（默认 24 小时，写在 `org/decisions.md` 插件那一节，你可以改）还没定，书记员按包头的“到期默认动作”记成决定，决定内容以“到期默认：”开头，执行方照这个选项办。不可逆的、执行方是你的、要你亲手做事的决策一直等你决定，不提醒截止，你来谈时它们排在清单最前；你定过一次、后来又回滚到待决定的决策也一样，不再走到期默认。决策待定期间，包里“冻结的动作”谁都不做，各会话只做选项中立的准备；hook 不拦这些动作，池会话每轮看到一行冻结提示，靠它们自己守住。决策登记以后、你定之前要改的，发出方写下一版，书记员原位换掉主文档开头（`docs.py revise`），文档链接不变；修订不推给你，你来谈时清单里显示新的版本号。

每条决策走三步：待决定、待执行、归档（已执行）；用 2.1.0 及以前的模板建的空间里，待执行叫“已决定”。你定了，书记员马上确认“决定”，决策进入待执行，书记员同时通知包头写的执行方，各会话就知道你选了哪个选项。执行方是你的，做完了在入口会话说一声，入口带着你的原话请书记员归档，书记员在评论里记下你做了什么；在那之前，你主动发起讨论时它照样在清单里，状态是“待执行”。执行方是会话的，书记员把决定内容发给它，它照决定执行完，马上请书记员归档，不在待执行里停留。只要有一个选项要你亲手做，包头的执行方就写你；你选了不用你动手的选项，告诉入口改由哪个会话执行，书记员确认“决定”时把执行方改成它（`workitem.py confirm --executor`），这条决策就不再列成等你执行。

在飞书里也看得到：用 2.2.0 的模板建的空间，空间置顶里有公开视图“待定决策”，列出待决定的决策和执行方是你、还没归档的决策，每行带执行方和要你亲手做的事，先按紧急程度、再按创建时间排，收藏一次就好找。视图只用来看，拍板仍在入口会话里说。

### 入口什么时候找你

入口主动告诉你的只有两类：决策（给主文档的飞书链接，执行方和要你亲手做的事一并写上）、里程碑（研究任务走完一步、出了结论）。各序列之间的接口问答不转述；收到【需拍板】，入口请发来的 +2 写成决策包，不直接转问你。

跨序列的需求不经入口转手：发起的 +2 把需求包交给路由（项目管理 +1）查重、登记，再直接委托对方的 +2，之后的接单、答复、交付、验收都在两个 +2 之间。路由记着谁在等谁，往来里出现改范围、改成功标准、改冻结项的内容，或者两边说法对不上，才报给入口。你问入口“这条跨序列需求走到哪了”，它查台账和路由的协调记录回答，比它亲手转每条消息时慢一拍。

被其他 agent 会话叫醒的轮次，你多半不在。这一种包括别的会话发来的消息、池会话开出的会话结束一轮时应用发来的回报、开会话时上级写的首轮。这些轮次里池会话面向你最多写一行状态：不提问，不标“等研究员回答”，不复述已经登记过的决策。hook 去掉收尾里的提问（一轮结束时应用画的提问框），拒绝 AskUserQuestion。唯一的例外是新登记的插队决策：入口在登记那一轮可以问你一次。

只要你动一下手、没有选项要挑的事，比如恢复集群连接、下载数据、连 VPN，会话不写决策包，记进“研究员任务清单”（`todo.py add`）：入口把它列在决策清单后面，你做完说一声，入口就划掉。hook 拦下只有你能跑的命令时，也让会话把完整命令记进这份清单。

建错的、不做了的工作项归档不了，脚本也终止不了，只能你在网页上处理。会话把它们记进清单里专门的一项。不管攒了几条，入口只当成一件事跟你说：“飞书项目里有 N 条工作项等你处理”，下面附每条的名称、原因和链接。会话不去查你处理了没有；你处理完告诉入口一声，它读一次台账，划掉确实已经终止或删除的，没处理的留着并告诉你还剩哪几条。

有选项要你挑、定下以后又要你亲手做的事，比如整理数据、挂 API、维护沙箱、开 Docker、调设置，写成决策：卡住的那个序列的 +2 写决策包，包头“执行方”写“研究员”，“研究员要做的事”一行写这条决策定下以后要你亲手做什么。每份决策包都有这两行：不用你亲手做什么的，执行方写执行这条决策的会话名，多半是发出方，“研究员要做的事”写“无”；执行方写会话的只收各序列的 +2、入口和路由。它和别的决策一样，登记时入口提一次，你主动发起讨论时列在清单里。卡住的工作项照旧记阻塞，阻塞原因写“等研究员：决策 #<ID>”，决策归档以后清掉。

### 直接找某个 +2

想和某个序列的 +2 深谈，或者有件事想直接交给它：在侧栏点开它的会话直接说。它会把自己标成“研究员在用”并告诉入口，这期间入口不委托它，新信息留在它的收件箱。结束前让它把谈定的事写成决策包交给入口。谈定的事没写进台账就不算数，因为别的会话看不到你们的对话。

### 写需求文档、评测协议、规格和实验方案

验证任务走到第 3、4、5 步时，找这一步负责序列的 +2 谈。它用 `solo-lab:spec` 先查代码库、评测脚本和数据，写出草稿，只把查不到的问题拿来问你。每条都标了来源：〔研究员确认〕、〔查到：…〕、〔推测，待确认〕，签字前你只需要核对标〔推测，待确认〕的条目。

| 步 | 文档 | 谁写 |
| --- | --- | --- |
| 3 | 需求文档 `spec/requirements.md` | 产品 +2 |
| 3 | Eval Set 和评测协议 `spec/eval-protocol.md` | 质量 +2，接产品 +2 的跨序列需求包 |
| 4 | 实验规格 `spec/spec.md`，含假设和阈值、波动估计 | 算法 +2 |
| 5 | 实验方案 | 算法 +2 |

文档写在本地。+2 请书记员确认这一步时，书记员把本地文件上传到研究任务单下面，链接填进研究任务的字段；签字前要你看的，会先传上去，链接写在决策包里。交给 +1 去查、去整理的产出，用它提交的交付包文档。

可写路径和只读路径要改的，会列在请你签字的决策包里。你同意后，在初始化会话里改任务文件、重跑 `init --apply`。

### 在飞书里给入口发消息

飞书私聊机器人的消息可以进入口。需要你在终端里启动监听，开着就行：

```bash
python3.12 -I .claude/solo-lab/bin/notify.py listen
```

消息落进 `inbox/feishu.jsonl`，入口下一轮对话时看到。监听只收你本人发给机器人的私聊，按消息 ID 去重；`feishu/ids.json` 里没有你的 open_id 时，它不会启动，免得谁私聊机器人都能进入口。没开监听时，把消息转述给入口也一样。

### 看进度

- 会话在做什么：侧栏里看，或者在入口会话的终端窗格里运行 `python3.12 -I .claude/solo-lab/bin/pool.py show --watch`。等你批准的、失败的、像是卡住的排在最前。
- 一件事走到哪一步：台账是正本。各角色用 `ledger.py` 的条件查询读台账：`queue`（决策队列）、`blocked`（阻塞）、`verifying`（待验收）、`open`（进行中的同序列需求）、`cross`（进行中的跨序列需求）、`tasks`（没归档的研究任务）、`recent`（近 7 天更新过的同序列需求）。
- 跨序列需求谈到哪了：`python3.12 -I .claude/solo-lab/bin/route.py cross` 列出最近 7 天有往来的各条和最近一句，后面写工作项 ID 就列出这一条的全部往来。它读本地的派发日志，日志只记每条消息的首行。
- 插件不配置视图。你想在飞书项目的网页上怎么看，自己在网页上设置，不影响插件。
- 文档：每个项目一个知识空间。研究任务单在“研究任务”节点下，各步的产出文档挂在它下面；同序列需求包按序列分节点，执行关系的需求包挂在它所属的下发需求包下面，交付包挂在它答复的那份包下面。办完归档的整棵子树移到“归档文档”下，链接不变。

## 会话池

**会话之间怎么交接。** 委托、交付、登记请求、需拍板都是消息，首行一个抬头，比如 `【委托 #2101】Alg-p2-01 → Alg-p1-01：需求包 <路径>`，正文在包文件里。委托前先用 `pool.py show --role <角色>` 找空闲的会话；没有就排队，工作项留在台账的“待开工”。收方的 hook 把收到的时间记进 `.claude/logs/dispatch.jsonl`；对不上派发图、没有登记回执的会提醒收方，但不拦。

**多开、恢复、换人。**

- 要多开会话：多开 +1，在那个序列 +2 的会话里说“补位”或“再开一个 alg-p1”；多开 +0，在它上面那个 +1 的会话里说“再开一个 alg-p0”。新会话在侧栏里嵌在开它的会话下面。你不说，会话不会自己开：它记一条补位请求，开那个角色的会话提一张启动卡，你到那个会话里点一下就开。你主动来入口会话谈时，入口先列等你的决策，再列研究员任务清单和还没处理的补位请求，补位请求写着启动卡在哪个会话里。
- 重启或电脑睡眠以后：对入口说“恢复”，它照 `pool.py show --recover` 的清单逐个续上，书记员先补完写到一半的登记。
- 补位请求不要了：告诉提请求的会话或入口，它用 `pool.py refill <角色> --count 0` 撤回。
- 某个会话丢了：先运行 `pool.py release <会话名>` 释放旧的认领，再请初始化会话把它重新开出来。
- 不要让会话去归档、清空或停止别的池会话。要收掉，由你本人在侧栏操作。归档一个会话，嵌在它下面的会话跟着一起归档：归档 +2 会带走本序列的 +1 和 +0，只想收掉 +2 时先在侧栏里把它下面的会话移到顶层（Detach to top level）。

**权限模式。** 全池和初始化会话用同一类。bypass 和其他模式之间，会话的消息双向被扣下，桌面端弹不出审批框，默认 5 分钟后丢弃；“每次询问”和 auto 是同一类，互相不扣。所以不要把池里某一个会话单独切到 bypass：命令被拦下时，会话会把它记进研究员任务清单，你到那个会话的窗口里说一句允许、说清是哪条命令，auto 模式会放行这一次，或者你自己在终端里跑。初始化会话用 auto 模式：这个模式下开池不用你点。

**登录过期。** 角色会话遇到登录过期会报给你。回到初始化会话说“重新登录”，它发起登录，你扫码。

**升级插件。** 请初始化会话重跑 `init --apply`。各会话下次开局、压缩或清空上下文时，hook 注入新的角色说明；想让它们下一轮就换上，你退出并重开桌面应用。哪一版必须重开（比如 1.0.1 的窗口设置），看下文“升级和检查”里那一版的说明。`check.py check` 会列出还停在旧版规则上的会话。

## 一项任务怎样走完一轮

以验证任务第 3 步“产品序列起草需求文档”为例：

| 步骤 | 谁 | 做什么 | 台账里的变化 |
| --- | --- | --- | --- |
| 下发 | 产品 +2 | 写下发关系的需求包，请书记员登记并开工，再委托产品 +1 | 新建同序列需求，状态“执行中”；排队还没委托的留在“待开工” |
| 拆分 | 产品 +1 | 按验收标准拆成执行关系的需求包，请书记员登记并开工，登记请求里写来源工作项；拿到工作项 ID 后委托产品 +0 | 新的同序列需求“执行中”，主文档挂在下发需求包的主文档下 |
| 执行 | 产品 +0 | 访谈整理、现状调研，写交付包交给 +1 | 书记员把交付包挂到这条需求下，确认“执行”，状态“待验收” |
| 验收 | 产品 +1 | 逐条对照验收标准。通过，请书记员确认“验收”；不通过，请书记员回滚到“执行”并写明原因 | “已验收”，或者回到“执行中” |
| 交付 | 产品 +1 | 汇总成交付包交给 +2，+2 验收 | 下发的那条需求走到“已验收” |

| 推进 | 产品 +2 | 需求文档和评测集版本齐了，请书记员确认研究任务的第 3 步 | 研究任务走到“确定假设条件” |
| 归档 | 书记员 | 办完的需求归档 | 状态“归档”，主文档移到“归档文档”下 |

## 哪些事 agent 做不了，要你本人来

- 扫码授权登录。登出、升级命令行工具、改它们的配置和诊断上报设置，由你在终端里做。
- lark-cli 风险表里的 high-risk-write 命令，以及任何带 `--yes` 的命令。例外只有一条：书记员可以删知识库里的文档（`lark-cli wiki +node-delete`），用来清被新版本换下来的旧文档和重复的副本，删掉的进知识空间的回收站。知识库里的文档可以删，改只能通过台账脚本。
- 签字：验证任务第 4 步的假设和阈值、第 9 步的下一步；回退、超预算、权限策略、质量和算法序列之间的争议、不可逆的对外动作、发给导师和合作人的材料。
- 去现场：访谈真实用户，拿到真实数据。
- 终止工作项，删工作项、删空间、删类型、删字段。搭建和修改飞书模板归模板维护者。
- 合并 `.new` 文件，改 `.claude/` 下的 hook、配置和角色定义。
- 在共享的项目目录里切分支、stash、reset、pull。

hook 只拦两类事：会损坏数据的，和你多半不在时向你提的问题。权限判断交给 Claude Code 自己：它的权限检查认为没问题的命令，只要不妨碍飞书项目里的台账，hook 一律不拦。hook 守的是和飞书项目有关的事：只有书记员写飞书和台账，高风险的飞书命令归你。

- 在任何会话里都直接拒绝：用编辑工具改 `.claude/` 下的 hook、配置、角色定义、认领表和本地决策状态，要改就改插件或任务文件再重跑 init；用编辑工具改评测协议用到的只读文件，质量序列的会话和你自己的会话例外，它们的改动弹窗要你确认；high-risk-write 和带 `--yes` 的飞书命令；派发时带 `name`；用 Agent 工具派书记员；第二条入口或书记员认领。
- 在你自己的会话里弹窗问你，在别的会话里拒绝：书记员以外的会话写飞书和台账，在共享目录里切分支、stash、reset 或 pull，释放认领。工作项、字段、节点和文档只有唯一认领的书记员能写。
- hook 只拦写，不拦读：读飞书的命令、带 `--help` 的命令，以及不加 `--apply` 的台账命令（它只预览，什么都不写），哪个会话都能跑。
- hook 不拦、也不弹窗的：不可逆事项清单里的命令（`sudo`、`ssh`、`git push`、`open -a Docker` 这类），用 rm、mv、cp、重定向、sed -i 这类 shell 命令删改受保护路径或 `.claude/` 下的文件，待定决策“冻结的动作”。这些命令的权限照 Claude Code 自己的检查，该弹的确认由它弹；和飞书读命令写在同一行也一样，hook 只对整条都是飞书、台账调用的命令答允许。规矩不变，靠规则、每轮的冻结提示和包检查：清单里的事要先有一条你批准、所选选项里列了它的决策再做；决策待定期间，包里“冻结的动作”谁都不做；评测协议的只读文件和 `.claude/` 下的文件用 shell 命令也不许改。不可逆事项清单在 `org/org.md` 的“不可逆事项”一节，九类：管理员权限、特权应用（先列 Docker Desktop）、系统和账号、权限、Docker 资源、对外发送、受保护路径、花钱、付费运行的条件；一件事可逆不可逆由决策包的作者按判据判断，清单是必须写不可逆的下限。
- 会话是 bypass 模式时，本该弹窗问你的一律直接拒绝，理由里写“请研究员在自己的终端里运行”。
- 池会话被其他 agent 会话叫醒的轮次：拒绝 AskUserQuestion，去掉收尾工具里的提问，只留回顾。插队决策的登记回执到入口的那一轮，入口的提问放行一次。

其余是规范，hook 只提醒、记日志，不拦：谁能委托谁、委托 +0 要写会话名、可改范围里的代码只由工程序列改、各序列写自己的草稿目录。提醒记在 `.claude/logs/guard.jsonl`，`route.py audit` 汇总。

受保护路径用编辑工具改，池会话一律拒绝，质量序列的会话和你自己的会话弹窗问你。用 shell 命令删改它们，hook 不拦；脚本自己在里面写文件也拦不住。要真正防住，靠运行环境的只读挂载。放在项目目录以外的评测数据 hook 管不到：在评测协议的“存放和版本”里写明放在哪、固定哪个版本，靠这条约定和账号权限保护。

hook 是防 agent 误操作的护栏。它按命令文本判断，刻意混淆的命令总有办法藏过去。所有 agent 用的是你一个飞书账号，真正的边界是这个账号的权限；hook 的判断都记在 `.claude/logs/guard.jsonl`，可以抽查。

## 插件定下的几处安排

插件按下面几条安排落地。初始化时它们会列在 `org/decisions.md` 开头，你可以逐条推翻：

- 项目管理 +2 是入口。决策只在两个时刻交给你：登记进决策队列时提一次，紧急程度为“插队”的，登记那一轮可以直接问你一次；你在入口会话里主动发起讨论、还有待决定或等你执行的决策时，把全部清单列一次。其余时候不提，你问起时照实回答。
- 书记员除了接项目管理 +1 的需求包，也接任何会话的登记请求（+0 交付之前也自己提），只登记请求方自己写的草稿。委托 +1、+0 之前要先有工作项 ID，请求方直接找书记员登记最快。
- 各会话可以自己加带会话标签的评论；工作项、字段、状态和文档仍只由书记员写。
- 你可以直接委托其余序列的 +2，不必都经过入口；谈定的事仍写成决策包交给入口登记。
- 各角色是你看得见的桌面会话，委托、交付、登记都发消息；书记员的写权只认唯一的那条认领。
- 同序列需求用“关系”字段区分下发和执行；反馈的主文档是导师或你的原话所在的文档。
- 决策队列按决策包包头的“紧急程度”排序；“渠道”写“研究员主动发起”的，登记后直接确认“决定”这一步。
- 取消送审，改由测量把关。
- 五类工作项都用节点流程，退回一律是回滚节点并写原因；阻塞是工作项上的两个字段。
- 七个序列都保留。外联只写给你以外的读者看的材料，导师意见的登记和解析归项目管理。周报、月报由你对入口说一句触发，不设定时任务。
- 流程、表单和字段清单不写在规则里，运行时读空间；脚本按含义处理的槽位写在约定文件里，每个项目的对应关系记在 `feishu/ids.json`。
- 被其他 agent 会话叫醒的轮次，池会话都不向你提问，只有插队决策的登记回执到入口的那一轮，入口可以在收尾里问你一次：其余收尾里的提问由 hook 去掉，AskUserQuestion 一律拒绝。
- 有选项要你挑、定下以后又要你亲手做的事是决策；只要你动一下手、没有选项要挑的事不写决策包，记进研究员任务清单，入口列在决策清单后面：决策包包头“执行方”写这条决策定下以后由谁执行，“研究员”或者执行它的会话名，多半是发出方；“研究员要做的事”写要你亲手做的事，没有写“无”，执行方是研究员时不能是“无”，执行方是会话时写“无”。执行方写会话的，只收各序列的 +2、入口和路由；要下级干的活，由 +2 用需求包委托。只要有一个选项要你亲手做，执行方就写“研究员”；你选了不用你动手的选项，书记员确认“决定”时用 `workitem.py confirm --executor <会话名>` 把执行方改成那个会话。每条决策走三步：待决定、待执行（用 2.1.0 及以前的模板建的空间里叫“已决定”）、归档（已执行）；你定了，书记员就确认“决定”，并通知执行方；执行方是会话的，照决定执行完马上请书记员归档，执行方是你的，你说做完了才归档。入口主动给你的内容只有决策（给链接，执行方和要你亲手做的事一并写上）和里程碑两类；补位请求不算决策。
- 跨序列需求的委托经路由，之后直连：发起的 +2 把需求包交路由查重、登记，拿到工作项 ID 后直接委托对方的 +2；接单、答复、交付、验收都在两个 +2 之间，入口不转手。路由维护协调记录，出了要你知道的事才报入口。改范围、改成功标准、改冻结项仍然只走决策包。
- 产品、算法和外联默认只开 +2。有封闭任务时它们的 +2 补 +0 直接委托，有要长期占上下文的设计阶段时才补 +1。任务文件里写了 `pool.later` 的照任务文件。
- +1 和 +0 的分工线：一件事做到一半还需不需要新的信息或新的判断。不需要的交 +0；需要的（开跑一个批次并盯着、撤作业、合并和解冲突、命令被拦下以后的重试这类）+1 自己做。
- 命令被拦下时不提升会话的权限模式：会话把完整命令记进研究员任务清单，你到那个会话的窗口里说一句允许，或者自己在终端里跑。把一个会话单独切到 bypass，它和其余会话之间的消息会双向被扣，桌面端弹不出审批框，默认 5 分钟后丢弃。
- 不可逆事项清单是插件的 `orgspec/irreversible.json`，随 `org/org.md` 生成：九类，每一类写包括什么、对应哪几条判据，是写决策包和判断可逆性的依据；数据一类收窄到任务文件登记的受保护路径。清单里的事要先有你批准、所选选项里列了它的决策再做；一件事可逆不可逆由决策包的作者按判据判断，清单是必须写不可逆的下限。决策待定期间，包里“冻结的动作”谁都不做；待定的决策记在本地决策状态 `.claude/state/gates.json`，由台账脚本维护。hook 不拦清单里的命令，也不按待定决策冻结：命令的权限照 Claude Code 自己的权限检查，这几条规矩靠各会话照规则办和包检查。可逆的决策到期没定，书记员按包头的到期默认动作记成决定，决定内容以“到期默认：”开头；不可逆的、执行方是你的决策一直等你，不提醒截止；你定过一次、又回滚到待决定的决策也一直等你，不再走到期默认。包头的回复期限只作参考。修订决策用 `docs.py revise` 原位换掉主文档开头，版本号加一，不推给你。
- 可逆决策的到期时长：登记后 24 小时。你可以改 `org/decisions.md` 里这一行的数字，台账脚本按这一行算，读不到时按 24 小时算。

## 在飞书项目里做不到、改成别的办法的

| 想做的 | 飞书的限制 | 插件的办法 |
| --- | --- | --- |
| 用命令建空间、工作项类型、字段和流程 | 命令行建不了 | 模板维护者在网页上搭好模板并发布；每个项目用模板创建空间，插件运行时读空间，按约定绑定，名字不同的指认一次 |
| 读一个类型的流程图 | 命令行只能从一条工作项读出它走的流程 | 某个流程登记了第一条工作项以后重读一次空间结构 |
| 一个字段关联多种工作项 | 关联字段要先在空间里建关系定义 | “来源工作项”“所属研究任务”用单行文本存工作项 ID |
| 按会话分写入权限 | 所有 agent 用你一个账号，飞书分不出会话 | 由 hook 管谁能写 |
| 用飞书通知提醒 agent | 没配过自动化，没测过 | agent 不依赖通知，靠台账查询和收件箱 |
| 用命令终止工作项 | 命令行没有终止的命令 | 你在网页上做；做完请入口跑 `pool.py show --prune` 清认领表 |
| 回滚以后让必填检查重新起作用 | 回滚以后已填的值还在 | 回滚时脚本把被退回各步的必填字段清空，旧值打印出来，也留在操作记录里。重走以后字段只留新一轮的值 |
| 读回人员字段 | `workitem get` 不返回人员字段的值 | 台账脚本改用 MQL 读，只显示名字 |
| 查询时去掉已终止的工作项 | MQL 不会自动排除 | 查询都显式排除“已终止” |
| 用命令给知识库节点改名 | lark-cli 没有改节点标题的命令 | 节点标题跟着节点文档的一级标题走；空文档整篇覆盖，有内容的在网页上改 |
| 让日期在谁看都是同一天 | 日期存成毫秒时间戳，网页按浏览者的时区显示 | 日期字段一律写目标日期的 UTC 中午，UTC-12 到 UTC+11 的人看到的都是同一天 |

## 升级和检查

```bash
python3.12 -I "$PLUGIN/scripts/check.py" check --target <项目目录>
```

`$PLUGIN` 是插件的安装目录，初始化会话知道它在哪；你想自己在终端里运行，向它要这条完整的命令。

`check` 分四层报告，四层都就绪才返回 0：

| 层 | 核对什么 |
| --- | --- |
| 本地配置 | 用现在的插件按 `spec/task.json` 重新生成一遍，和初始化时逐个文件比对：插件、规则、术语表、约定文件或 `feishu/ids.json` 变了要更新的文件，你改过的文件，没合并的 `.new` |
| 飞书 | 项目空间绑定了没有，知识空间记下了没有，21 个节点齐不齐，`.env` 的两行在不在 |
| 会话 | 清单里的会话都已认领，入口和书记员各一条，权限模式同一类，工作目录是项目目录 |
| 首条研究任务 | 有登记回执和主文档，草稿里写着工作项 ID |

加 `--live` 只读回读飞书：空间结构和绑定还对不对得上，每个节点还在不在，研究任务、主文档和它的上一级节点是不是互相对得上。

加 `--readback <回读文件>` 比对每个会话实际用的模型、推理强度和窗口。回读文件由初始化会话逐个读会话信息后写成，做法见 setup 技能第 8 步。模型和开池清单不在一档、窗口小于初始化会话的，算问题；推理强度不同、没读到的，只提醒。最后打印一张回读表。

## 常见问题

**入口说“没有空闲的会话”。** 每个序列的 +2 只有一个，+1 最多三个，+0 最多五个。工作项留在台账的“待开工”里排队，等有会话空出来；要多开 +1，在那个序列 +2 的会话里说一句“补位”，要多开 +0，在它上面那个 +1 的会话里说；会话自己记了补位请求的，到入口说的那个会话里点一下启动卡。

**台账脚本说“还没绑定飞书空间”，或者任务文件里的空间和绑定的不同。** 请初始化会话重新绑定：它运行 `space.py feishu --live` 预览，核对后加 `--apply`。

**绑定预览说空间里没有一种类型对得上。** 这个名字的空间不是用模板建的。换一个空间名，让初始化会话用模板创建；空间里其实有这些类型、只是名字不同的，用 `--map` 指认，做法见技能 `solo-lab:space-bind`。

**要把项目换到另一个飞书项目空间。** 照 setup 技能 `feishu-space.md` 的“换空间”一节做。插件搬不了工作项，旧空间里的工作项留在原处当档案，你确认以后才加 `--leave-old-items` 写入。项目进行中尽量别换空间。

**书记员说“字段还没绑定”。** 看 `feishu/binding.md` 的“要处理的问题”：已经有、只是名字不同的，用 `--map` 指认；空间里确实没有的，把这张表交给模板维护者。

**书记员说“上次已经建了工作项，但没做完”。** 登记到一半失败了，比如建文档时断网。工作项已经在了，回执在 `packages/sent/` 下。修好原因后让书记员加 `--resume` 接着做，它不会再建一个。

**书记员说“上次建文档没有拿到确定的结果”。** 建文档超时，或者返回里没有链接时，文档可能已经建好了。到提示里的节点下看一眼：建好了的，让书记员重跑时加 `--doc <文档链接>`；确认没建成的，加 `--doc new`。

**确认节点被拒，说要先填某个字段。** 那是这一步的必填项，脚本在写之前先问了一遍空间。把值告诉书记员。

**确认节点被拒，说决策不合格。** 签字的那条决策没决定、签字结果不是批准、不属于这条研究任务，或者是在任务走到这一步之前决定的。没决定的等你决定；你确实批准了、只是签字结果或所属研究任务没记上的，请书记员补记后重跑；决定早于这一步的，要你就现在这一步重新决定一次。

**角色会话说登录过期。** 回到初始化会话说“重新登录”，它给你二维码。角色会话自己发起不了登录。

**hook 拦下了一条看起来无害的命令。** 多半是命令里藏着飞书命令行，hook 看不到里面在做什么。把它拆成单条简单命令重试；插件自己的脚本只在内容和清单一致时被信任，改过就会被拦。

**飞书项目空间或知识空间被删了。** 这一版不支持恢复。对初始化会话说“检查部署有没有漂移”，带回读的检查会报“知识库节点读不到”或者查不到研究任务；被删的工作项和文档找不回来，要继续做就换一个新目录重新初始化。

**初始化停下来，说目录里原来就有同名文件。** 目录里已有 `CLAUDE.md` 或 `.claude/settings.json` 时，初始化不覆盖也不合并，新内容写在旁边的 `.new` 文件里。这两个文件没合并以前，会话读不到组织规则，hook 也没装上，所以它不开池。你对照 `.new` 把内容合进原文件，删掉 `.new`，再让它接着做。这一版不做自动合并，新项目用空目录最省事。

**台账里的“负责会话”，有的写 `Alg-p0-01`，有的写 `Alg-p0-2105`。** 都是 +0 的名字，脚本都认。`Alg-p0-01` 是池位名，会话标题和消息抬头用它；`Alg-p0-<工作项 ID>` 是工作名，标的是一条活。约定“负责会话”记池位名：+1 在需求包包头的接收方后面写上 +0 的池位名，登记时就记它；包头没写的，登记时脚本填工作名。

**开池时每开一个会话都弹一张确认卡。** 初始化会话开在了 bypass 模式。这个模式下应用对每一次开会话都要你点一次，卡片只有 Deny 和 Allow once，弹在发起的那个会话里，+2 开 +1、+1 开 +0 也一样，默认的 15 个会话要点 15 次。这是应用有意留的确认，插件不去绕开。还没开池的话，在项目目录新开一个 auto 模式的会话，说“用 solo-lab 初始化这个目录”，它从开池接着做。已经开出一部分的，不要换模式，新旧会话不同类，消息会被扣下；到带“Needs your input”标记的会话里逐个点完。

**想先在不连飞书的情况下看看会发生什么。** 台账脚本默认只预览；加 `--offline` 连读都不读，只打印命令。
