# 智能体组织插件使用说明

## 插件装好以后是什么样子

在一个项目目录里初始化以后，Claude 桌面应用的侧栏里多出一个以项目命名的分区，里面每个会话是一个角色：顶层是七个序列的 +2，+1 嵌在 +2 下面，+0 嵌在 +1 下面。七个序列（产品、算法、工程、基础设施、质量、项目管理、外联）各有 +2、+1、+0 三级，你是 +3。

你平时只和一个会话说话：项目管理 +2，也就是入口 `PMO-p2-01`。你把信息和指示告诉入口，它按路由决策表把事情分给其余六个序列的 +2，各序列再逐级派给 +1、+0。特殊情况下你也可以直接点开某个 +2 的会话交代。交接写成三种任务包：需求包、交付包、决策包。书记员把它们登记进飞书项目、上传到飞书文档。

研究的主线是研究任务。一条研究任务回答一个问题，在飞书项目里一步一步往前走，每一步由一个序列负责。有判据、要下结论的走验证流程，你每条签两次字；还没有假设、只为找方向的走试探流程。

你每天做两件事：看决策队列，替 agent 拍板它们超出授权的事；研究任务走到哪一步，就找那一步负责序列的 +2 深谈。

运行方式只有一种，叫会话池：每个角色是侧栏里的一个会话，你能看到每个会话在做什么，派活和交回都是会话之间的消息，留在各自的记录里。它只支持 Claude 桌面端。

插件只覆盖你和 agent 之间的协作。导师和合作人不用飞书，给他们的材料由外联序列准备，你签字后自己转交。

## 装之前准备好这些

| 要准备的 | 说明 |
| --- | --- |
| Claude 桌面应用 | 会话池要用它开会话、发消息。Claude Code 2.1.219 以上 |
| 飞书账号 | 能登录飞书项目和知识库，能在飞书项目里用模板创建空间。建空间的人就是空间管理员 |
| lark-cli | 1.0.96 以上，配置好应用。用户身份登录失效没关系，初始化时会给你二维码 |
| meegle | 1.0.23 以上。登录失效同样在初始化时扫码；诊断上报建议关闭 |
| Python | 3.9 以上，插件的脚本只用标准库 |
| 飞书项目模板 | 不用自己搭。插件的约定文件里记着一个参考模板的链接，初始化时照它创建项目空间 |

## 第一次：安装插件

插件装在用户级，装一次，所有项目都能用。

```bash
claude plugin marketplace add <本仓库的路径或地址>
```

```bash
claude plugin install agent-org@agent-org
```

装好后多出八个技能：`agent-org:setup`、`agent-org:charter`、`agent-org:spec`、`agent-org:packages`、`agent-org:ledger`、`agent-org:entry`、`agent-org:space-read`、`agent-org:space-bind`。插件本身不带任何 hook：hook 只在初始化过的项目里、写在项目设置里，普通项目不受影响。

## 每个项目一次：初始化

你只做一件事。在 Claude 桌面应用里选中项目目录，新开一个会话，模型选你能用的最高的那一档（默认配置里 +2 用 opus，模型高于这个会话的会被降档），说一句：

```text
用 agent-org 初始化这个目录
```

可以顺带说项目名和一句话描述，比如“项目名 code-opt，做面向代码的约束优化器”。不说项目名就用目录名。

这个会话叫初始化会话。它调用 `agent-org:setup`，按下面的顺序做完。一路顺利的话，中途不停下来问你：

1. 打印一份“将要新建”的清单，开始计时，做前置检查。
2. 命令行登录失效的，发起登录，把二维码和链接给你。
3. 写任务文件，生成项目文件：21 份角色定义、项目权限和 hook、`CLAUDE.md`、`org/`、`packages/`、`inbox/`、`spec/`，以及插件脚本和规则的副本。
4. 按项目名找飞书项目空间。没有就打开模板链接，用模板创建。
5. 读空间结构，把插件的约定绑定到这个空间；按项目名找知识空间，没有就新建。
6. 开出会话池，默认 19 个会话。初始化会话分 3 批开七个 +2，+2 开 +1，+1 开 +0；分批是因为应用限制会话自己开出的会话同时最多 5 个在跑。书记员在入口下面第三层，它在知识空间里建 21 个节点，登记一条最小的研究任务。
7. 在项目目录的 `.env` 里写飞书项目和知识空间的两条链接。
8. 回读飞书，做四层检查：本地配置、飞书、会话、首条研究任务。
9. 结束计时，向你交接。

过程中可能要你动手的只有这几种情况：

- **扫码。** lark-cli 或 meegle 的登录失效时，每个扫一次。会话不接触密码、验证码和令牌。
- **点确认框。** 浏览器的站点许可或电脑控制的应用授权，目录信任，默认权限模式下的命令确认和移动会话的确认。
- **用模板创建空间。** 会话的浏览器工具都用不了时，它把模板链接和空间名给你，请你自己创建。
- **手工开会话。** 初始化会话开不了会话时走回退档：你在项目目录手工建 7 个会话，各粘贴它给的一句话。

它会停下来问你的情况：同名的项目空间或知识空间不止一个；同名的空间已经有了、但和插件的约定对不上；目录里原来就有 `CLAUDE.md` 或 `.claude/settings.json` 这样的同名文件；页面上出现付费、升级或权限申请的弹窗。它只新建，不删除、不覆盖、不改已有的对象。

交接时它告诉你：四层检查的结果，新建和沿用了什么，耗时（飞书操作这一类对照 300 秒的指标，只是指标），和默认不一样的地方，还空着的设置，以及从哪个会话开始。然后请你做两件事：打开 `org/decisions.md`，开头列着插件定下的几处安排，逐条确认或推翻；点一下 `.env` 里的两条链接，看能不能打开。

初始化会话留着别归档，它以后是你自己的会话：重新登录、检查部署、升级插件都在它里面做。

### 默认值

| 项 | 默认值 | 想改 |
| --- | --- | --- |
| 项目名 | 目录名 | 开场那句话里说 |
| 飞书项目空间、知识空间的名字 | 等于项目名 | 开场时说，或改任务文件的 `feishu.meegle_space`、`feishu.wiki_space` |
| 模板 | 约定文件里的参考模板链接 | 任务文件的 `feishu.template_url` |
| 会话池 | 19 个：七个 +2、路由、书记员，外联以外的五个序列各一个 +1 和一个 +0 | 任务文件的 `pool`。外联的 +1、+0 第一次要出材料时，在外联 +2 的会话里说一句“补位” |
| 模型 | +2 用 opus，+1 和 +0 用 sonnet，书记员用 haiku，质量 +1 用 opus | 任务文件的 `models`。会话的模型不能高于开它的会话（+2 看初始化会话，+1 看 +2，+0 看 +1），高出的不生效 |
| 会话标题 | `[<飞书项目空间名>] <会话名>`，都归入同名的侧栏分区 | 任务文件的 `pool.label` |
| 可写路径、只读路径 | 空着 | 设计阶段定下后写进任务文件的 `editable_paths`、`protected_paths` |

任务文件是项目目录里的 `agent-org.task.json`，只放脚本和 hook 要用的几项，格式见插件的 `scaffold/task.example.json`。要改设置，改它，再请初始化会话重跑 `init --apply`。`spec/task.json` 是它的副本，不手改。

每一步的命令、输出和失败时的处理写在技能 `agent-org:setup` 里。

## 研究任务和五类工作项

### 五类工作项

飞书项目里有五类工作项，都走节点流程，每个流程最后一步是书记员确认的“归档”。

| 类型 | 用途 | 流程 | 主文档 |
| --- | --- | --- | --- |
| 研究任务 | 主线。一个空间可以有多条，后一条用“来源工作项”指向前一条 | 验证或试探，新建时选 | 研究任务单 |
| 同序列需求 | 序列内派活和交回，发出方验收 | 开工、执行、验收、归档 | 需求包 |
| 跨序列需求 | 序列之间 +2 对 +2 的请求 | 提出、接单、执行、验收、归档 | 需求包 |
| 决策 | 你拍板和签字 | 决定、归档 | 决策包 |
| 反馈 | 导师和你的反馈 | 解析、归档 | 原话所在的文档 |

一份需求包、决策包或研究任务单对应一条工作项。交付包是对某条需求的答复，挂在那条需求下面，不另建工作项。

节点流程有这几条规矩：

- 每一步有一个负责方，完成时有必填的字段。产出齐了，由这一步的负责方请书记员确认节点。
- 有哪些步骤、每一步谁负责、必填什么，以飞书空间为准，脚本现读。任何会话都能问：`python3 -I .claude/agent-org/bin/ledger.py next <工作项 ID>`。
- 退回就是回滚节点，必须写原因。验收不通过，发出方请书记员回滚到“执行”；跨序列需求不接，承接方回滚到“提出”。
- 阻塞记在工作项的两个字段里：阻塞原因、阻塞开始日期。没有“阻塞”这个状态，走到哪一步和卡没卡住分开记。
- 终止工作项命令行做不了，要你在网页上做。

### 研究任务的两个流程

新建研究任务时选流程。下面是参考模板里的两个流程，你的空间以 `org/phases.md` 为准。

**验证流程**用于有判据、要下结论的问题。一条验证任务只回答一个能被一次冻结的评测回答的问题，多个问题开多条。

| 步 | 节点 | 负责 | 配合 | 完成时必填 |
| --- | --- | --- | --- | --- |
| 1 | 确定目标 | 产品 +2 | | 成功标准 |
| 2 | 准备上下文 | 算法 +2 | | 上下文文档 |
| 3 | 准备 PRD 和 Eval Set | 产品 +2 | 质量：建并冻结 Eval Set，写评测协议 | 需求文档、评测集版本 |
| 4 | 确定假设条件 | 算法 +2 | 质量：核对阈值 | 规格、规格版本、总预算、波动估计、假设签字 |
| 5 | 设计实验方案 | 算法 +2 | | 实验方案、实验轮次 |
| 6 | 搭建实验平台 | 基础设施 +2 | | 冒烟运行 ID |
| 7 | 跑 Eval Set | 工程 +2 | 质量：出正式分 | 运行 ID、试过的变体数 |
| 8 | 得出结论 | 算法 +2 | | 结论、结论文档 |
| 9 | 下一步讨论 | 项目管理 +2 | | 下一步签字 |
| | 归档 | 书记员 | | |

配合方的活，由负责这一步的 +2 发跨序列的需求包去请。结论三选一：成立、不成立、无法判定。

**试探流程**用于还没有假设的时候：读代码、小规模试跑、看错误样例。它有四步：定方向、试探、提出假设、归档，都由开这条任务的那个 +2 负责。它不冻结、不签字、不出正式分，产出是值得验证的假设；要下结论，另开一条验证任务。

### 每条验证任务签两次字

- **第 4 步，花算力之前。** 签的是假设和阈值。签字以后，前四步的产出一起冻结：目标和成功标准、需求文档、评测集版本、含假设和阈值的规格、总预算。
- **第 9 步，定下一步。**

签字走决策：负责那一步的 +2 写决策包进决策队列，你批准后，决策工作项的 ID 填进“假设签字”或“下一步签字”字段。书记员确认节点前，脚本核对这条决策：类型是决策，已经决定，签字结果是批准，属于这条研究任务，并且是在任务走到这一步之后决定的。一条决策只用一次。

冻结以后要改，只有两条路，都要你决定：退回到第 4 步或之前，改完重新签字；或者结束这条任务，另开一条。回退也由你决定：退到哪一步、为什么，写成决策包，你批准后书记员回滚节点。

### 把关靠测量

没有送审这一环。把关靠管住测量：

- Eval Set 和阈值在出结果之前定下，第 4 步签字后冻结。
- 正式分数只由质量序列在冻结的 Eval Set 上跑出。执行方自己跑的是开发分，用来调试，不写进结论。
- 结论只对照签过字的阈值。“不成立”和“无法判定”都是合法结论。
- 所有运行都进台账，失败的也算。

一个项目的第一条验证任务定为“复现并测量基线”，成功标准写成和公开数字相差多少以内，后面的任务拿它的结果定阈值。

## 日常使用

### 和入口说话

在侧栏分区里点开 `[<分区名>] PMO-p2-01`，这个会话就是入口。

初始化时已经登记了一条最小的研究任务，内容只有项目名和一句话描述。第一件事是把它补全：对入口说“立项”，入口用 `agent-org:charter` 访谈你，写出修订的研究任务单，请书记员换成这条研究任务的主文档。工作项不变，还停在第一步“确定目标”。以后要开新的研究任务，对入口说“开一条研究任务”，入口问清交给哪个序列，由那个序列的 +2 访谈你。

之后你说的每句话、转来的每条消息，入口都先过路由决策表：

| 你说的 | 入口怎么办 |
| --- | --- |
| 带工作项 ID 或会话名的，比如“#2101 的访谈记录补上了” | 在那个工作项下留评论，交给负责的会话接着做 |
| 没带 ID 的补充信息，比如“导师想看和人工基线的对比” | 交路由对照进行中工作项的名称、字段和状态包找归属；只对上一项就转过去，对上多项或一项也没有，回来问你 |
| 新任务 | 先问你要不要做、交给哪个序列；你拍板后由那个序列的 +2 写需求包 |
| 要你拍板的事 | 建成“待决定”的决策，进决策队列 |
| 导师或你的反馈 | 请书记员登记成反馈，入口解析出类别和处理说明，拆出的事项经你确认后交对应序列 |
| “出本周周报” | 给外联 +2 发跨序列的需求包；材料写好后由你签字 |

说话时带上工作项 ID 或会话名，路由就不用猜。

### 看决策队列

每天入口把待决定的决策交给你一次，紧急程度为“插队”的随时交。每件附选项、代价和建议。你在入口会话里拍板，书记员确认决策的“决定”这一步，再通知受影响的会话。决策一直等到你决定，没有过期和默认处理。

### 直接找某个 +2

想和某个序列的 +2 深谈，或者有件事想直接交给它：在侧栏点开它的会话直接说。它会把自己标成“研究员在用”并告诉入口，这期间入口不给它派活，新信息留在它的收件箱。结束前让它把谈定的事写成决策包交给入口。谈定的事没写进台账就不算数，因为别的会话看不到你们的对话。

### 写需求文档、评测协议、规格和实验方案

验证任务走到第 3、4、5 步时，找这一步负责序列的 +2 谈。它用 `agent-org:spec` 先查代码库、评测脚本和数据，写出草稿，只把查不到的问题拿来问你。每条都标了来源：〔研究员确认〕、〔查到：…〕、〔推测，待确认〕，签字前你只需要核对标〔推测，待确认〕的条目。

| 步 | 文档 | 谁写 |
| --- | --- | --- |
| 3 | 需求文档 `spec/requirements.md` | 产品 +2 |
| 3 | Eval Set 和评测协议 `spec/eval-protocol.md` | 质量 +2，接产品 +2 的跨序列需求包 |
| 4 | 实验规格 `spec/spec.md`，含假设和阈值、波动估计 | 算法 +2 |
| 5 | 实验方案 | 算法 +2 |

可写路径和只读路径要改的，会列在请你签字的决策包里。你同意后，在初始化会话里改任务文件、重跑 `init --apply`。

### 在飞书里给入口发消息

飞书私聊机器人的消息可以进入口。需要你在终端里启动监听，开着就行：

```bash
python3 -I .claude/agent-org/bin/route.py listen
```

消息落进 `inbox/feishu.jsonl`，入口下一轮对话时看到。监听只收你本人发给机器人的私聊，按消息 ID 去重；`feishu/ids.json` 里没有你的 open_id 时，它不会启动，免得谁私聊机器人都能进入口。没开监听时，把消息转述给入口也一样。

### 看进度

- 会话在做什么：侧栏里看，或者在入口会话的终端窗格里运行 `python3 -I .claude/agent-org/bin/route.py pool --watch`。等你批准的、失败的、像是卡住的排在最前。
- 一件事走到哪一步：台账是正本。各角色用 `ledger.py` 的条件查询读台账：`queue`（决策队列）、`blocked`（阻塞）、`verifying`（待验收）、`open`（进行中的同序列需求）、`cross`（进行中的跨序列需求）、`tasks`（没归档的研究任务）、`recent`（近 7 天更新过的同序列需求）。
- 插件不配置视图。你想在飞书项目的网页上怎么看，自己在网页上设置，不影响插件。
- 文档：每个项目一个知识空间。研究任务单在“研究任务”节点下，各步的产出文档挂在它下面；同序列需求包按序列分节点，执行关系的需求包挂在它所属的下发需求包下面，交付包挂在它答复的那份包下面。办完归档的整棵子树移到“归档文档”下，链接不变。

## 会话池

**会话之间怎么交接。** 派活、交回、登记请求、需拍板都是消息，首行一个抬头，比如 `【派活 #2101】Alg-p2-01 → Alg-p1-01：需求包 <路径>`，正文在包文件里。派活前先用 `route.py pool --role <角色>` 找空闲的会话；没有就排队，活留在台账的“待开工”。收方的 hook 把收到的时间记进 `.claude/logs/dispatch.jsonl`；对不上派发图、没有登记回执的会提醒收方，但不拦。

**多开、恢复、换人。**

- 要多开会话：多开 +1，在那个序列 +2 的会话里说“补位”或“再开一个 alg-p1”；多开 +0，在它上面那个 +1 的会话里说“再开一个 alg-p0”。新会话在侧栏里嵌在开它的会话下面。你不说，会话不会自己开，只记补位请求，进入口的每日决策队列。
- 重启或电脑睡眠以后：对入口说“恢复”，它照 `route.py pool --recover` 的清单逐个续上，书记员先补完写到一半的登记。
- 某个会话丢了：先运行 `route.py release <会话名>` 释放旧的认领，再请初始化会话把它重新开出来。
- 不要让会话去归档、清空或停止别的池会话。要收掉，由你本人在侧栏操作。归档一个会话，嵌在它下面的会话跟着一起归档：归档 +2 会带走本序列的 +1 和 +0，只想收掉 +2 时先在侧栏里把它下面的会话移到顶层（Detach to top level）。

**权限模式。** 全池和初始化会话用同一类。bypass 和其他模式之间，会话的消息会被扣下。

**登录过期。** 角色会话遇到登录过期会报给你。回到初始化会话说“重新登录”，它发起登录，你扫码。

**升级插件。** 请初始化会话重跑 `init --apply`，然后退出并重开桌面应用；各会话下一轮开始时，hook 注入新的角色说明。`setup.py check` 会列出还停在旧版规则上的会话。

## 一项任务怎样走完一轮

以验证任务第 3 步“产品序列起草需求文档”为例：

| 步骤 | 谁 | 做什么 | 台账里的变化 |
| --- | --- | --- | --- |
| 下发 | 产品 +2 | 写下发关系的需求包，请书记员登记并开工，再派产品 +1 | 新建同序列需求，状态“执行中”；排队还没派的留在“待开工” |
| 拆分 | 产品 +1 | 按验收标准拆成执行关系的需求包，请书记员登记并开工，登记请求里写来源工作项；拿到工作项 ID 后派产品 +0 | 新的同序列需求“执行中”，主文档挂在下发需求包的主文档下 |
| 执行 | 产品 +0 | 访谈整理、现状调研，写交付包交回 +1 | 书记员把交付包挂到这条需求下，确认“执行”，状态“待验收” |
| 验收 | 产品 +1 | 逐条对照验收标准。通过，请书记员确认“验收”；不通过，请书记员回滚到“执行”并写明原因 | “已验收”，或者回到“执行中” |
| 交回 | 产品 +1 | 汇总成交付包交回 +2，+2 验收 | 下发的那条需求走到“已验收” |
| 配合 | 产品 +2 | 给质量 +2 发跨序列的需求包，请它建并冻结 Eval Set、写评测协议，经入口转交 | 跨序列需求从“待接单”走到“已验收” |
| 推进 | 产品 +2 | 需求文档和评测集版本齐了，请书记员确认研究任务的第 3 步 | 研究任务走到“确定假设条件” |
| 归档 | 书记员 | 办完的需求归档 | 状态“归档”，主文档移到“归档文档”下 |

## 哪些事 agent 做不了，要你本人来

- 扫码授权登录。登出、升级命令行工具、改它们的配置和诊断上报设置，由你在终端里做。
- lark-cli 风险表里的 high-risk-write 命令，以及任何带 `--yes` 的命令。
- 签字：验证任务第 4 步的假设和阈值、第 9 步的下一步；回退、超预算、权限策略、质量和算法序列之间的争议、不可逆的对外动作、发给导师和合作人的材料。
- 去现场：访谈真实用户，拿到真实数据。
- 终止工作项，删工作项、删空间、删类型、删字段。搭建和修改飞书模板归模板维护者。
- 合并 `.new` 文件，改 `.claude/` 下的 hook、配置和角色定义。
- 在共享的项目目录里切分支、stash、reset、pull。

hook 只拦会损坏数据的事：

- 在任何会话里都直接拒绝：改 `.claude/` 下的 hook、配置、角色定义和认领表，要改就改插件或任务文件再重跑 init；改评测协议用到的只读文件，质量序列的会话例外，它的改动要你确认；high-risk-write 和带 `--yes` 的飞书命令；派发时带 `name`；用 Agent 工具派书记员；第二条入口或书记员认领。
- 在你自己的会话里弹窗问你，在别的会话里拒绝：书记员以外的会话写飞书和台账，在共享目录里切分支、stash、reset 或 pull，释放认领。工作项、字段、节点和文档只有唯一认领的书记员能写。
- 会话是 bypass 模式时，本该弹窗问你的一律直接拒绝，理由里写“请研究员在自己的终端里运行”。

其余是规范，hook 只提醒、记日志，不拦：谁能给谁派活、派 +0 要写会话名、可改范围里的代码只由工程序列改、各序列写自己的草稿目录。提醒记在 `.claude/logs/guard.jsonl`，`route.py audit` 汇总。

路径边界只管 Claude 的文件工具。在 shell 里写文件拦不住，要靠运行环境的只读挂载。放在项目目录以外的评测数据 hook 管不到：在评测协议的“存放和版本”里写明放在哪、固定哪个版本，靠这条约定和账号权限保护。

hook 是防 agent 误操作的护栏。它按命令文本判断，刻意混淆的命令总有办法藏过去。所有 agent 用的是你一个飞书账号，真正的边界是这个账号的权限；hook 的判断都记在 `.claude/logs/guard.jsonl`，可以抽查。

## 插件定下的几处安排

插件按下面几条安排落地。初始化时它们会列在 `org/decisions.md` 开头，你可以逐条推翻：

- 项目管理 +2 是入口，每日决策队列由它交给你。
- 书记员除了接项目管理 +1 的需求包，也接各序列 +2、+1 的登记请求，只登记请求方自己写的草稿。派 +1、+0 之前要先有工作项 ID，请求方直接找书记员登记最快。
- 各会话可以自己加带会话标签的评论；工作项、字段、状态和文档仍只由书记员写。
- 你可以直接委托其余序列的 +2，不必都经过入口；谈定的事仍写成决策包交给入口登记。
- 各角色是你看得见的桌面会话，派活、交回、登记都发消息；书记员的写权只认唯一的那条认领。
- 同序列需求用“关系”字段区分下发和执行；反馈的主文档是导师或你的原话所在的文档。
- 决策包包头有“紧急程度”和“渠道”两行。决策队列按紧急程度排序；渠道写“研究员主动发起”的，登记后直接确认“决定”这一步。
- 取消送审，改由测量把关。
- 五类工作项都用节点流程，退回一律是回滚节点并写原因；阻塞是工作项上的两个字段。
- 七个序列都保留。外联只写给你以外的读者看的材料，导师意见的登记和解析归项目管理。周报、月报由你对入口说一句触发，不设定时任务。
- 流程、表单和字段清单不写在规则里，运行时读空间；脚本按含义处理的槽位写在约定文件里，每个项目的对应关系记在 `feishu/ids.json`。

## 在飞书项目里做不到、改成别的办法的

| 想做的 | 飞书的限制 | 插件的办法 |
| --- | --- | --- |
| 用命令建空间、工作项类型、字段和流程 | 命令行建不了 | 模板维护者在网页上搭好模板并发布；每个项目用模板创建空间，插件运行时读空间，按约定绑定，名字不同的指认一次 |
| 读一个类型的流程图 | 命令行只能从一条工作项读出它走的流程 | 某个流程登记了第一条工作项以后重读一次空间结构 |
| 一个字段关联多种工作项 | 关联字段要先在空间里建关系定义 | “来源工作项”“所属研究任务”用单行文本存工作项 ID |
| 按会话分写入权限 | 所有 agent 用你一个账号，飞书分不出会话 | 由 hook 管谁能写 |
| 用飞书通知提醒 agent | 没配过自动化，没测过 | agent 不依赖通知，靠台账查询和收件箱 |
| 用命令终止工作项 | 命令行没有终止的命令 | 你在网页上做 |
| 回滚以后让必填检查重新起作用 | 回滚以后已填的值还在 | 回滚时脚本把被退回各步的必填字段清空，旧值打印出来，也留在操作记录里 |
| 读回人员字段 | `workitem get` 不返回人员字段的值 | 台账脚本改用 MQL 读，只显示名字 |
| 查询时去掉已终止的工作项 | MQL 不会自动排除 | 查询都显式排除“已终止” |
| 用命令给知识库节点改名 | lark-cli 没有改节点标题的命令 | 节点标题跟着节点文档的一级标题走；空文档整篇覆盖，有内容的在网页上改 |
| 让日期在谁看都是同一天 | 日期存成毫秒时间戳，网页按浏览者的时区显示 | 日期字段一律写目标日期的 UTC 中午，UTC-12 到 UTC+11 的人看到的都是同一天 |

## 升级和检查

```bash
python3 -I "$PLUGIN/scripts/setup.py" check --target <项目目录>
```

`$PLUGIN` 是插件的安装目录，初始化会话知道它在哪；你想自己在终端里运行，向它要这条完整的命令。

`check` 分四层报告，四层都就绪才返回 0：

| 层 | 核对什么 |
| --- | --- |
| 本地配置 | 用现在的插件按 `spec/task.json` 重新生成一遍，和初始化时逐个文件比对：插件、规则、术语表、约定文件或 `feishu/ids.json` 变了要更新的文件，你改过的文件，没合并的 `.new` |
| 飞书 | 项目空间绑定了没有，知识空间记下了没有，21 个节点齐不齐，`.env` 的两行在不在 |
| 会话 | 清单里的会话都已认领，入口和书记员各一条，权限模式同一类，工作目录是项目目录 |
| 首条研究任务 | 有登记回执和主文档，草稿里写着工作项 ID |

加 `--live` 只读回读飞书：空间结构和绑定还对不对得上，每个节点还在不在，研究任务、主文档和它的上一级节点是不是互相对得上。

插件更新后，请初始化会话重跑 `init` 预览差异：没人改过的文件直接更新，改过的写 `.new`。`spec/` 下的文档、`org/decisions.md` 和 `org/phases.md` 归你和各角色维护，插件改了模板也不会覆盖。组织规则（职级、包、路由表）只在插件的 `orgspec/rules.json` 里存一份，中文名在 `orgspec/terms.zh.json`；改名只改术语表，脚本和 hook 按英文标识走，飞书查询按绑定时记下的键走。

这一版只认用节点流程的空间。`feishu/ids.json` 还是旧版格式的项目，`setup.py feishu --live` 会提醒按空间重新绑定；旧版结构的空间不迁移，用模板新建一个空间重新初始化。

## 常见问题

**入口说“没有空闲的会话”。** 每个序列的 +2 只有一个，+1 最多三个，+0 最多五个。活留在台账的“待开工”里排队，等有会话交回；要多开 +1，在那个序列 +2 的会话里说一句“补位”，要多开 +0，在它上面那个 +1 的会话里说。

**台账脚本说“还没绑定飞书空间”，或者任务文件里的空间和绑定的不同。** 请初始化会话重新绑定：它运行 `setup.py feishu --live` 预览，核对后加 `--apply`。

**绑定预览说空间里没有一种类型对得上。** 这个名字的空间不是用模板建的。换一个空间名，让初始化会话用模板创建；空间里其实有这些类型、只是名字不同的，用 `--map` 指认，做法见技能 `agent-org:space-bind`。

**要把项目换到另一个飞书项目空间。** 照 setup 技能 `feishu-space.md` 的“换空间”一节做。插件搬不了工作项，旧空间里的工作项留在原处当档案，你确认以后才加 `--leave-old-items` 写入。项目进行中尽量别换空间。

**书记员说“字段还没绑定”。** 看 `feishu/binding.md` 的“要处理的问题”：已经有、只是名字不同的，用 `--map` 指认；空间里确实没有的，把这张表交给模板维护者。

**书记员说“上次已经建了工作项，但没做完”。** 登记到一半失败了，比如建文档时断网。工作项已经在了，回执在 `packages/sent/` 下。修好原因后让书记员加 `--resume` 接着做，它不会再建一个。

**书记员说“上次建文档没有拿到确定的结果”。** 建文档超时，或者返回里没有链接时，文档可能已经建好了。到提示里的节点下看一眼：建好了的，让书记员重跑时加 `--doc <文档链接>`；确认没建成的，加 `--doc new`。

**确认节点被拒，说要先填某个字段。** 那是这一步的必填项，脚本在写之前先问了一遍空间。把值告诉书记员。

**确认节点被拒，说决策不合格。** 签字的那条决策没决定、签字结果不是批准、不属于这条研究任务，或者是在任务走到这一步之前决定的。没决定的等你决定；你确实批准了、只是签字结果或所属研究任务没记上的，请书记员补记后重跑；决定早于这一步的，要你就现在这一步重新决定一次。

**角色会话说登录过期。** 回到初始化会话说“重新登录”，它给你二维码。角色会话自己发起不了登录。

**hook 拦下了一条看起来无害的命令。** 多半是命令里藏着飞书命令行，hook 看不到里面在做什么。把它拆成单条简单命令重试；插件自己的脚本只在内容和清单一致时被信任，改过就会被拦。

**想先在不连飞书的情况下看看会发生什么。** 台账脚本默认只预览；加 `--offline` 连读都不读，只打印命令。

## 还没实测的部分

这一版的初始化流程还没有做现场测试，测完的结果另记在 `docs/Claude实测记录.md`。现在只有离线回归：规则和包检查、初始化和四层检查、hook 的拦截、读空间和绑定、台账的节点流程，都用录下的空间结构和替身命令测过。台账的节点流程命令另外在模板空间的样例工作项上试过一轮（2026-11-12）：读工作项、问下一步、条件查询、改字段、确认、回滚、归档的最后一步，以及签字的前四项核对和冻结核对。

| 环节 | 不成立时 |
| --- | --- |
| 会话发起设备码登录，你扫码完成 | 这个命令行的登录退回你在终端里做 |
