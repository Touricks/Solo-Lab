## 名字

插件在 1.0.0 从 `agent-org` 改名为 `solo-lab`。各处现在的叫法：

| 对象 | 名字 |
| --- | --- |
| 仓库和产品 | Solo-Lab |
| 插件名、市场名、技能前缀 | `solo-lab` |
| 项目里的脚本副本和任务文件 | `.claude/solo-lab/`、`solo-lab.task.json` |
| Codex 适配的安装名、项目目录、AGENTS.md 里的标记 | 沿用 `agent-org`、`.agent-org/` |
| 0.6.0 和更早的记录 | 沿用 `agent-org`，照当时的写法保留 |

Codex 适配不跟着改，因为已有的 Codex 项目里就是这些名字，升级测试要从旧项目升上来。

## 规则

职级、序列、三类包、关系矩阵、交接规则、路由决策表、研究任务怎么推进都在 `orgspec/rules.json`，用不变的英文标识；中文名在 `orgspec/terms.zh.json`。agent 定义、CLAUDE.md 和组织规则全文都由它生成，测试会检查生成物和它一致。改名只改术语表。

不可逆事项清单在 `orgspec/irreversible.json`：五条判据和九个类别，每一类写包括什么（`covers`）、对应哪几条判据（`criteria`），文件开头的说明写了怎么用。它是写决策包和判断可逆性的依据，不给 hook 用：1.0.6 去掉了 1.0.4 加的命令拦截，guard hook 不读清单，也不读本地决策状态，`policy.json` 里没有它。初始化时 setup.py 用它生成 `org/org.md` 的“不可逆事项”一节；orgspec.py 的包检查拿它核对决策包选项表的“不可逆的动作”一列（类别要在清单里，任一选项列了类别的必须写不可逆），“冻结的动作”里写了类别的也照它读；ledger.py 把待定决策的选项和冻结的动作记进本地决策状态 `.claude/state/gates.json`，inbox hook 照它出每轮的冻结提示和到期提示。这个文件随初始化复制进项目的 `.claude/solo-lab/orgspec/`；`orgspec.py check` 一并校验它。

hook 管什么：`scaffold/hooks/guard.py` 守和飞书项目有关的事（只有认领的书记员写飞书和台账，high-risk-write 和带 `--yes` 的命令归研究员，改过的插件脚本里调飞书命令行的按看不见的命令拦下）、编辑工具的路径规则、Agent 调用的规则（派发不带 `name`，不用 Agent 工具派书记员）、池会话在共用目录里的 git 操作、认领、预登记和释放（连同只有研究员的会话运行 `setup.py`，命令不改会话身份变量 `CLAUDE_CODE_SESSION_ID`），和被其他 agent 会话叫醒的轮次里的提问。硬规则的全表在 `skills/setup/references/mechanisms.md`。命令的权限判断交给 Claude Code 自己：表以外的命令 hook 不作答复，不拦、不弹窗，也不答允许。hook 答允许，整条命令就跳过 Claude Code 自己的权限检查，所以允许只答给它整条判过的命令（`feishu_cmd.py` 的 `Parsed.plain`）：只有 `lark-cli`、`meegle` 和本项目的 `ledger.py`，中间可以有 `cd`、`pushd`、`popd`。同一行里还有别的命令、写文件的重定向、`sudo` 这类包装或命令替换的，允许降成不作答复，`guard.jsonl` 记下原因；拒绝和弹窗照旧。改 `guard.py` 的判定或 `policy.json` 的内容时，`setup.py` 和 `guard.py` 里的 `POLICY_VERSION` 一起加一。

飞书空间里有哪些流程、节点怎么排、每一步必填什么，不写在规则里：脚本运行时读空间。脚本按含义处理的类型、字段、角色和状态写在 `orgspec/contract.json`，飞书项目模板见 [feishu-template/](../feishu-template/README.md)。

```bash
python3 -I plugins/solo-lab/scripts/orgspec.py check
```

## 测试

测试都不连飞书，在仓库根目录运行：

```bash
python3 -I -B plugins/solo-lab/tests/test_plugin.py
python3 -I -B plugins/solo-lab/tests/test_delivery.py
python3 -I -B plugins/solo-lab/tests/test_space.py
python3 -I -B plugins/solo-lab/tests/test_ledger.py
python3 -I -B plugins/solo-lab/tests/test_binding.py
python3 -I -B plugins/solo-lab/tests/test_codex.py
python3 -I -B plugins/solo-lab/tests/test_codex_upgrade.py
python3 -I -B plugins/solo-lab/tests/test_initialization.py
```

`test_codex_upgrade.py` 从 git 历史里取旧版的源码，所以要在带完整历史的克隆里跑，取不到时这一组会跳过。

Python 文件每行不超过 1000 字节，长的中文字符串写成相邻的几段，一段一行。Python 3.9 把脚本当文件运行时，超长的行分几段读，哪一段断在汉字中间就报 `SyntaxError: Non-UTF-8 code`；别的测试都是把脚本当模块导入，测不出这一类问题，所以 `test_plugin.py` 里的 `RunAsAFileTest` 单独核对行长，并把 `setup.py` 当文件运行一次。

改 README 时两种语言一起改。`test_plugin.py` 里的 `ReadmeTest` 核对两份的章节数和命令块一致，并且都写着插件清单里的版本号。
