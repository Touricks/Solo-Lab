# 绑定空间

脚本按含义处理的类型、字段、角色和状态叫槽位，列在约定文件 `orgspec/contract.json` 里。绑定就是给每个槽位指定这个空间里的一个对象，结果记在项目的 `feishu/ids.json`。照参考模板建出来的空间，槽位都对得上，绑定不用人管。本技能处理剩下的情况：有槽位没绑上，或者空间里的名字和约定不同。

做法是先看清哪些槽位没绑上。名字不同的，提出对应方案请研究员确认；空间里确实没有的，写成缺项清单交给模板维护者。

绑定只由 `setup.py feishu --apply` 写入，在研究员自己的会话里跑，也就是做初始化的那个会话。池里的角色会话可以读空间、试对应方案，不写绑定。

下面的 `<插件目录>` 是插件根目录，也就是本技能目录往上两级。槽位的全表见技能 `agent-org:ledger` 的 `references/structure.md`。

## 先看核对结果

```bash
python3 -I <插件目录>/scripts/setup.py feishu --target <项目目录> --live
```

这是预览：只读飞书，不写文件。它按任务文件里写的空间读出结构，逐个槽位找对应的对象，再核对流程能不能被脚本推进。输出里看三处：

- “约定核对（…）：通过”或者“约定核对（…）：N 个问题”这一行。
- “绑定结果”表：每个类型槽位绑到了空间里的哪个类型，字段、角色、状态各绑上几个，写成“绑上的 / 约定要的”。类型没绑上的写“没绑定”。
- “要处理的问题”表：对象、问题、怎么办，一行一个问题。

通过的：没用 `--map` 指认过的直接加 `--apply` 写入；用了指认的，请研究员核对绑定结果以后再加。用不着往下做。预览说空间里没有一种类型对得上的，照技能 `agent-org:setup` 用模板建空间；研究员确认空间里其实有这些类型、只是名字不同，才往下做指认。

## 每条问题怎么处理

| “问题”一栏写的 | 是什么情况 | 怎么办 |
| --- | --- | --- |
| “空间里没有这个类型”“空间里没有”（对象是字段） | 可能只是名字不同 | 到快照里找候选。找得到，提对应方案；找不到，进缺项清单 |
| “按“…”找不到类型”“按“…”找不到字段” | `--map` 写的名字空间里没有 | 核对名字；指认类型时要带 `--live` |
| “空间里有 N 个对得上的类型”“有 N 个对得上的字段” | 重名 | 请研究员定用哪一个，`--map` 的值写它的 type_key 或 field_key |
| “空间里这个类型是停用的” | 要改空间配置 | 进缺项清单 |
| “空间里的类型是 …，约定的是…” | 字段类型不对 | 进缺项清单 |
| “缺选项：…” | 单选字段少了脚本要用的选项 | 进缺项清单 |
| 对象是角色或状态，“空间里没有”“有 N 个同名的…” | `--map` 指认不了角色和状态 | 进缺项清单 |
| “读不到流程”“最后一个节点要正好一个…”“负责角色 … 不在约定里”“要正好一个负责角色…”“没有节点把它设成必填…” | 流程不合约定 | 进缺项清单 |

表后的“提醒”不算问题。“…的流程“…”还没有工作项，流程图读不到”：登记第一条以后重读。“…新建时必填的“…”不在约定里”：告诉书记员登记时用 `--set` 按字段名传。

## 提出对应方案

**找候选。** 候选从快照里找：

- 类型：`feishu/space.json` 末尾的 `other_types` 列着没读全的类型，有名字、系统标识和 type_key；`disabled_types` 是停用的类型。
- 字段：`feishu/space.md` 里这个类型一节的字段表，有字段名、field_key、类型和选项。只有自定义字段能指认。

本地还没有这个空间的快照时，先请研究员看预览，同意后加 `--apply` 把现状写入。这一步只写项目里的文件，不改飞书；绑上的槽位能用，没绑上的槽位，用到它的台账命令会停下报错。

**判断是不是同一个东西。** 三样都对得上才提：

- 类型对得上。约定要的字段类型见槽位表，指到类型不对的字段上，核对照样报问题。
- 选项够用。槽位表里“脚本要用的选项”，候选字段都要有。
- 含义一致。看名字，也看它在哪一步是必填。

拿不准的不提，直接问研究员。不拿含义不同的字段顶替。

**请研究员确认。** 把方案列成表，一行一个槽位，研究员逐行确认：

```text
| 槽位 | 约定里叫什么 | 空间里的候选 | 依据 | 参数 |
| --- | --- | --- | --- | --- |
| decision.sign_result | 签字结果，单选，选项批准、退回 | “批不批”，单选，选项批准、退回 | 类型和选项相同，只在决策上有 | --map decision.sign_result=批不批 |
| research_task | 研究任务，主线 | “研究课题”，系统标识 topic | 有验证、试探两个流程 | --map research_task=研究课题 |
```

**预览，再写入。** 研究员确认后带着 `--map` 再预览一遍，问题少了、绑定数满了，再加 `--apply`：

```bash
python3 -I <插件目录>/scripts/setup.py feishu --target <项目目录> --live --map research_task=研究课题 --map decision.sign_result=批不批
python3 -I <插件目录>/scripts/setup.py feishu --target <项目目录> --live --map research_task=研究课题 --map decision.sign_result=批不批 --apply
```

写入的是 `feishu/ids.json`（绑定）、`feishu/space.json` 和 `feishu/space.md`（快照）、`feishu/binding.md`（绑定结果和还缺什么）、`org/phases.md`（研究任务的流程对照）。写入后在项目目录里核对一遍，最后一行以“通过”结尾，或者剩下的问题都已经进了缺项清单：

```bash
python3 -I .claude/agent-org/bin/space.py check --target .
```

## --map 的写法

| 写法 | 指认什么 | 值可以写 |
| --- | --- | --- |
| `--map <类型槽位>=<值>` | 一个类型 | 空间里的类型名、系统标识或 type_key |
| `--map <类型槽位>.<字段槽位>=<值>` | 这个类型上的一个字段 | 空间里的字段名或 field_key |

- 可以写多个。名字里有空格的，整个参数加引号。
- 指认写入一次就够：绑定记的是 type_key 和 field_key，以后重读不带 `--map` 也沿用，类型和字段在空间里改名也不会断。
- 哪些类型是指认过的，看 `feishu/ids.json` 的 `meegle.types`：某个槽位记下的 `api_name` 和槽位标识不同，`name` 也和约定里的名字不同，它就是指认过的。
- 只指认字段时不用读飞书。在项目目录里跑 `python3 -I .claude/agent-org/bin/space.py bind --target . --map <类型槽位>.<字段槽位>=<字段名>`，它照本地的快照算一遍，只打印绑定结果和问题，不写文件。
- 角色、状态、系统字段和流程指认不了，只能改空间。

## 给模板维护者写缺项清单

空间是用模板建出来的，缺的东西要在模板里补。清单交给研究员，由研究员转给模板维护者；模板更新、空间重建或补齐以后，重跑 `setup.py feishu --live`。

清单这样写：

1. 开头写明空间名、约定的版本（核对输出里的 `contract_version`）和日期。
2. 把“要处理的问题”表里靠指认解决不了的各行抄进来，对象、问题、怎么办三栏照原样，不改写。
3. 另列一段“已经指认、不用改空间的”，写上用过的 `--map` 参数。
4. 提醒模板维护者：类型的系统标识、角色 id 照槽位标识填，名字照约定里的名字写。绑定先认标识，再认名字，照这样建，下次绑定不用指认。

清单不写进 `feishu/binding.md`，它每次绑定都会重新生成。

## 换模板或模板大改之后

- 模板改了流程、表单、字段或选项，槽位都还在：不用重新指认。重跑 `setup.py feishu --live`，指认过类型的带上原来的 `--map`。预览里的“变化：”各行就是结构上的改动，核对通过后加 `--apply`。
- `space.py check` 报“绑定按约定第 … 版做的，插件现在是第 … 版”：插件升级后约定的槽位增减过，从“先看核对结果”重新走一遍。
- 项目换到另一个空间：预览会打印“换空间”，`feishu/binding.md` 多出“换空间”一节。旧空间的工作项搬不过来，研究员确认它们留在旧空间以后，才加 `--leave-old-items` 写入。步骤照技能 `agent-org:setup`。

## 不做的事

- 不在网页上改空间配置：不建、不改、不删类型、字段、角色、状态和流程，也不启用停用的类型。缺的东西报给模板维护者。
- 不拿别的字段顶替，不为了让核对通过去指认含义不同的对象。
- 用了 `--map` 指认的绑定，研究员没核对预览，不加 `--apply`。
- 不删飞书里的任何东西。
