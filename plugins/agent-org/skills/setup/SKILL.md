# 初始化智能体组织

插件装一次，每个项目初始化一次。研究员只做一件事：在项目目录开一个会话，说一句“用 agent-org 初始化这个目录”。其余由这个会话做完。它叫初始化会话，做完以后留作研究员自己的会话，用来重新登录、检查和升级。

中途要研究员动手的只有两种情况：命令行登录失效时扫一次码，客户端弹出确认框时点一下。

| 步 | 做什么 | 写不写飞书 |
| --- | --- | --- |
| 1 | 开始计时，前置检查 | 不写 |
| 2 | 登录：只在有命令行登录失效时做 | 不写 |
| 3 | 写任务文件，生成项目文件 | 不写 |
| 4 | 找项目空间，没有就用模板创建 | 新建项目空间 |
| 5 | 绑定项目空间，找到或新建知识空间 | 新建知识空间 |
| 6 | 开池；书记员建节点、登记首条研究任务 | 新建节点、研究任务和主文档 |
| 7 | 写 `.env` | 不写 |
| 8 | 补读流程，四层检查 | 只读 |
| 9 | 结束计时，交接 | 不写 |

## 开始之前

### 插件目录和两类脚本

插件根目录是本技能目录往上两级。先把它解析成绝对路径，下面的命令里 `$PLUGIN` 指这个路径，`<项目目录>` 是项目目录的绝对路径。两个路径写进命令时都加双引号：路径里常有空格和方括号。

- 插件自带的脚本：`python3 -I "$PLUGIN/scripts/setup.py" <子命令>`。项目目录用 `--target` 给，在哪里运行都行。
- 项目里的副本：`python3 -I .claude/agent-org/bin/<脚本>`。第 3 步生成以后才有，在项目目录里照这个写法原样运行，前面不加环境变量，后面不接管道。

### 支持的环境

只支持 Claude 桌面端。本会话要有开会话的工具 `start_session`，还要有给别的会话发消息的工具。

- 两样都没有，比如终端里的 `claude`：停下，告诉用户这一版只支持 Claude 桌面端，请他在桌面应用里选中项目目录新开一个会话，再说这句话。不换成别的做法。
- 工具都有，第 6 步开第一个会话却失败：走第 6 步的回退档。

### 项目目录

项目目录就是本会话所在的目录。

- 家目录和根目录不初始化，已经有另一运行平台的组织（`.agent-org/manifest.json`）的目录也不初始化。这两种情况 `init` 会报错停下。
- 用户另指目录的：用 `change_directory` 切过去，结束本轮，请用户回一句“继续”。工作目录到本轮结束才切换，后面的步骤要在项目目录里运行。

### 默认值

用户那句话里说了的照用，没说的取默认值，不停下来问。

| 项 | 默认值 |
| --- | --- |
| 项目名（任务文件的 `name`） | 用户说的名字；没说用目录名 |
| 描述（`description`） | 用户的原话；没说写“待立项访谈补充”，交接时提醒 |
| 飞书项目空间（`feishu.meegle_space`） | 等于项目名。按名字精确查找：没有就用模板创建，有一个就沿用，两个以上停下列出 |
| 知识空间（`feishu.wiki_space`） | 等于项目名。翻完全部分页再判断：没有就新建，有一个就沿用，两个以上停下列出 |
| 模板（`feishu.template_url`） | 不写，用约定文件 `orgspec/contract.json` 里的参考模板链接 |
| 会话池 | 19 个会话：七个序列各一个 +2，路由和书记员，外联以外的五个序列各一个 +1 和一个 +0。外联开池只开 +2（`pool.later` 默认是 `["liaison"]`） |
| 模型（`models`） | +2 用 opus，+1 和 +0 用 sonnet，书记员用 haiku，质量 +1 用 opus。高于本会话的会被客户端降档，差异记进交接 |
| 权限模式 | 全池和本会话一致：开会话时不填权限模式 |
| 会话标题和侧栏分区 | 标题是 `[<飞书项目空间名>] <会话名>`，会话都归入同名的分区，不置顶。标题要在 60 个字符以内：空间名太长或带方括号时，在任务文件里写 `pool.label` 另指一个短名 |
| 可写路径和只读路径（`editable_paths`、`protected_paths`） | 空着，交接时提醒 |

### 授权：打印一次清单，不等回复

开场那句话就是授权。开工前把将要新建的东西打印一次，接着往下做，不等回复：

```text
将要新建（已经有的直接沿用，不重复建）：
- 飞书项目空间 1 个：<空间名>，用模板创建
- 飞书知识空间 1 个：<知识空间名>
- 知识库节点 21 个
- 研究任务 1 条和它的主文档
- 桌面会话 19 个，侧栏分区 1 个：<分区名>
- 项目目录里的 CLAUDE.md、.claude/、org/、packages/、inbox/、spec/、feishu/、runs/，以及 .env 里的两行链接
```

新建以外的动作一律停下问：删除、覆盖、改已有的对象、改分享权限。下面几种情况也停下，把脚本的原话报给用户：

- 同名的飞书项目空间或知识空间有两个以上。
- 同名的项目空间已经有了，约定核对没通过。
- `init --apply` 报告目录里原来就有同名文件，新版本写成了 `.new`。
- 页面上出现升级提示、付费弹窗、权限申请或没见过的对话框。

### hook 生效以后

第 3 步的 `init --apply` 把 hook 写进项目的 `.claude/settings.json`。hook 在本会话里什么时候开始生效，没有实测。生效以后会遇到两件事：

- 项目里的脚本照规定的写法运行，不受影响。写台账的 `ledger.py` 命令只有书记员能运行，本会话不运行。
- 插件目录里的 `setup.py`、`space.py`、`onboarding.py`：`init --apply` 把它们的路径和内容校验值记进项目清单，hook 照这份记录放行本会话运行它们，bypass 模式下也一样；角色会话运行 `setup.py` 会被拒绝。命令里的插件路径就写初始化时用的那个绝对路径。插件升级或换了位置以后记录对不上，hook 会拦：默认权限模式下弹确认，请研究员点允许；bypass 和 dontAsk 模式下直接拒绝，这时把第 3 步 `init --apply` 那条完整命令交给研究员在终端里运行一次，记录更新后就恢复。不改写命令去绕开 hook。

### 计时

`onboarding.py` 按阶段计时。第 3 步之前项目里还没有它，用插件目录里的那份，带 `--target`：

```bash
python3 -I "$PLUGIN/scripts/onboarding.py" start <阶段> --target <项目目录>
```

```bash
python3 -I "$PLUGIN/scripts/onboarding.py" end <阶段> --target <项目目录>
```

第 3 步以后用项目里的副本，在项目目录里运行：

```bash
python3 -I .claude/agent-org/bin/onboarding.py start <阶段>
```

```bash
python3 -I .claude/agent-org/bin/onboarding.py end <阶段>
```

| 阶段 | 归类 | 包住什么 | 谁打点 |
| --- | --- | --- | --- |
| `precheck` | 本机 | 第 1 步的 `setup.py precheck` | 本会话 |
| `login` | 等人 | 第 2 步，从发出二维码到读回已登录 | 本会话 |
| `init` | 本机 | 第 3 步和第 5 步的 `init --apply` | 本会话 |
| `project_space` | 飞书操作 | 第 4 步，从第一次查空间到预览能读到空间，创建空间也在里面 | 本会话 |
| `binding` | 飞书操作 | 第 5 步的 `feishu --live --apply` | 本会话 |
| `sessions` | Claude 平台 | 第 6 步开会话和预登记 | 本会话 |
| `claims` | Claude 平台 | 第 6 步等认领、核对认领 | 本会话 |
| `detach` | Claude 平台 | 第 6 步把会话移到顶层 | 本会话 |
| `section` | Claude 平台 | 第 6 步建分区、归入分区、改标题 | 本会话 |
| `prompts` | Claude 平台 | 等研究员点目录信任和客户端确认框 | 本会话 |
| `nodes` | 飞书操作 | 建知识库节点 | 书记员 |
| `first_task` | 飞书操作 | 登记首条研究任务 | 书记员 |
| `env` | 本机 | 第 7 步 | 本会话 |
| `readback` | 飞书操作 | 第 8 步的补读和 `check --live` | 本会话 |

- 阶段名只能用表里的。脚本里还有一个 `wiki_space`（知识空间的查找和新建）：它和绑定在同一条命令里，分不开，时间记在 `binding` 里，不单独打点。
- 同一个阶段可以记多次。上一次没 `end`，不能再 `start`；不同的阶段可以重叠。
- 只有归类是“飞书操作”的阶段计入 300 秒这个指标。它只是指标，不影响第 8 步的结论。
- 计时命令报错不拦初始化：报错就跳过，接着做。

## 第 1 步：开始计时，前置检查

```bash
python3 -I "$PLUGIN/scripts/onboarding.py" begin --target <项目目录>
```

重复运行不会重置起点。上一次初始化已经结束的，这次记成“补齐”，和首次分开。

```bash
python3 -I "$PLUGIN/scripts/setup.py" precheck
```

打点：`precheck`。它逐项打印“通过、提醒、失败、跳过”，最后一行是“预检：没有失败项。”或“预检：N 项失败。”。

- “lark-cli 用户身份”或“meegle 登录”失败：做第 2 步。
- 版本太低、诊断上报这类要升级或改设置的：把命令给研究员，由他本人执行，不代跑。
- “飞书项目权限”是提醒、说明写着“这个账号还看不到任何空间”：接着做，第 4 步用模板建出项目空间。
- 其余各项的含义和处理办法见 `references/precheck.md`。

## 第 2 步：登录

前置检查里登录都通过的，跳过这一步。

```bash
python3 -I "$PLUGIN/scripts/setup.py" login
```

它给登录失效的那个命令行发起设备码登录，两个都失效就各发起一次。每个命令行打印三行：“<命令行>：请研究员扫码或打开链接授权，N 分钟内有效。”、二维码图片的路径、链接。把图片和链接交给研究员，开始给 `login` 打点。设备码不打印，本会话不接触密码、验证码和令牌。

研究员说扫好了，或者过一会儿，读回登录状态：

```bash
python3 -I "$PLUGIN/scripts/setup.py" login --wait
```

| 输出 | 怎么办 |
| --- | --- |
| “<命令行>：已登录。” | 结束 `login` 打点，接着做 |
| “<命令行>：还没授权，二维码还有 N 分钟有效；…” | 提醒研究员扫码，再运行一次 `login --wait` |
| “<命令行>：授权超时，这次的二维码作废；重新运行 setup.py login。” | 从 `setup.py login` 重来 |
| “出错：<命令行> 的设备码登录没发起成…” | 这个命令行的登录请研究员在自己的终端里做，做完重跑第 1 步的前置检查 |

- `--wait` 最多等 300 秒。运行命令的超时比它短时，加 `--timeout <秒数>`，没等到就再运行一次。
- 不直接运行 `lark-cli auth login` 和 `meegle auth login`：登录只走 `setup.py login` 这一个入口。项目初始化以后，直接运行它们会被项目权限和 hook 拒绝。
- 以后角色会话报“登录过期”，也回到本会话做这一步。角色会话运行 `setup.py login` 会被 hook 拒绝。

## 第 3 步：写任务文件，生成项目文件

任务文件只放脚本和 hook 要用的几项，不写研究内容。照“默认值”写成 `<项目目录>/agent-org.task.json`：

```json
{
  "name": "<项目名>",
  "description": "<一句话描述>",
  "feishu": {
    "meegle_space": "<飞书项目空间名>",
    "wiki_space": "<知识空间名>"
  }
}
```

- 必填的只有 `name`、`description` 和 `feishu.meegle_space`。
- `feishu.wiki_space` 不写也能绑定，脚本会用项目名；但 `CLAUDE.md` 里知识库一栏会显示“未填”，所以照样写上。
- 用户说了别的设置才加别的项：`editable_paths`、`protected_paths`、`models`、`pool`（`p1`、`p0`、`later`、`max_sessions`、`label`）、`feishu.template_url`。格式见 `$PLUGIN/scaffold/task.example.json`。
- 目录已经初始化过的（有 `spec/task.json`）：不重写任务文件，`--task` 指原来的任务文件；找不到原文件就指 `spec/task.json`。

```bash
python3 -I "$PLUGIN/scripts/setup.py" init --target <项目目录> --task <项目目录>/agent-org.task.json --apply
```

打点：`init`。看两处：

- 最后一行“已写入 N 处。”。同样的输入再运行一次，是“已写入 0 处。”。
- “合计”一行。里面有“本地改过，新版本写 .new”或“内容不同，.new 已存在”，说明目录里原来就有同名文件，脚本没有覆盖它。把这些文件列给用户，停下，请他对照合并。`CLAUDE.md` 和 `.claude/settings.json` 没合并以前不开池：会话读不到组织规则，hook 也没装上。

输出里的“提醒：任务文件没有写 editable_paths…”“提醒：任务文件没有写 protected_paths…”记进交接。“提醒：项目还没绑定飞书空间”是下两步的事。

`init` 还生成一份最小研究任务单草稿 `packages/drafts/pmo/研究任务单-首条.md`，第 6 步由书记员登记；已经有这份草稿就不动它。只启用部分序列用 `--sequences`，项目管理和质量必须启用。生成了哪些文件、各自管什么，见 `references/mechanisms.md`。

| 报错 | 怎么办 |
| --- | --- |
| “不在家目录或根目录里初始化：换一个只放这个项目的目录” | 请用户指一个项目目录 |
| “目标目录已有另一运行平台的组织。…” | 停下，请用户换一个独立的目录 |
| “研究任务里有不认识的字段：…” | 照列出的可写字段改任务文件 |
| “研究任务的 mode 只支持 pool（桌面会话池）：…” | 删掉任务文件里的 `mode` 一行 |

## 第 4 步：找项目空间，没有就用模板创建

先预览。它读 `spec/task.json` 里写的空间，只读飞书，不写文件：

```bash
python3 -I "$PLUGIN/scripts/setup.py" feishu --target <项目目录> --live
```

打点：`project_space`，到预览能读到空间为止。约定核对有问题，或者空间里没有一种类型对得上时，这条命令的退出码是 1；预览和写入都一样。

| 输出 | 意思 | 怎么办 |
| --- | --- | --- |
| “出错：没有叫“<空间名>”的飞书项目空间，什么都没写。用模板建一个：…” | 空间不存在 | 照 `references/create-space.md` 用模板创建，建好重跑这条命令 |
| “出错：按“<空间名>”找到 N 个飞书项目空间，要正好一个。候选：…” | 同名空间不止一个 | 停下，把候选列给用户。他选定后把 simple_name 或 project_key 写进任务文件，重跑第 3 步 |
| “约定核对（contract_version 1）：通过” | 空间符合约定 | 做第 5 步 |
| “约定核对（…）：N 个问题，见 feishu/binding.md 的“要处理的问题””，后面还有一句“空间“<空间名>”里没有一种类型对得上插件的约定。…” | 这个名字的空间不是用模板建的 | 停下问用户：换一个空间名，还是这个空间里的类型只是名字不同 |
| 只有“约定核对（…）：N 个问题…”，没有后面那一句 | 空间认出来了，个别槽位对不上 | 停下。名字不同的用技能 `agent-org:space-bind` 提出对应方案；空间里确实没有的，把问题表交给用户转给模板维护者 |

预览末尾打印 `feishu/binding.md` 的全文。新空间里没有工作项，“提醒”一节会有几条“…还没有工作项，流程图读不到；登记第一条以后重读”，这是正常的，第 8 步补读。

预览也查知识空间。打印“提醒：有 N 个知识空间叫“<名字>”…”的，停下把这些 space_id 列给用户。

## 第 5 步：绑定

```bash
python3 -I "$PLUGIN/scripts/setup.py" feishu --target <项目目录> --live --apply
```

打点：`binding`。它读空间结构，把约定里的槽位绑到这个空间，写入 `feishu/ids.json`（绑定）、`feishu/space.json` 和 `feishu/space.md`（空间结构）、`feishu/binding.md`、`org/phases.md`。知识空间找不到同名的，这一次新建，打印“知识空间：没有叫“<名字>”的，已新建。”。

- 最后一行是“已写入 feishu/ids.json、…。”，上面有“约定核对（contract_version 1）：通过”，才算绑上。
- “提醒：新建知识空间没有拿到 space_id。…”：先在网页上看它建出来没有，再重跑这条命令，已经建出来的会被找到并沿用。
- “提醒：没能读回知识空间：…”：多半是 lark-cli 的登录失效，做第 2 步后重跑。
- “提醒：lark-cli whoami 里没有用户身份的 open_id；飞书私聊监听不会启动”：不影响初始化，记进交接。

绑定写入以后重跑一次 `init --apply`，让 `CLAUDE.md` 和开池清单带上空间的标识和名字（打点：`init`）：

```bash
python3 -I "$PLUGIN/scripts/setup.py" init --target <项目目录> --task <项目目录>/agent-org.task.json --apply
```

然后核对一次：

```bash
python3 -I "$PLUGIN/scripts/setup.py" check --target <项目目录>
```

这时该看到“本地配置：就绪”，“飞书”一层只剩“知识库节点还缺 21 个…”。

- “飞书”一层报“飞书项目空间还没绑定”：绑定没写进去，回到本步开头。
- 报“还没有知识空间”：知识空间没找到也没建成，看上一条命令的“提醒”，处理后重跑。
- “会话”和“首条研究任务”两层这时有问题是正常的，第 6 步做完才就绪。

空间的三层关系、绑定怎么匹配、换空间，见 `references/feishu-space.md`。

## 第 6 步：开池

```bash
python3 -I "$PLUGIN/scripts/setup.py" pool --target <项目目录>
```

只读。第一行是“开池清单：<项目名>（共 19 个会话，总上限 30）。会话标题的前缀和侧栏分区的名字：<分区名>”。下面按开的顺序列出每个会话的 name、title、model、prompt、background 和 expect，书记员 `PMO-p0-01` 排第 1 个。

### 默认档：本会话开出全部会话

照清单的顺序，每个会话做两件事（打点：`sessions`）：

1. 用 `start_session` 开。`initiation` 写 `user_asked`，`context` 写 `fresh`，`use_worktree` 写 `false`，权限模式不填；`name`、`title`、`model`、`prompt`、`background` 照清单原样填。
2. 拿到返回的会话 ID，马上运行清单里这个会话的 expect 命令：

   ```bash
   python3 -I .claude/agent-org/bin/route.py expect <会话名> --role <角色> --desk <开会话时返回的会话 ID>
   ```

   输出“已预登记 <会话名>（<角色>），桌面会话 <ID>。对方运行 route.py claim 时转正。”就登记上了。+2 的开局句自己能认领，可能赶在预登记前面，这时输出“…已经由这个会话认领，不用再预登记。”，也算成功。

顺序和分批：

- 第 1 个开书记员。它的 prompt 比别的长，认领以后接着做两件初始化写入，见下一小节。
- 其余的每批至多 4 个，这一批都认领了再开下一批。
- 清单里标着“已认领，不用再开”的跳过。中断以后重跑，从没认领的接着开。

看认领（打点：`claims`）：

```bash
python3 -I .claude/agent-org/bin/route.py pool
```

第一行是“会话池：N 条认领，M 条待转正的许可，上限 30 个会话。”。还没认领的列成“- 待转正：<会话名>（<角色>），预登记方 researcher”。

开完一批先查一次。还有待转正的，结束本轮：子会话首轮结束时应用会把本会话叫起来，叫起来以后再查。这个办法没有实测；等不来的话，请用户回一句“继续”。

| 情况 | 怎么办 |
| --- | --- |
| 第 1 个会话就开不出来 | 走回退档 |
| 中途某一个开不出来 | 记下名字，接着开别的，最后一并报给用户 |
| `model` 填不进去 | 不填，开好以后告诉用户哪几个要改模型 |
| 过了一两分钟还是“待转正” | 给这个会话发一条消息，请它重新运行 prompt 里的认领命令。子会话等预登记最多 60 秒，超时会报“没有找到本会话认领 … 的许可” |
| 子会话停在目录信任或权限确认框上 | 请研究员到侧栏点开它处理，这段时间记 `prompts` |

### 书记员的两件初始化写入

飞书一侧还缺东西，或者还没登记过研究任务时，清单里书记员的 prompt 带着这一段。它认领以后接着做：

1. `ledger.py ensure-node all --apply`：在知识空间里建 21 个节点。已经有同名节点的直接用，不再建。
2. `ledger.py query tasks`：空间里已经有研究任务就跳过；没有就运行 `ledger.py register packages/drafts/pmo/研究任务单-首条.md --apply`，登记首条研究任务。

两件各用 `nodes`、`first_task` 打点。做完它回话，写明建了几个节点、沿用了几个，研究任务的工作项 ID 和主文档链接；哪条命令失败，原样贴出报错。

本会话不替它写：台账的写命令只有唯一认领的书记员能运行。等其余会话认领的同时等它回话。

| 书记员回话里的情况 | 怎么办 |
| --- | --- |
| “这个项目还没绑定飞书空间”或“ids.json 里没有知识空间 space_id” | 回第 5 步，做完给它发消息让它接着做 |
| “上次已经建了工作项 #…，但没做完（停在：…）” | 让它运行 `ledger.py register packages/drafts/pmo/研究任务单-首条.md --resume --apply`，不重新登记 |
| “…建主文档没有拿到确定的结果…”或“上次建文档没有拿到确定的结果…” | 照报错到网页上核对文档建出来没有，再让它带 `--resume --doc <文档链接>` 或 `--resume --doc new` 重跑 |
| 登录过期、没有权限 | 做第 2 步，再让它接着做 |
| 认领以后没做这两件 | 把 `.claude/agent-org/pool-plan.json` 里 `scribe_first` 那一段话发给它 |

### 全部认领以后

```bash
python3 -I "$PLUGIN/scripts/setup.py" pool --target <项目目录>
```

末尾是“当前：19/19 条认领；入口 1 条，书记员 1 条；待转正的许可 0 条。”和“会话池已开齐。…”，就开齐了；会话数跟着清单走。

等书记员的两件写入也做完，再做下面四件事。会话移到顶层以后，它结束一轮时应用不再叫醒本会话。

1. 移到顶层（打点：`detach`）：对开出来的每个会话调 `detach_session`。留在本会话下面的会话，会随本会话一起归档。
2. 找分区（打点：`section`）：`list_sections` 里找名字等于分区名的，没有就用 `create_section` 建一个。
3. 归入分区：调一次 `move_sessions`，`session_ids` 写全部会话的 ID 再加 `self`，`section_id` 写分区的 ID。默认权限模式下移动别的会话要研究员点一次确认。
4. 本会话的标题是应用自动起的，用 `set_session_title` 改成 `[<分区名>] Researcher`；用户自己起的不动。

这四件都没有实测：

- `detach_session` 失败，或者移到顶层以后会话之间的消息送不到：不再移，会话留在本会话下面，交接时告诉研究员不要归档本会话。
- `move_sessions` 失败或被拒：给每个会话发一条消息，请它用 `move_sessions` 把自己（`self`）归入这个分区。移动自己不用确认。

### 回退档：研究员手工开七个 +2

本会话开不了会话时用，比如它是别的会话代开的。

1. 改任务文件，把项目管理以外、已启用的序列都写进 `pool.later`，重跑第 3 步的 `init --apply`。开池清单缩到 9 个：七个 +2、路由、书记员。

   ```json
   "pool": {"later": ["product", "alg", "rnd", "infra", "quality", "liaison"]}
   ```

2. 打印手工开池的做法：

   ```bash
   python3 -I "$PLUGIN/scripts/setup.py" pool --target <项目目录> --manual
   ```

3. 请研究员照它做：在桌面应用里新建 7 个会话，目录选本项目，不开 worktree，模型照括号里的选，每个粘贴清单里的一句。hook 按这句话认领。项目管理 +2 在首轮开出路由和书记员。
4. 这样开出来的书记员，prompt 里没有两件初始化写入。`setup.py pool --manual` 的输出里有一行“书记员认领以后，把这段话发给它…”，它认领以后把这段话发给它；本会话发不了消息，就请研究员点开书记员的会话粘贴。
5. 每个 +2 认领以后把自己的标题改成 `[<分区名>] <会话名>`，归入分区。第 8 步带 `--sessions` 的检查会列出没改、没归的，请研究员在那个会话里交代一句。
6. 各序列的 +1、+0 开池时不建。某个序列第一次有活时，研究员在它的 +2 会话里说一句“补位”。
7. 项目管理 +2 首轮开不出路由和书记员的：请研究员再手工建两个会话。本会话用 `list_sessions` 查到它们的会话 ID，各运行一次 `route.py expect`，研究员再把默认清单里这两个会话的 prompt 粘贴进去。这条路没有实测。

核对还是用 `setup.py pool`，认领数等于清单的会话数就开齐了。

## 第 7 步：写 .env

等书记员的两件写入都做完再写。知识空间的链接要用租户域名，它在首条研究任务登记完、第一篇文档建出来以后才记进 `feishu/ids.json`。

```bash
python3 -I "$PLUGIN/scripts/setup.py" env --target <项目目录> --apply
```

打点：`env`。它往项目目录的 `.env` 写两行，`FEISHU_PROJECT_URL` 和 `FEISHU_WIKI_URL`，都从 `feishu/ids.json` 生成。`.env` 里的其他行不动，也不显示；只写链接，不写令牌和密码。

- 成功是“已写入 .env。”；已经是这两行就打印“.env 已经是这样，没有改。”。
- “出错：…知识空间的链接还拼不出来：…”：租户域名还没记下，它在书记员登记第一份文档以后才记进 `feishu/ids.json`。等首条研究任务登记完再运行。
- 知识空间链接的格式没有实测。交接时请研究员点一下，打不开就记下来报给插件维护者。

## 第 8 步：补读流程，四层检查

打点：`readback`，包住本步的两条命令。

流程图只能从一条工作项读出来。首条研究任务登记以后重读一次，验证流程的节点、负责角色和必填项才进 `feishu/space.md` 和 `org/phases.md`：

```bash
python3 -I "$PLUGIN/scripts/setup.py" feishu --target <项目目录> --live --apply
```

再取会话列表：调 `list_sessions`，`include_archived` 写 `true`，`limit` 写 200。把返回的 JSON 数组原样存成一个文件，放在系统临时目录里，不放进项目目录。

```bash
python3 -I "$PLUGIN/scripts/setup.py" check --target <项目目录> --live --sessions <会话列表文件>
```

它分四层报告，每层一行“就绪”或“N 个问题”，下面列“提醒：”和“问题：”。四层都就绪，最后一行是“检查：四层都就绪”，退出码 0；有问题时退出码是 1。`--live` 只读回读飞书。

| 层 | 核对什么 | 常见的问题和办法 |
| --- | --- | --- |
| 本地配置 | 项目文件和现在的插件、规则、绑定对得上 | “现在的插件、规则或 feishu/ids.json 生成的内容和初始化时不同…”：重跑第 3 步的 `init --apply`。“待合并：….new”：请用户合并 |
| 飞书 | 绑定、知识空间、21 个节点、`.env` 的两行；`--live` 再回读空间结构和每个节点 | “知识库节点还缺…”：让书记员运行 `ledger.py ensure-node all --apply`。“项目目录的 .env 还没有…”：做第 7 步。“空间结构：…”：空间配置改过，用技能 `agent-org:space-bind` 处理 |
| 会话 | 清单里的会话都已认领，入口和书记员各一条，没有剩下的预登记，权限模式同一类，工作目录是项目目录；带 `--sessions` 再核对会话还在、没归档、都在分区里 | “会话池还没开齐：…”：回第 6 步补开。“有 N 条预登记还没转正：…”：给那个会话发消息让它重新认领。“客户端的会话列表里没有这些认领的会话…”：先把 `limit` 写大重取一次列表。“不在侧栏分区…”：重做归入分区 |
| 首条研究任务 | 有登记回执、回执里有主文档地址、草稿的“关联工作项”是真实 ID；`--live` 再回读工作项、主文档和它的上一级节点 | “还没有登记过研究任务…”：让书记员做第 6 步的第二件写入 |

“提醒：”不算问题，比如“…的流程“试探”还没有工作项，流程图读不到”。标题和置顶对不上也只是提醒。

有问题就照表处理，再运行一次检查。处理不了的，原样写进交接。

## 第 9 步：结束计时，交接

```bash
python3 -I .claude/agent-org/bin/onboarding.py finish
```

它打印全程耗时和四类各自的耗时，“飞书操作”一行写着“指标 300 秒以内：达到”或“超过”，超过时再列最慢的 3 段。报“还有没结束的阶段：…；先 end”的，把那几个阶段 `end` 掉再运行。

交接时告诉用户：

- **结果。** 四层检查各层的结论。没就绪的层，列出问题和该谁来做。
- **新建和沿用了什么。** 项目空间、知识空间、节点数、研究任务的工作项 ID 和主文档链接、会话数、分区名、`.env`。
- **耗时。** `finish` 的输出原样给出，再加上研究员扫了几次码、点了几次确认框。
- **和默认不一样的地方。** 被降档的模型，没开出来的会话，走了回退档，会话没移到顶层。
- **还空着的。** 描述是“待立项访谈补充”；`editable_paths`、`protected_paths` 没写，工程序列改不了代码，评测文件没有只读保护；外联的 +1、+0 没开，第一次要出材料时在外联 +2 的会话里说一句“补位”。
- **请研究员做的。** 打开 `org/decisions.md`，开头列着插件定下的几处安排，逐条确认或推翻；点一下 `.env` 里的两条链接。
- **怎么开始。** 在侧栏分区里找 `[<分区名>] PMO-p2-01` 说话，想直接找某个序列就点开它的会话。本会话留着，不要归档。

## 初始化之后

首条研究任务是照项目名和一句话描述生成的，停在第一步“确定目标”。接下来的事不在初始化里做：

- 研究员在入口说“立项”。入口用技能 `agent-org:charter` 访谈研究员，把修订稿另存成新的草稿，请书记员换成这条研究任务的主文档。书记员先预览，再加 `--apply`：

  ```bash
  python3 -I .claude/agent-org/bin/ledger.py register <修订稿> --existing <研究任务的工作项 ID>
  ```

  工作项不变，它还在第一步时才能换；原来那份文档留在原处。
- 可写路径、只读路径在设计阶段由算法 +2、质量 +2 用 `agent-org:spec` 定下。研究员同意后，在本会话里改任务文件，重跑第 3 步的 `init --apply`。

## 不做的事

- 登录由本会话发起，研究员扫码完成。不直接运行命令行自己的登录命令，不接触密码、验证码和令牌。
- 用模板创建项目空间是默认动作，不另行确认。搭建和修改模板归模板维护者：空间缺什么报给他，不在网页上改空间配置。
- 不删飞书里的任何东西。删空间、删类型、删字段、删工作项只能研究员本人做，终止工作项也由他在网页上做。
- 不配置视图：初始化和各角色都不建、不改、不查视图，读台账只走 `ledger.py` 的条件查询。
- 不开通飞书权限，不升级命令行工具，不改 meegle 的诊断上报设置。这几样把命令给研究员，由他本人执行。
- 不替书记员写台账，不在初始化里做研究访谈和业务派活。
- 不运行插件的开发测试。
