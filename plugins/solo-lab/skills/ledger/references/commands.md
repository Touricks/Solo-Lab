# 台账脚本的命令

脚本在项目的 `.claude/solo-lab/bin/` 下，插件里的原件在 `scripts/`：读台账的 `ledger.py`（谁都能用），写文档的 `docs.py`（文档谁负责谁写，脚本核对运行它的会话），写工作项的 `workitem.py`（只有书记员）。在项目目录里运行，照 `python3.12 -I .claude/solo-lab/bin/<脚本> <子命令> …` 的写法，项目权限只放行这种写法。

它们读三样东西：

| 文件 | 里面是什么 | 谁写 |
| --- | --- | --- |
| `feishu/ids.json` | 绑定：project_key，约定里每个槽位对应这个空间的哪个类型、字段、角色和状态，知识库空间和节点 | `space.py feishu --apply`；`ensure-node` 往里加节点 |
| `feishu/space.json` | 空间结构的快照：每个类型的字段和选项、角色、状态、流程、新建时的必填字段 | `space.py feishu --live --apply`、`space.py snapshot --apply` |
| `.claude/solo-lab/orgspec/` | 规则文件、术语表和约定文件：包名、命名、文档放在哪、槽位 | 初始化时从插件复制 |

字段名和选项名靠快照换成空间里的键。节点不看快照，每次从这条工作项现读。

## 三种运行方式

| 方式 | 怎么进入 | 读飞书 | 写飞书 |
| --- | --- | --- | --- |
| 预览 | 默认 | 真读 | 不写，打印“将执行：<命令>” |
| 执行 | 写命令加 `--apply` | 真读 | 真写。每条写命令记进 `feishu/write-log.jsonl`，带着是哪个会话写的；确认和回滚写完回读节点，登记写完核对角色人员 |
| 离线 | `--offline` 放在子命令前 | 不读，打印“将读取：<命令>” | 不写。用于测试和没网时看命令 |

- 写命令先预览，核对打印出来的 meegle 和 lark-cli 命令，再加 `--apply`。预览里的结果行以“预览：会…”开头，最后一行是“这是预览，没有写飞书。核对后加 --apply 执行。”；以“上传：”“登记：”“修订：”“验收：”“确认：”“回滚：”“归档：”开头的行才是写成了。
- `--apply` 运行期间占着写锁 `feishu/.ledger.lock`，同一时间只有一条写命令在跑，后来的最多等 60 秒。
- 退出码：0 是做完了；1 是出错，输出以“出错：”开头；2 是参数不对。

## 通用的写法

工作项 ID 写数字，比如 `2101`，不带 `#`：shell 把 `#` 开头的词当注释。`--source`、`--task`、`--decision` 的值也写数字。没建工作项的任务写它的编号，比如 `2101-3`：读命令和 `docs.py` 的 `accept`、`revise`、`append` 认它，`workitem.py` 不认。

`--type <类型槽位>` 在 confirm、rollback、update 上有，读不出工作项的类型时才要写，离线预览一定要写。类型槽位是 `research_task`、`same_seq`、`cross_request`、`decision`、`feedback`。

### 字段怎么写

`--set <字段>=<值>` 在 `workitem.py` 的 register、confirm、update 上有，可以重复。字段有三种写法：

| 写法 | 例子 | 说明 |
| --- | --- | --- |
| 空间里的字段名 | `--set 成功标准=…` | 这个类型的字段都能这样写；同名字段不止一个时认不出，改写 field_key |
| 槽位标识 | `--set main_doc=…` | 约定里的字段才有，标识见 `structure.md` 的槽位表 |
| field_key | `--set <field_key>=…` | 从 `feishu/space.md` 这个类型的字段表里查 |

### 值怎么写

| 字段类型 | 怎么写 | 例子 |
| --- | --- | --- |
| 单行文本、多行文本、链接 | 照原样写 | `--set 成功标准='留出集准确率不低于 0.85'` |
| 日期 | `YYYY-MM-DD`，要是存在的日期；存成这一天的 UTC 中午 | `--set due=2026-12-01` |
| 数字 | 数字，可以带小数点和负号 | `--set 总预算=120` |
| 开关 | “是”或“否” | `--set <开关字段>=是` |
| 单选 | 选项名 | `--set 结论=成立` |
| 多选 | 选项名，一次写一个 | `--set <多选字段>=<选项名>` |
| 人员 | 只能写“研究员”：所有 agent 用的是研究员一个账号，也只有研究员拍板 | `--set 决定人=研究员` |
| 清空 | 值留空 | `--set blocked_reason=` |
| 读文件 | `@文件`，先按当前目录、再按项目目录找 | `--set 成功标准=@packages/drafts/product/success.md` |
| 产出文档 | 链接字段写 `@文件`：不读内容，也不上传。脚本照文件和内容找这一步的负责会话用 `docs.py attach` 传好的那份文档，字段填它的链接；没传、或者传了以后文件改过，停下并打印该跑的 `attach` 命令。`confirm` 和 `update` 可以，`register` 不行 | `--set 规格=@spec/spec.md` |

`@文件` 找不到时，只要它像文件名（一个词，或者带 `/`、扩展名、`<占位符>`）就停下；中间有空格的文字照原样写，比如 `@研究员 还没批预算`。要写以 @ 开头的文字，用 `@@`。文件要是 UTF-8 文本。

## 读命令

### get：读一条工作项

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py get <工作项 ID> [--raw]
```

```text
#2105  同序列需求  待开工  需求包（Alg-p1-01）：在留出集上重评第 2 轮结果
  序列（sequence）：算法
  发出方（sender）：Alg-p1-01
  主文档（main_doc）：https://<租户域名>/wiki/<节点>
  来源工作项（source_item）：2102
  所属研究任务（task_ref）：2101
  负责会话（owner_session）：Alg-p0-2105
  关系（relation）：执行
```

- 第一行是工作项 ID、类型、状态、名称；类型有不止一个流程时，类型后面带流程名，比如“研究任务·正式实验”。
- 下面每行一个有值的字段，没填的不显示。约定里的字段后面带着括号里的槽位标识。
- 人员字段另用一条 MQL 读出名字。读不出来时打印“提醒：人员字段读不出来，按空的处理”。
- `--raw` 打印 meegle 的原始输出，人员字段在里面是空的。

### next：这一步谁负责、还缺什么

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py next <工作项 ID>
```

输出的样子和读法见 `SKILL.md` 的“推进之前先问空间”。几种特别的情况：

| 输出 | 意思 |
| --- | --- |
| “没有必填项” | 这一步的完成表单没有必填字段，带上 `--by` 就能确认 |
| “下一步：没有了，这是最后一步”，推进命令是 `archive` | 走到归档这一步了 |
| “流程已经走完。” | 已归档 |
| “没有进行中的节点：工作项可能已终止。” | 用 `get` 看状态 |
| “阻塞中（<日期> 起）：<原因>” | 工作项记着阻塞原因 |

### settled：以前定过什么、得出过什么结论

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py settled [--task <研究任务 ID>] [--sequence <序列>] [--keyword <词>] [--all]
python3.12 -I .claude/solo-lab/bin/ledger.py settled <同样的范围> --cards <ID,ID> [--into <草稿路径>]
```

列的是两类工作项：研究员定了的决策（待执行和已执行的，待决定的不算），和有结论的研究任务（正式实验填了“结论”的，探索填了“去向”的）。已终止的不列。

| 用法 | 输出 |
| --- | --- |
| 不带 `--cards` | 清单：每条一行，新的在前。决策一行是 ID、阶段（待执行或已执行）、决定日期、名称、“决定内容”的第一行；被取代的在最前面标“（已被 #ID 取代）”。研究任务一行是 ID、状态、名称、结论或去向。最后一行是条数 |
| `--cards <ID,ID>` | 一行范围说明、整份清单，再给点到的每条出一张卡片，一次最多 5 张，只出清单里有的 |
| `--cards … --into <草稿>` | 把上面这些写进草稿的“已有的决定和结论”一节，原来的内容换掉，草稿别的地方不动。草稿要在 `packages/drafts/` 下面，并且已经有这一节的标题。范围里一条都没有时写“无” |

| 参数 | 含义 |
| --- | --- |
| `--task` | 只看这条研究任务下的：它自己，和“所属研究任务”是它的决策 |
| `--sequence` | 只看这个序列的，写标识或中文名 |
| `--keyword` | 只看名称或内容里有这个词的，不分大小写 |
| `--all` | 不带范围时超过 60 条也全部列出 |

- 决策的卡片：标题行带阶段、决定日期和决定人；“要定的事”和“背景”是它的决策包“认知层”“背景”两节的原文，超过 600 字的截断并注明；“决定”是工作项上“决定内容”的原文；“选项”写定的是哪个、没选的有哪些（登记时记下了选项表才有）；“后来”写有没有被取代、有没有回滚过；最后是主文档链接。主文档读不到时，卡片里写明读不到，不省略。
- 研究任务的卡片：标题行带流程和结论（或去向）；下面是工作项上有值的几个字段（探索问题、成功标准、评测集版本、规格版本、总预算、已用预算、波动估计、候选假设）；结论文档有“结论”一节的，摘这一节的原文；第 9 步签过字的，摘那条决策的“决定内容”；最后是主文档、结论文档或探索记录的链接。
- 决定日期和选项来自本项目的登记回执 `packages/sent/<ID>.json`。别处登记、这里没有回执的决策，清单里没有日期，卡片里没有“选项”一行。
- 清单只用来看有哪些。要引用一条决定，出它的卡片；卡片不够的，读它末尾链接的原文。脚本不判断以前的决定对眼下的事有什么影响。
- 不带范围、结果超过 60 条时停下，提示加范围或 `--all`。

### query 和 mql：按条件查

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py query <查询名> [--sequence <序列标识>] [--json]
python3.12 -I .claude/solo-lab/bin/ledger.py mql <查询名> [--sequence <序列标识>]
```

| 查询名 | 查什么 | 条件 |
| --- | --- | --- |
| `queue` | 决策队列：等研究员的决策 | 决策，状态是“待决定”；状态是“待执行”（用 2.1.0 及以前的模板建的空间里叫“已决定”）、执行方是研究员的也列，到归档为止。执行方看回执里的 `executor`；没有这一项的旧回执，`researcher_action` 有值的算研究员 |
| `blocked` | 卡住的工作 | 研究任务、同序列需求、跨序列需求里阻塞原因非空的，已归档的不算 |
| `verifying` | 待验收 | 同序列需求，状态是“待验收” |
| `open` | 进行中的同序列需求 | 同序列需求，状态不是“已验收”“归档” |
| `cross` | 进行中的跨序列需求 | 跨序列需求，状态不是“已验收”“归档” |
| `tasks` | 没归档的研究任务 | 研究任务，状态不是“归档” |
| `recent` | 近 7 天更新过的同序列需求 | 同序列需求，近 7 天有更新，已归档的也算 |
| `source:<ID>` | 由某个工作项引出的工作项 | 研究任务、两类需求和决策里，“来源工作项”是这个 ID 的 |

- 每个查询都排除“已终止”。
- `--sequence` 按“序列”字段筛，写标识或中文名：product、alg、rnd、infra、quality、pmo、liaison，或者“算法”这样的中文名。跨序列需求的“序列”记的是承接序列。`source:<ID>` 不能带 `--sequence`。
- 输出每行是 `#<ID>  <状态>  <名称>`，最后一行“共 N 项。”。`--json` 打印成 JSON，每项有 `work_item_id`、`name`、`work_item_status`。
- `queue` 的状态一栏写决策走到哪一步：“待决定”；“待决定（已到期，继续等研究员）”，排在最前，是登记满了到期时长又不走到期默认的（不可逆的、执行方是研究员或者要他亲手做事的、定过一次又回滚到待决定的）；或者“待执行”（执行方是研究员，还没归档）。确认“决定”时用 `--executor` 把执行方改成会话的，不再列。每行另带版本（“版本：第 N 版”）、紧急程度、回复期限、执行方、研究员要做的事和主文档链接，版本和后四样取自登记回执，修订以后是新的版本号；`--json` 里是 `stage`、`urgency`、`due`、`executor`、`researcher_action`、`doc`，另有 `version`。`blocked` 每行另带阻塞原因和主文档链接。
- 每页 50 项，自动翻页，最多翻 20 页。没翻完时打印“提醒：…只读出 N 项（每页 50 项，没翻完）…”，这时结果不全，剩下的到网页上看。
- `mql` 只打印 MQL，不查。`blocked` 和 `source:<ID>` 每个类型打印一条。

### trace：沿来源工作项往回查

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py trace <工作项 ID>
```

每行一个工作项：`#<ID>  <类型>  <状态>  <名称>`。从给的这一条开始，顺着“来源工作项”往回，查到没有来源工作项的那一条为止，最多 20 条。

### status：读状态包

```bash
python3.12 -I .claude/solo-lab/bin/ledger.py status <工作项 ID>
```

打印主文档里“状态包”一节。研究任务的状态包由路由维护；各会话压缩上下文以后先读它，路由还拿它、工作项的名称和字段去匹配没带工作项 ID 的信息。反馈的主文档没有这一节；没建工作项的任务读的是它的需求包。

## 写文档的命令（docs.py）

文档谁负责谁写。每条命令先核对运行它的会话：是这份文档的负责会话才写；不是的停下，报“（<会话名>）不能…”，写明该谁来跑。在研究员自己的会话里、或者离线运行时不核对。下面的例子都没带 `--apply`，是预览；核对后在末尾加 `--apply` 执行。

| 文档 | 负责会话 |
| --- | --- |
| 需求包、决策包 | 包头的发出方 |
| 研究任务单、反馈 | 发出方是会话的是它；发出方写“研究员”“导师”的，是这条任务所属序列的 +1，认不出序列的是入口 |
| 交付包 | 包头的发出方，也就是承接的会话 |
| 一步的产出文档 | 这一步的负责方，`ledger.py next` 里写着 |
| 状态包 | 路由、入口，或者这条工作项的负责会话 |
| 交接记录 | 谁的会话标签谁写 |
| 首条研究任务单 `packages/drafts/pmo/研究任务单-首条.md` | 书记员（开池时登记），之后的修订由入口做 |

### upload：上传自己写的文档

```bash
python3.12 -I .claude/solo-lab/bin/docs.py upload <草稿路径> [--source <上级工作项 ID>] [--doc <文档链接>|new]
```

草稿是什么，脚本就照什么传：

| 草稿 | 传到哪 | 之后 |
| --- | --- | --- |
| 需求包（下发、跨序列）、决策包、研究任务单、反馈 | 它的类型在知识库里的节点下，标题先不带工作项 ID，“关联工作项”一行还是占位 | 给书记员发【登记请求】（跨序列的需求包交路由，入口自己写的也交路由）；登记回执到了以后 `relink` |
| 需求包，关系是执行 | 上级工作项的主文档下面 | 不登记。脚本取编号“上级工作项 ID-序号”，见下面“没建工作项的任务” |
| 交付包 | 它答复的那条需求的主文档下面，标题是 `交付包（<作者会话名>）：<任务名>` | 请书记员 `workitem.py reply <草稿>` 填“交付包”字段，再确认“执行”这一步；答复的是没建工作项的任务时不找书记员 |

- 草稿先过和登记一样的检查：包检查、“关联工作项”是占位、发出方带会话名认得出序列、要放的节点在 `feishu/ids.json` 里。除了反馈和交付包，文末补“状态包”和“交接记录”两节，状态包的简介取自包的“认知层”，研究任务单取“目标”。
- 回执是 `packages/sent/upload-<草稿文件名>.json`：`status`（`created` 是文档还没建完，`uploaded` 是传好了）、`doc`（`/wiki/` 链接）、`sha256`（传上去的内容的摘要）、`title`、`by`。交付包的回执是 `packages/sent/reply-<需求 ID>-<草稿文件名>.json`，另记交的是第几版。
- 同一份草稿再跑一次不会再建文档：打印“这份草稿已经上传过，没有再传”。传了以后草稿又改过、还没登记的，文档整篇换成现在的内容，标题跟着改，链接不变。已经登记的草稿不能再 `upload`：改了内容用 `revise`。
- 建文档超时、或者返回里没有链接时，下一次运行会停下：到网页上核对。建好了的加 `--doc <文档链接>` 接着用，确认没建成的加 `--doc new`。
- 交付包验收不通过退回以后重新交：改好，包头“版本”写上一次交的那一版加 1，再 `upload`。脚本新建一份文档，上一版留在原处（回执的 `earlier` 记着）；版本没加 1 的停下，报错写明该写第几版；工作项已经关闭的不收。

**没建工作项的任务。** 派给 +0 的封闭任务（执行关系）不进飞书项目：

```bash
python3.12 -I .claude/solo-lab/bin/docs.py upload packages/drafts/alg/20261103-需求包-重评第2轮.md --source 2101
```

- `--source` 写它所属的工作项 ID：+0 派的写它手上那条下发需求，+1 派的写这件活所属的研究任务、跨序列需求或下发需求；包头“关联工作项”一行后面写了“；来源工作项 #<ID>”的不用传。
- 脚本取编号 `<上级工作项 ID>-<序号>`（如 `2101-3`，序号从 1 起，看 `packages/sent/` 里已有的回执），文档标题是 `<编号>｜需求包（<作者会话名>）：<任务名>`，“关联工作项”一行写成“#<编号>（不建工作项，上级工作项 #<ID>）”，草稿里的这一行也写回。
- 本地回执 `packages/sent/<编号>.json` 记 `local: true`、`type`、`relation`、`source`、`title`、`by`（派活的会话）、`receiver`、`state`（执行中、待验收、已验收）、`doc`，交付以后记 `deliveries`，验收以后记 `acceptances`。
- 输出的最后写着接下来给 +0 发什么：【委托 #<编号>】，消息里单独写一行“会话名：<简写>-p0-<编号>”。
- +0 的交付包“关联工作项”写 `#<编号>`，`upload` 把它挂在这份需求包下面，任务的状态改成“待验收”，不找书记员。
- `ledger.py get`、`next`、`status`、`trace` 都认这种编号；`workitem.py` 的命令不认，写了会停下，报这件事该用哪条 `docs.py` 命令。

### accept：验收没建工作项的任务

```bash
python3.12 -I .claude/solo-lab/bin/docs.py accept <编号> --result 通过|不通过 [--note '<一句话>']
```

- 只管没建工作项的任务，由派活的会话跑。给的是工作项 ID 时停下：工作项的验收由发出方请书记员确认“验收”这一步。
- 要先有交付包。`--result 不通过` 必须带 `--note`，写哪一条没有证据、要补什么。
- 脚本在需求包末尾追加一行“[<会话标签>] 验收（日期）：<结论>”。通过的，本地回执的状态改成“已验收”，这件活了结；不通过的回到“执行中”，承接的会话改好后版本号加 1 重新 `upload`。
- 已经验收的再跑一次什么都不写。

### relink：把工作项 ID 写回文档

```bash
python3.12 -I .claude/solo-lab/bin/docs.py relink <工作项 ID>
```

书记员登记以后，作者跑这一条：脚本找到主文档开头“关联工作项”那一行，原位换成工作项 ID，标题前面加上“工作项 <ID>｜”，文档的标题和它在知识库里的节点标题是同一个，一起变；文档身份和链接不变。那一行已经写着这个 ID 的，不改。没建工作项的任务不用它：编号在上传时已经写进去了。

### revise：修订已经登记的包

```bash
python3.12 -I .claude/solo-lab/bin/docs.py revise <工作项 ID> <新草稿路径> --note '<改了什么>'
```

- 由作者自己跑。新草稿是需求包或决策包的下一版：主文档开头到“状态包”之前那部分改好的样子，包头“版本”写上一版加 1，“关联工作项”写这条工作项的 ID 或“待建”。`--note` 必填，进交接记录。
- 研究任务单也用它。研究任务单不写“版本”，脚本照回执里的版本加 1，日期用当天。工作项要是研究任务、还没关闭，修订稿“流程”一行和它走的流程相同。研究任务过了第一步也能修订，这时输出里打印“提醒：#<ID> 已经过了第一步“…”，现在在“…”：后面各步已经定下的文档不会跟着研究任务单变。”，照样修订。
- 没建工作项的任务也能修订：`<工作项 ID>` 写它的编号，修订稿也要是执行关系的需求包；已经验收的不再修订。
- 修订稿的标题变了的（“# <包名>：<事项>”或“# 研究任务单：<任务名>”），主文档的标题块换掉：文档的标题和它在知识库里的节点标题是同一个，一起变。成功时打印“改名：主文档和它的知识库节点的标题从“…”改成“…”。”；标题没改成的，修订照样完成，打印“提醒：主文档的标题没有改成，还是“…”；请在网页上把它改成“…”。”。
- 修订不看文档上的批注：正文换掉以后，挂在旧段落上的批注不再显示在原来的位置，`lark-cli drive +list-comments --solved-status all` 仍然读得到。
- 草稿回写只改“关联工作项”一行；草稿在修订期间改过的，打印“提醒：草稿在命令运行期间改过…”。
- 交付包不用它：改好后包头“版本”加 1，用 `upload` 重新交。反馈的主文档没有状态包，也不用它。
- 脚本先核对，有一样不过就什么都不写：草稿过包检查；包类型、关系都和工作项登记的一致（下发改成跨序列这类改关系的，另写一份登记）；版本号是回执记的上一版加 1（1.0.4 以前登记、回执没记版本的，算第 1 版）；决策还在“待决定”；需求包的工作项还没关闭；“关联工作项”写的是别的 ID 时停下。
- 修订稿照主文档开头改，可以没有“# <包名>：<事项>”这行标题：没有的，事项沿用回执里的。修订稿里“关联工作项”写成“#ID”的，换进主文档时仍带工作项链接。
- 写的顺序是：用 `docs +update --command block_replace` 把主文档从第一块到“状态包”标题前一块整段换成新草稿（标题不换）；用 `--command append` 在交接记录末尾追加“[<作者的会话标签>] 第 N 版（日期）：<改了什么>”；最后是回执和本地决策状态。文档身份和链接不变，旧版本留在飞书文档的历史版本里。中途失败的，报错写明已经写了什么；修好后重跑同一条命令接着做，交接记录里已经有这一版的一行就不再加。
- 修订不写工作项。这一版改了记在工作项上的内容时，输出的最后打印“这一版改了记在工作项上的内容，工作项只由书记员写”，后面是一条现成的 `workitem.py update <ID> --set … --apply`：作者把它放进【登记请求】，书记员照着运行。会进这条命令的有：工作项的名称（标题变了）、研究任务的“发出方”“序列”、来源工作项、决策的紧急程度，以及空间里有这两个字段时的执行方和研究员要做的事、需求包写了日期的回复期限对应的截止时间。
- 回执的版本和每次修订的 `revisions`（版本、日期、说明、草稿）跟着更新；决策队列来的决策在本地决策状态里的那一条也更新，登记时间不变，到期仍从第一次登记算。1.0.4 以前登记、本地决策状态里没有的决策，修订以后写进去，登记时间取工作项建成的时间。
- 修订稿里的“关联工作项”写回成工作项 ID，它不会被当成新包再登记。修订不推给研究员，`query queue` 显示新的版本号。跨序列需求的修订，输出里提醒把这次修订告诉路由一声。
- 成功时打印“修订：#<ID> 的主文档开头换成第 N 版（文档链接不变），交接记录追加了一行。”（续做、交接记录里已经有这一行的，写“没有再加”）；预览时打印“预览：会把 #<ID> 的主文档开头换成第 N 版，交接记录追加一行。”。

### attach：上传一步的产出文档

```bash
python3.12 -I .claude/solo-lab/bin/docs.py attach <工作项 ID> <字段> <本地文件>
```

- 一步要填链接的产出（规格、需求文档、实验方案、结论文档这类），由这一步的负责会话写在本地，用这条命令传到这条工作项的主文档下面，打印文档链接。字段写名字、槽位标识或 field_key；不是链接字段的停下，值直接交给书记员写。
- 回执是 `packages/sent/attach-<工作项 ID>-<字段>-<文件名>-<内容摘要>.json`，一份文件的一版内容一份回执，记着文档链接。文件没改过再跑一次，沿用上次传的文档；改过的传成一份新文档，链接是新的。
- 传好以后请书记员写进工作项：登记请求里写 `<字段>=@<本地文件>`，书记员照样写进 `--set`，脚本照文件和内容找到这份文档；或者直接写 `<字段>=<文档链接>`。文件在上传以后改过的，书记员那边会停下，请负责会话重新 `attach`。
- 建文档没有拿到确定的结果时停下：到网页上看这条工作项的主文档下有没有这份文档，有就把链接直接交给书记员，没有就删掉报错里写的那份回执重跑。

### status-block：替换状态包

```bash
python3.12 -I .claude/solo-lab/bin/docs.py status-block <工作项 ID> --file <状态包文件>
```

把主文档里从“状态包”标题到“交接记录”标题之前的内容，整段换成文件的内容。文件不是以 `## 状态包` 开头的，脚本补上这个标题。研究任务的状态包由路由维护；别的工作项由它的负责会话写。没建工作项的任务没有自己的状态包，进展记在它的需求包的交接记录里。

### append：追加交接记录

```bash
python3.12 -I .claude/solo-lab/bin/docs.py append <工作项 ID> --file <交接记录文件>
```

文件第一行要带自己的会话标签，比如 `[Alg+0]`：每个会话只记自己的交接，写别人的标签会停下。内容追加到主文档末尾，“交接记录”是主文档的最后一节。没建工作项的任务写它的编号，追加到需求包末尾。

### brief：简版决策

```bash
python3.12 -I .claude/solo-lab/bin/docs.py brief <草稿> [--doc <文档链接>|new]
python3.12 -I .claude/solo-lab/bin/docs.py brief <链接或草稿> --words '<研究员的原话>' [--promote 是|否]
python3.12 -I .claude/solo-lab/bin/docs.py brief <链接或草稿> --package
python3.12 -I .claude/solo-lab/bin/ledger.py query briefs
```

- 要研究员挑或点头、又不用写决策包的事，由提出的 +1 写一份简版决策，一事一份。第一条命令照模板（`.claude/solo-lab/templates/brief.md`）检查草稿：标题、七个栏目、至少两个选项、建议升不升级，对不上的全部列出来，不传。通过的传到知识库的“简版决策”节点下，打印链接。+0 不能跑：它要研究员定的事写进交付包。
- 简版决策不是任务包：不建工作项，不进决策队列，到期不按默认办。文档标题是 `<上传日期>｜简版决策（<会话名>）：<标题>`。回执是 `packages/sent/brief-<文件名>.json`。草稿没改过再跑一次，不再传；改过的把文档换成新内容，链接不变，只有当初上传它的会话能改。
- 第二条命令把研究员的回答写回文档：文末加“研究员的决定”一节，原话照抄，写日期、谁记的、升不升级，标题前加“已定｜”。入口跑，或者它的作者跑。`--promote` 只在研究员说了升不升级时写，不写就照作者的建议。定了以后这份文档不再改，再上传会停下。
- 第三条命令给升级用：照定了的简版决策和研究员的原话生成一份决策包草稿，放在草稿旁边，渠道是“研究员主动发起”，过了包检查才写文件。作者照它打印的三步办：`docs.py upload`，请书记员登记并确认“决定”，`docs.py relink`。原来记的是不升级、后来要升级的，也跑这一条。
- 第四条命令列出全部简版决策，一份一行：待定的写作者的建议，已定的写研究员回答的第一行和升没升级。`ledger.py query queue` 在决策队列后面列出待定的。清单读本地回执，飞书项目里没有它们。
- 建文档没有拿到确定的结果时停下：到网页上看“简版决策”节点下有没有这份文档，有就加 `--doc <文档链接>` 接着用，确认没有加 `--doc new`。没有这个节点也会停下：请书记员运行 `docs.py ensure-node brief --apply`。

### ensure-node：建知识库节点

```bash
python3.12 -I .claude/solo-lab/bin/docs.py ensure-node <键>
python3.12 -I .claude/solo-lab/bin/docs.py ensure-node all
```

- 只有书记员跑。键是节点树里的位置，比如 `feedback`、`same_seq/alg`、`archive/alg`，全部的键见 `structure.md` 的节点树。
- `feishu/ids.json` 里已经记着的直接返回。没记的，先在知识空间里上一级节点下找同名节点，有就直接用，没有才建；结果写进 `feishu/ids.json`。
- 序列的节点要等上一级建好。`all` 一次建齐整个骨架：先建一级节点，再建已启用序列的节点。

## 写工作项的命令（workitem.py）

只有书记员能运行，别的会话运行会被 hook 拦下。下面的例子都没带 `--apply`，是预览；核对后在末尾加 `--apply` 执行。给的是没建工作项的任务的编号（如 `2101-3`）时，这些命令都停下，报这件事该用哪条 `docs.py` 命令。

### register：登记草稿，新建工作项

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py register <草稿路径> [--task <研究任务 ID>] [--source <来源工作项 ID>] [--set <字段>=<值>] [--resume] [--doc <文档链接>]
```

| 草稿 | 脚本怎么认 | 建成 |
| --- | --- | --- |
| 需求包，关系是下发 | 包头“包类型：需求包” | 同序列需求 |
| 需求包，关系是跨序列 | 同上 | 跨序列需求 |
| 需求包，关系是执行 | 同上 | 不登记，脚本停下：派活的会话自己 `docs.py upload --source <上级工作项 ID>` |
| 决策包 | 包头“包类型：决策包” | 决策 |
| 研究任务单 | 标题 `# 研究任务单：<任务名>`，开头有“流程”“发出方”“关联工作项”三行 | 研究任务，走“流程”一行写的那个流程 |
| 反馈 | 标题 `# 反馈：<名字>`，开头有“发出方”“关联工作项”两行 | 反馈 |

| 参数 | 用途 |
| --- | --- |
| `--source <ID>` | 来源工作项。草稿里写了“来源工作项 #<ID>”的不用传 |
| `--task <ID>` | 所属研究任务。包头写了“所属研究任务：#<ID>”的不用传；空间里只有一条没归档的研究任务时脚本自动填 |
| `--set <字段>=<值>` | 新建时一并写的字段。新建页必填、草稿里又读不出来的字段从这里传 |
| `--resume` | 接着上一次没做完的登记做，不会再建一个工作项 |
| `--doc <文档链接>` | 没有上传回执时用（比如作者是在另一台机器上传的）：给作者传好的那份文档的 `/wiki/` 或 `/docx/` 链接。书记员不建文档，`--doc new` 会停下 |

脚本依次做这几件事：

1. 检查，任何一项不过就什么都不建：
   - 包草稿过一遍包检查，看包头、栏目和旧包名。
   - “关联工作项”一行写的是“待建”这样的占位。
   - 包的发出方带会话名，认得出序列。
   - 同序列需求的关系和发出方的职级一致：+1 发下发。
   - 研究任务单的“流程”一行写的是空间里有的流程。
   - 新建页的必填字段都有值。
   - 作者已经上传：读上传回执 `packages/sent/upload-<草稿文件名>.json`。没上传的停下，打印作者该跑的 `docs.py upload` 命令；上传以后草稿改过的也停下，请作者重新 `upload`（文档链接不变）。把这条命令回给请求方，不替它传。
2. 建工作项。名称照命名规则，各角色的人员都填研究员本人，“主文档”填作者传好的那份文档的链接。回执 `packages/sent/<ID>.json` 这时就写下。
3. 回读角色人员，缺研究员的补上。
4. 加一条登记评论。“负责会话”记包头接收方括号里的会话名。
5. 工作项 ID 写回草稿的“关联工作项”一行，回执标成已登记。脚本这时重新读一遍草稿，只改这一行。草稿和命令开始时不一样的，输出里打印“提醒：草稿在命令运行期间改过…”，回执里记 `draft_changed`；书记员把这句话写进给作者的回执。
6. 打印“回执里告诉发出方 <会话名>：运行 … docs.py relink <工作项 ID> --apply”：书记员把工作项 ID 和这句话写进【登记回执】，作者照着把 ID 写回文档。

登记完，脚本打印接下来该做什么：

| 登记的是 | 之后 |
| --- | --- |
| 同序列需求 | 停在“待开工”。登记请求写了“开工”的，接着 `confirm <ID> --by <承接方的会话名>`；排队还没委托的等请求方说开工再确认 |
| 跨序列需求 | “提出”是发出方自己的一步，必填项新建时已经填好，随登记确认，停在“待接单”。输出里多一行“回执另发一份给路由”，之后在它上面的每次写入也有 |
| 决策，渠道是决策队列 | 停在“待决定”，等研究员定 |
| 决策，渠道是研究员主动发起 | 脚本打印接着要跑的 `confirm <ID> --by 研究员 --set 决定内容=… --set 决定人=研究员`；包的“决定”一节没写全的，退回作者补上 |
| 研究任务、反馈 | 跑 `next <ID>` 看第一步要什么。研究任务上的每次写入，输出里也多一行“回执另发一份给路由” |

几条细则：

- “序列”字段：同序列需求和决策填发出方的序列，跨序列需求填承接方的序列。研究任务和反馈填发出方的序列，发出方写的是“研究员”“导师”这样认不出序列的，填项目管理。
- 工作项名称是 `<包名>（<作者会话名>）：<任务名>`，主文档标题在 `relink` 以后是 `工作项 <工作项 ID>｜<包名>（<作者会话名>）：<任务名>`。研究任务的名称就是任务名，主文档标题是 `工作项 <工作项 ID>｜研究任务单：<任务名>`。
- 需求包的“回复期限”是存在的日期时写进“截止时间”。决策没有截止时间字段，决策包的回复期限不写进工作项。决策包的“紧急程度”写进同名字段。
- 决策包的“执行方”和“研究员要做的事”按名字写进同名字段：执行方写“研究员”或会话名（写成“算法 +1（Alg-p1）”的写 `Alg-p1`，和回执的 `executor` 一样），研究员要做的事照包头原样写。这两个字段不是约定里的槽位：空间里没有（用 2.1.0 及以前的模板建的），或者快照里还没有，就不写，也不提醒，其余照常登记。`--set` 传了同一个字段的，以 `--set` 为准。
- 登记回执另记工作项类型（`type`），决策还记是否进决策队列（`queue`）、是否插队（`urgent`）、回复期限（`due`）、包头的“执行方”（`executor`：“研究员”或会话名，写成“算法 +1（Alg-p1）”的记 `Alg-p1`）和“研究员要做的事”（`researcher_action`，写“无”的记 null）。`query queue` 照它们显示，`confirm` 确认“决定”以后照它打印执行方。
- 回执还记版本（`version`）和登记时间（`registered_at`）；决策另记事项、可逆性、判据、到期默认动作、选项表（每个选项的不可逆的动作，`options[].irreversible`）和冻结的动作。确认“决定”以后再记怎么定的：`option`（没加 `--option` 是 null）、`decided_by`（“研究员”或“到期默认”）、`decided_at`；回滚到待决定时这三项清空，记 `rolled_back_at`。
- 包头“版本”要是第 1 版：已经登记过的包改了内容，作者用 `docs.py revise`，不重新登记。
- 决策队列来的决策，工作项一建好就写进本地决策状态 `.claude/state/gates.json` 的待定决策，冻结的动作从这时生效（所有池会话每轮看到一行冻结提示，hook 不拦），到期时长从这时算。研究员主动发起的决策不进待定决策。
- 研究任务单“资源上限”的执行环境、计算资源写了具体内容、却没写定下它的决策 ID 时，打印“提示：…要进决策队列”，照样登记。
- 登记时不上传产出文档：`--set <链接字段>=@文件` 在 `register` 上会停下。先登记，这一步的负责会话再 `docs.py attach`。
- 续做时，来源工作项、所属研究任务和 `--set` 的值从回执里取，`@文件` 记的是当时读到的内容；再传的 `--set` 以新传的为准。
- 同一个草稿文件只能登记一次。

**研究任务单要改。** 作者用 `docs.py revise`：文档还是那一篇，链接不变。初始化时登记的那条研究任务，访谈以后的修订稿由入口这样换进去。

登记时可能出现的提醒，不算出错：

| 提醒 | 怎么办 |
| --- | --- |
| “回复期限“…”不是存在的日期，截止时间没写；改好后用 update 补” | 向请求方问清日期，用 `update` 补 |
| “跳过字段 …（之后可以用 update 补）：…” | 选填字段的值转换不了，照后面的原因改好，用 `update` 补。决策没有截止时间字段，决策包的回复期限只留在包头里 |
| “读不到 #… 的角色人员，没法确认各节点有没有负责人；请在网页上核对。” | 请研究员在网页上看这条工作项的角色人员 |
| “建工作项时带的角色人员没全生效，已用 --role-operate 把研究员补进：…。” | 已经补好，不用处理 |
| “登记好了，第一步没能确认：…。接着运行 workitem.py confirm … --by … --apply” | 照它给的命令确认 |

### reply：填交付包字段

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py reply <草稿路径> [--doc <文档链接>]
```

- 只收交付包。包头的“关联工作项”写它答复的那条需求的 ID，比如 `#2103`；这条需求要是同序列需求或跨序列需求。答复没建工作项的任务的交付包不用它。
- 承接的会话先 `docs.py upload` 把交付包挂到这条需求的主文档下面。书记员的 `reply` 不传文档：读上传回执，把链接写进这条需求的“交付包”字段，再加一条评论。不新建工作项，也不确认节点。没上传的停下，打印承接方该跑的命令。
- 填完，承接方请书记员确认“执行”这一步：`confirm <需求 ID> --by <承接方的会话名>`。
- 回执是 `packages/sent/reply-<需求 ID>-<草稿文件名>.json`，记着交的是第几版（`version`）。
- 验收不通过退回以后重新交：承接方改好交付包，包头“版本”加 1，重新 `upload`，再请书记员 `reply`：“交付包”字段换成新链接，评论写“收到交付包第 N 版”，上一版的文档留在原处。
- 没有上传回执时（承接方在另一台机器上传的），用 `--doc <文档链接>` 给出文档。

### confirm：确认当前这一步

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py confirm <工作项 ID> --by <会话名> [--set <字段>=<值>] [--option <选项>] [--executor <会话名>] [--node <节点>] [--decision <决策工作项 ID>] [--type <类型槽位>]
python3.12 -I .claude/solo-lab/bin/workitem.py confirm <决策 ID> --by 到期默认
```

| 参数 | 用途 |
| --- | --- |
| `--by <会话名>` | 提出请求的会话，要是这一步的负责方；研究员交代的写 `研究员`。负责方是书记员的步骤不用写。写 `到期默认` 时见下面“到期默认” |
| `--set <字段>=<值>` | 这一步的必填字段，也可以顺带写别的字段。之前已经填好的不用再传 |
| `--option <选项>` | 只用在决策的“决定”这一步，可以不加：研究员选的选项，写选项表第一列的名字，带空格的加引号（`--option '本机 Docker'`）；表里一个都没选写 `无`。记进回执和评论 |
| `--executor <会话名>` | 只用在决策的“决定”这一步，可以不加：把执行方改成这个会话 |
| `--node <节点>` | 有几个节点同时在进行时指明确认哪一个，写节点名或节点 ID |
| `--decision <ID>` | 冻结的字段在签字后改过、研究员认可这些改动时，写认可它的决策工作项 ID |

脚本依次做：

1. 读工作项和它的节点，找到进行中的那个。最后一步不在这里确认，提示改用 `archive`。
2. 核对谁来提。
3. 问空间这个节点还缺哪些必填项，去掉这次 `--set` 传的；还有缺的就停下，列出字段名。
4. 这一步要求签字字段的，核对它引用的决策；这一步要求“结论”的，核对冻结的字段。规则见 `SKILL.md` 的“确认之前脚本自己核对什么”。
5. 写 `--set` 的值，确认节点，回读。成功时打印“确认：#<ID> “<节点>”完成，现在到“<下一个节点>”，状态“<状态>”。”。决策确认了“决定”这一步、到了“待执行”的，最后再打印一行“执行方：<研究员或会话名>。”：这次加了 `--executor` 的是改成的那个会话；否则回执里记着 `executor` 的照它；升级前登记、没有这一项的，`researcher_action` 有值的是研究员，其余是工作项上的发出方。

**决策的选项和执行方。** 确认决策的“决定”这一步，决策移出本地决策状态里的待定决策，冻结解除。这一步可以另带两样，都不是必须的：

- `--option <选项>` 记下研究员选的选项。脚本拿它对决策登记（或修订）时记下的选项表，名字对不上的停下，列出有哪些选项；表里一个都没选写 `--option 无`。对上了就记进回执的 `option`，确认以后加一条评论“研究员选的选项：<选项>（不可逆的动作：<类别；类别>）”，没列类别的没有括号。评论没写上不影响确认，输出里给出补评论的命令。它只是记录：hook 不看它，不可逆事项清单里的命令 hook 都不拦。
- 1.0.4 以前登记、没记选项表的决策，`--option` 写了选项名会停下（写 `无` 或者不写可以）：研究员定的内容写进 `--set 决定内容`。
- `--executor <会话名>` 把执行方改成一个会话，包头“执行方”写的是研究员、研究员选的选项却不用他动手时用。会话名过和包头一样的检查：只收各序列的 +1、入口和路由。生效时回执的 `executor` 改成会话名、`researcher_action` 记 null，`as_packaged` 留下包头原来的两项；空间里有“执行方”“研究员要做的事”两个字段的，随这一步的字段写入写成会话名和“无”，没有就跳过；评论里多一句“执行方改成 <会话名>（包头写的是研究员），“研究员要做的事”记“无””。之后照执行方是会话的规矩走：书记员通知它，它执行完马上请书记员归档，`query queue` 不再把这条列成等研究员执行。写的会话就是包头的执行方时，什么都不记。
- `--executor` 不收“研究员”：要把执行方改成研究员，请发出方写下一版（包头“执行方”写“研究员”，“研究员要做的事”写清楚要他做什么），它自己 `docs.py revise`，书记员照它转来的 `update` 命令改好字段以后再确认。执行方和研究员要做的事也不能同时用 `--set` 传。
- 研究员在网页上确认了“决定”以后，这两个参数都用不上了：选的选项用 `workitem.py comment` 记一条评论；要改执行方，先 `rollback <ID> --to 决定 --reason '<原因>' --by 研究员`，再带 `--executor` 确认。

**到期默认。** `confirm <决策 ID> --by 到期默认`：可逆的决策登记满到期时长还没定，按包头的到期默认动作记成决定。脚本要下面几条都满足才写，有一条不满足就停下，什么都不写：

| 条件 | 不满足时 |
| --- | --- |
| 还在“待决定” | “现在是“…”，不在“待决定””：已经定了 |
| 在本地决策状态里 | 不是决策队列来的，或者是 1.0.4 以前登记的：请发出方写下一版，它自己 `docs.py revise` 以后再看 |
| 执行方是会话，“研究员要做的事”是“无” | 执行方是研究员（或者要研究员亲手做事），到期继续等研究员 |
| 可逆 | 不可逆的决策到期只能等研究员 |
| 没有回滚过 | 研究员定过一次、又回滚到待决定的决策不再走到期默认，一直等研究员 |
| 登记满到期时长 | 打印登记了多久、到期时长和几点以后才能确认 |
| 到期默认动作指向选项表里的一个选项 | 到期继续等研究员 |

- 到期时长取 `org/decisions.md` 里最后一处“可逆决策的到期时长：登记后 N 小时（或 N 天）”；研究员写在“补充决定”里的盖过插件那一节。脚本和 hook 的到期提示每次都现读这一行，改了马上生效，到期一律从登记时间算。读不到按 24 小时。一行里写了不止一个时长的，取“改成、改为、延长到、缩短到”后面的那个；没有这类词、或者时长不是数字的（“改成两天”），不猜，提醒一句再按 24 小时算：写成“登记后 36 小时”或“改成登记后 36 小时”。
- 写的是：决定内容“到期默认：<选项>：<做法>（登记后 <时长>内研究员没有决定）”，决定人研究员（这个字段只能填人，靠决定内容的开头区分），再加一条同样内容的评论。打印“到期默认：照选项“<选项>”办，执行完请书记员归档。”，最后一行照常是执行方。
- 不能和 `--set`、`--option`、`--executor`、`--decision` 一起用；离线做不了，它要先读决策现在的状态。

`--by` 认的是工作项上记的名字：

- 负责方是 `发出方（<会话名>）`、`承接方（<会话名>）` 时，`--by` 要和括号里的名字一样，大小写不论；这个会话所在序列的 +1 也可以提。
- 升级到 1.1.0 以前登记的执行关系需求（之后不再登记这类工作项），“负责会话”记的是 +0 的池位名（`Alg-p0-01`）或工作名 `<简写>-p0-<工作项 ID>`，比如 `Alg-p0-2105`。+0 的这两个名字 `--by` 写哪一个都行；别的序列的 +0 不认。
- “负责会话”还是“待委托”时，`next` 显示“承接方（工作项上还没记是谁）”，这时带上 `--by` 就放行。定下委托给谁以后用 `update <ID> --set owner_session=<会话名>` 记上，核对才起作用。

必填字段可以提前用 `update` 填好，轮到那一步再确认；还没走到的节点确认不了。

### rollback：退回到已完成的一步

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py rollback <工作项 ID> --to <节点> --reason '<原因>' --by <会话名> [--type <类型槽位>]
python3.12 -I .claude/solo-lab/bin/workitem.py rollback <工作项 ID> --to <节点> --reason '<原因>' --decision <决策工作项 ID>
```

| 参数 | 用途 |
| --- | --- |
| `--to <节点>` | 退回到哪个已完成的节点，写节点名或节点 ID |
| `--reason '<原因>'` | 必填，写进操作记录；带了 `--decision` 的，原因后面自动加“（研究员决定 #<ID>）” |
| `--by <会话名>` | 提出回滚的会话；研究员交代的写 `研究员` |
| `--decision <ID>` | 研究员批准回退的决策工作项 ID，研究任务的回滚必填 |

谁可以提：

| 情况 | 核对什么 |
| --- | --- |
| 研究任务 | 只认 `--decision`，照签字的五项核对这条决策：它要在任务走到现在这一步之后决定，用过一次就作废 |
| 需求、决策、反馈，带了 `--decision` | 脚本停下：这几类的退回不走决策 |
| 需求、决策、反馈，流程还在走 | `--by` 要是工作项当前这一步的负责方 |
| 需求、决策、反馈，只剩归档没做 | `--by` 要是退回到的那一步的负责方 |
| 需求、决策、反馈，已经归档 | 只认 `--by 研究员` |

回滚以后：

- 退回到的节点变成进行中，它后面的节点回到未开始。
- 从退回到的那一步到原来所在的那一步，各步的必填字段都清空，旧值逐条打印在输出里，也留在操作记录里。新建页必填的字段不清；人员字段的值读不回来，也清不到。
- 这几步要重做才能再确认。执行后用 `get <ID>` 看一眼：打印过“清空”的字段不该再出现在输出里；还在的，写进异常清单报给路由。
- 重做以后，这些字段只留新一轮的值，比如“运行 ID”“实验轮次”。上一轮的值不回填，要用就从回滚的输出或操作记录里抄。
- 决策回到“待决定”：回执里怎么定的那几项清空，记下回滚的时间（`rolled_back_at`）；决策队列来的重新进本地决策状态，冻结的动作重新生效。它定过一次，从此不走到期默认，一直等研究员：`confirm --by 到期默认` 会被拒绝，登记满到期时长以后 `query queue` 把它标成“待决定（已到期，继续等研究员）”、排在最前，入口每轮的到期提示写“继续等”，路由不会再被提示去确认它。确认时用 `--executor` 改过执行方的，回执和空间里的两个字段改回包头写的。

常见的三种回滚：

| 场景 | 命令 |
| --- | --- |
| 验收不通过，发出方退回 | `rollback <需求 ID> --to 执行 --reason '<哪条验收标准没过>' --by <发出方的会话名>` |
| 跨序列需求，承接方不接 | `rollback <需求 ID> --to 提出 --reason '<为什么不接>' --by <承接序列 +1 的会话名>`，状态回到“已退回” |
| 研究任务，研究员决定回退 | `rollback <研究任务 ID> --to <节点> --reason '<原因>' --decision <决策工作项 ID>` |

### archive：归档

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py archive <工作项 ID> [--moved]
```

1. 核对工作项已经走到最后一步；已经是“归档”的直接返回。决策是“已终止”的不用归档，移出本地决策状态里的待定决策就返回。
2. 按工作项的“序列”字段找到归档节点 `archive/<序列标识>`，把主文档整棵子树移过去。移动的是原节点，文档身份和链接都不变。
3. 确认最后一步，回读状态是“归档”。
4. 工作项在会话池的认领表（`.claude/state/pool.json` 的 `owners`）里有负责会话的，把这一条移出，`pool.py show` 不再把它列在那个会话名下。

文档移好了、节点没确认成的，修好原因后跑 `archive <ID> --moved`：不再移动文档，只确认最后一步。

决策归档或终止以后不再冻结任何动作。回滚到“待决定”的决策（`rollback <ID> --to 决定`）重新写进待定决策，重新冻结，并且不再走到期默认。

### update：改字段

```bash
python3.12 -I .claude/solo-lab/bin/workitem.py update <工作项 ID> --set <字段>=<值> [--type <类型槽位>]
```

## MQL

```sql
SELECT `work_item_id`, `name`, `work_item_status` FROM `<project_key>`.`<type_key>` WHERE `work_item_status` = '待决定'
```

- 表名用 type_key，或者类型现在的名字；系统标识不行。`ledger.py` 用绑定时记进 `feishu/ids.json` 的 type_key。
- 自定义字段用 field_key 当列名，`ledger.py mql <查询名>` 打印出来的就是这种写法。
- 视图默认不显示已终止的工作项，MQL 不会自动排除，查询要显式排除。
- 时间条件：``RELATIVE_DATETIME_BETWEEN(`updated_at`, 'past', '7d')`` 是近 7 天。
- “来源工作项”“所属研究任务”是单行文本，存工作项 ID 的数字，查“由谁引出”用 `= '<ID>'`。阻塞按字段查：阻塞原因 `IS NOT NULL`。
- 单次最多 50 条。首查的返回里有 `session_id`，下一页带 `--session-id <session_id>` 和 `--group-pagination-list '[{"group_id":"1","page_num":2}]'` 取；`ledger.py query` 自动翻页。
- 结果在 `data.<分组>[].moql_field_list` 里，工作项 ID 是 `{key: work_item_id, value: {long_value}}`；空结果是 `data: {}`。
- 手写 MQL 时用带引号的 heredoc 传入，免得 shell 解释反引号。

## 脚本底下跑的命令

预览打印的就是这些命令。每条 meegle 命令后面都带 `--project-key <project_key> --format json`，每条 lark-cli 命令后面都带 `--as user`。

| 用途 | 命令 | 说明 |
| --- | --- | --- |
| 建工作项 | `meegle workitem create --work-item-type <类型的系统标识> --fields '<JSON>'` | `field_value` 一律是字符串；带流程（`template`）和各角色的人员（`role_owners`） |
| 改字段 | `meegle workitem update --work-item-id <ID> --fields '<JSON>'` | 空字符串是清空；补角色人员用 `--role-operate` |
| 读工作项 | `meegle workitem get --work-item-id <ID> --fields '["_all"]'` | 没填值的字段不出现；人员字段读不回来 |
| 读节点 | `meegle workflow get-node --work-item-id <ID> --page-num <页>` | 每页 20 个节点 |
| 问节点还缺什么 | `meegle workflow list-state-required --work-item-id <ID> --state-key <节点 ID> --mode unfinished` | 只列没填的必填项 |
| 确认、回滚节点 | `meegle workflow` 的节点操作，带 `--node-id <节点 ID> --action confirm`，回滚是 `--action rollback --rollback-reason <原因>` | 项目权限不放行直接运行，只能经 `workitem.py` |
| 读操作记录 | `meegle workitem list-op-records --work-item-id <ID> --op-record-module field_mod` | 每页 20 条 |
| 查 | `meegle workitem query --mql '<MQL>'` | 见上一节 |
| 评论 | `meegle comment add --work-item-id <ID> --content '<文本>'` | |
| 建文档（`docs.py upload`、`attach`） | `lark-cli docs +create --parent-token <节点> --title '<标题>' --doc-format markdown --content -` | 正文走标准输入。返回的是 docx 链接，再用 `lark-cli wiki +node-get --node-token <document_id>` 换成 `/wiki/` 链接 |
| 上传以后草稿改过 | `lark-cli docs +update --doc <链接> --command overwrite --doc-format markdown --content -` | 整篇换成现在的内容，链接不变 |
| 追加交接记录、记验收结论 | `lark-cli docs +update --doc <链接> --command append --doc-format markdown --content -` | |
| 替换状态包、写回工作项 ID、修订 | `lark-cli docs +fetch --doc <链接> --scope outline --detail with-ids` 找到块，再 `lark-cli docs +update --doc <链接> --command block_replace --start-block-id <块> --end-block-id <块> --doc-format markdown --content -` | |
| 移动子树 | `lark-cli wiki +move --node-token <节点> --target-parent-token <新父节点>` | 节点和原链接都不变 |
| 建节点 | 先 `lark-cli wiki +node-list --space-id <ID> --page-all` 查同名节点，没有才 `lark-cli wiki +node-create --space-id <ID> --obj-type docx --node-type origin --title <标题>` | 序列的节点另带 `--parent-node-token <上一级节点>` |

lark-cli 只读当前目录、`/tmp`、`~/files` 下的 `@文件`，所以台账脚本不落临时文件，正文都从标准输入传。每条命令最多等 120 秒。
