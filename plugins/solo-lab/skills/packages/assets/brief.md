# 简版决策模板（各序列 +1 → 研究员）

要研究员定或确认一件事，都给他一个读得到背景的飞书链接，对话里每件事只写一行。先分清写哪一种：

| 什么事 | 写什么 | 进飞书项目吗 |
| --- | --- | --- |
| 用来签字的；不可逆的；改范围、成功标准、冻结项或组织规则的；定下以后要研究员亲手做的 | 决策包（`decision.md`） | 进，进决策队列 |
| 其余要他挑或点头的事 | 简版决策，一事一份 | 默认不进；他定了以后升级的才进 |
| 只要他动一下手、没有选项要挑的 | 研究员任务清单（`todo.py add`） | 不进 |

简版决策不是任务包：不建工作项，不进决策队列，到期不按默认办。它放在知识库的“简版决策”节点下，研究员的回答由脚本写回同一份文档。飞书项目里只留以后还要查的决定，所以每一份都要写明建议升不升级。

| 步骤 | 谁 | 做什么 |
| --- | --- | --- |
| 写和传 | 提出的 +1 | 照下面的模板写到 `packages/drafts/<序列>/`，一件事一份。运行 `docs.py brief <草稿> --apply`，脚本照模板检查，栏目不齐不传。再给路由发【通知】：要研究员确认 <一句话> <链接>，写上建议升不升级 |
| 转 | 路由、入口 | 路由把那一句话和链接原样转给入口，没带链接的退回作者。入口把一句话和链接给研究员 |
| 定 | 研究员 | 在对话里回话，或者在文档上批注后说“批完了”。要不要升级成决策项，他说了算；没说就照作者的建议 |
| 写回 | 入口 | 运行 `docs.py brief <链接或草稿> --words '<研究员的原话>' --apply`，研究员说了升不升级的加 `--promote 是` 或 `--promote 否`。原话写回文档，标题前加“已定”。再用一行告诉研究员这件升不升级，把原话交给路由转给作者 |
| 升级 | 作者 | 记的是升级的，运行 `docs.py brief <草稿> --package --apply`。脚本用简版决策的内容和研究员的原话生成一份决策包草稿，照它打印的三步上传、请书记员登记并确认“决定”、写回工作项 ID。登记请求里写上研究员选的是哪个选项 |

没定的和定了的简版决策，用 `ledger.py query briefs` 看；`ledger.py query queue` 也把没定的列在决策队列后面。

## 模板

```markdown
# 简版决策：<要研究员定什么，一个问句>

- 所属研究任务：#<研究任务的工作项 ID>（没有写“无”）
- 来源工作项：#<引出这件事的工作项 ID>（没有写“无”）

## 这是什么事
<用研究员没读过相关材料也看得懂的话写。>

## 为什么现在要定
<现在不定会卡住什么，卡到什么时候。>

## 选项和后果
- <选项 A>：<做了以后会发生什么，花多少时间或钱，能不能撤回。>
- <选项 B>：<同上；其中一个可以是“不做”。>

## 建议
<选哪个，为什么。>

## 定了以后谁做
<会话名，做什么。>

## 要不要升级成决策项
<“建议升级”或“建议不升级”，后面写理由。>

## 出处
<飞书文档链接；只在本地的材料，把要看的那几行抄在这里。>
```

## 填写规则

- 一份只讲一件事。几件事一起要研究员定，写几份，入口在对话里列成几行。
- 写到研究员不翻别的材料就能回答。出现的名词、编号、清单都在“这是什么事”里说清：是什么，在哪里，从哪来。清单逐条列出，不写“那十条”“在途的四条”。
- “选项和后果”只写选项，至少两个，一行一个，写成“- <选项>：<后果>”，不用表格，不写引言和子条目。升级成决策包时，每一行变成选项表的一行，“：”前面的字是选项名（不写“无”）。
- “要不要升级成决策项”以“建议升级”或“建议不升级”开头。定了以后别的会话还要照着做，或者以后还要回头查的，建议升级：新增或解除一条约束，把一件事推到某个时点再看，在两种做法里选了一种而后面的工作要建在它上面。只影响眼前这一步、做完就结束的，建议不升级。
- 有一个选项是不可逆的、要研究员亲手做的，或者改范围和规则的，不写简版决策，写决策包。
- 出处只给飞书链接。研究员打不开本地路径：只在本地的材料，把要看的内容抄进来。
- 不临时加栏目，栏目名照模板。传上去以后要改，改草稿再跑一次 `docs.py brief <草稿> --apply`，链接不变；研究员定了以后不再改，事情变了写一份新的。
- 文档标题由脚本写成 `<上传日期>｜简版决策（<会话名>）：<标题>`，定了以后前面加“已定｜”。
