# 用模板创建项目空间

初始化第 4 步用。`setup.py feishu --target <项目目录> --live` 报“没有叫“<空间名>”的飞书项目空间”时才创建；按名字查到一个就沿用，查到两个以上停下。

脚本不建项目空间：meegle 命令行管空间的只有 `project search` 这一条查找命令。所以这一步是界面操作，初始化里的界面操作也只有这一处。

## 模板从哪来

报错里带着链接和做法：“用模板建一个：打开模板 <链接>，点“使用模板”，空间名填“<空间名>”，“实例数据”勾选“视图”，其余用默认值；建好以后重跑这条命令。”

链接取任务文件的 `feishu.template_url`。没写就用约定文件里的参考模板链接，也就是插件 `orgspec/contract.json` 的 `template.url`。链接只记在约定文件这一处，技能和文档里不重复写。

## 用哪个工具

按顺序取第一个能用的：

1. Claude 自带浏览器。
2. Chrome 扩展。
3. 飞书桌面端加电脑控制。电脑控制点不了浏览器窗口，所以两种网页工具排在它前面。
4. 都用不了：把链接和空间名交给研究员，请他自己打开链接创建，建好说一声。

浏览器里还没登录飞书项目时，页面会要求登录。请研究员在那个浏览器里扫码一次，会话不输入账号和密码。

## 步骤

1. 打开模板链接。
2. 点“使用模板”。
3. 空间名填任务文件的 `feishu.meegle_space`，默认等于项目名。
4. “实例数据”勾选“视图”，页面上有“空间置顶”或“导航”的选项也勾上：模板里的“待定决策”视图和它在空间置顶里的位置这样才会带到新空间。其余选项用页面给的默认值。
5. 确认创建，等页面进入新空间。

“使用模板”之后页面上的字样和步数，以实际页面为准：这一段还没有在真实的初始化里走过。

操作时守这几条：

- 只做“使用模板”这一件事。不改模板，不改新空间的配置，不另建视图：视图只随模板带过来。
- 只建不删。建错了名字的空间留着，告诉研究员，删空间只能他本人做。
- 遇到升级提示、付费弹窗、权限申请或没见过的对话框，停下来问研究员。
- 同一个名字只建一次。点“使用模板”之前再查一次空间，查到已经有了就不再建。
- 每次点击之前重新看一眼页面，不沿用上一次的位置。

这一步的时间记在 `project_space` 里。研究员扫码登录、点浏览器许可的等待另记 `prompts`。

## 建好以后怎么核对

重跑预览：

```bash
python3 -I "$PLUGIN/scripts/setup.py" feishu --target <项目目录> --live
```

| 输出 | 意思 | 怎么办 |
| --- | --- | --- |
| “约定核对（contract_version 1）：通过” | 空间建好了，符合约定 | 接着做第 5 步 |
| 还是“没有叫“<空间名>”的飞书项目空间” | 没建成，或者实际的名字不一样 | 到页面上看新空间的名字。名字不同的，把任务文件的 `feishu.meegle_space` 改成实际的名字或 simple_name，重跑 `init --apply` 再预览 |
| “按“<空间名>”找到 N 个飞书项目空间，要正好一个。候选：…” | 同名空间不止一个 | 停下，把候选列给研究员。他选定后把 simple_name 或 project_key 写进任务文件 |
| “约定核对（…）：N 个问题，见 feishu/binding.md 的“要处理的问题”” | 建出来的空间和约定对不上 | 停下，把“要处理的问题”表交给研究员，由他转给模板维护者。不在网页上补 |

预览打印的 `feishu/binding.md` 里，“绑定结果”表该是五个类型都绑上：研究任务、同序列需求、跨序列需求、决策、反馈。“提醒”一节有六条“…的流程“…”还没有工作项，流程图读不到；登记第一条以后重读”：新空间里没有工作项，这是正常的。

## 没验证过的

| 假设 | 不成立时 |
| --- | --- |
| 界面操作能完成“使用模板” | 换下一种工具；都不行，请研究员自己打开链接创建 |
| 用模板建出来的空间通过约定核对 | 停下报出缺项，模板维护者修好模板以后重建空间 |
| 用模板建出来的空间，类型、角色和节点的标识和模板相同 | 绑定每次按这个空间现读，先认标识，再认名字。标识不同时按名字绑定，名字也对不上才要指认 |
| 勾选“视图”以后，“待定决策”视图和空间置顶跟着带到新空间 | 新空间里没有这个视图也不影响插件：入口照旧用 `ledger.py query queue` 列决策。研究员要这个视图的，由模板维护者照插件仓库顶层 `feishu-template/` 的搭建手册第 6 节在空间里补 |
| 别的企业的账号打开模板链接也能创建出同样的空间 | 那个企业照插件仓库顶层 `feishu-template/` 的搭建手册自建模板，任务文件的 `feishu.template_url` 指向它 |

搭建和修改模板归模板维护者，手册在插件仓库顶层的 `feishu-template/`，不随插件安装。
