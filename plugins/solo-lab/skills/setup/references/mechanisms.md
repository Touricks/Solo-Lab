# 组织设计怎样落到 Claude 桌面端

运行方式只有一种：会话池。每个角色是研究员在桌面应用侧栏里看得见的一个会话，委托、交付、登记都是会话之间的消息。

## 生成的目录

```text
<项目目录>/
├─ CLAUDE.md                     所有会话都要知道的：研究任务、职级、交接规则、命名、东西在哪、运行机制
├─ solo-lab.task.json           任务文件，初始化会话写的；改设置就改它，再重跑 init
├─ .env                          飞书项目和知识空间的两行链接
├─ .claude/
│  ├─ settings.json              权限（allow、ask、deny）和 hook 注册
│  ├─ agents/                    21 份角色定义：七个序列各三级；项目管理的 +1、+0 是 pmo-router、pmo-scribe
│  ├─ hooks/                     guard、audit、instances、inbox、feishu_cmd、pool，和它们读的 policy.json、lark-risk.json
│  ├─ solo-lab/
│  │  ├─ bin/                    orgspec.py、ledger.py、route.py、space.py、pool.py、project_paths.py、onboarding.py
│  │  ├─ orgspec/                规则文件、术语表和约定文件的副本
│  │  ├─ templates/              三种包的模板副本
│  │  ├─ pool-plan.json          开池清单：每个会话的标题、模型、开局句和预登记命令
│  │  └─ manifest.json           插件版本、启用的序列、规则、术语表和约定文件的哈希、每个生成文件的哈希
│  ├─ state/                     pool.json（认领表）、sessions/（各会话的状态）、onboarding.json（初始化计时）、gates.json（本地决策状态）
│  └─ logs/                      guard.jsonl（hook 的判断和提醒）、dispatch.jsonl（消息和认领）、compact/（压缩摘要）
├─ org/                          org.md（组织规则全文）、grants.md（授权表）、decisions.md、phases.md（研究任务的流程）
├─ packages/drafts/<序列>/       任务包草稿；drafts/pmo/ 里有首条研究任务单；packages/sent/ 是书记员的登记回执
├─ inbox/                        各会话的收件箱、飞书私聊消息
├─ spec/                         实验规格、评测协议、需求文档的草稿，和 task.json
├─ feishu/                       ids.json（绑定）、space.json 和 space.md（空间结构）、binding.md、写操作日志
└─ runs/                         运行记录
```

- 已有文件分三种处理。上次生成后没人改过的直接更新；本地改过的，新版本写在旁边的 `.new`，由研究员对照合并；`org/decisions.md`、`spec/` 下的三份文档、首条研究任务单和 `runs/README.md` 归研究员和各角色维护，建好以后 `init` 不再动；`runs/README.md` 是运行记录格式定下以后要往里写的文件，项目写进去的内容不算本地改动。`org/phases.md` 是生成的文件，里面是空间里的流程和“怎么推进”的规则：空间绑定以前 `init` 不动它；绑定以后，`init` 照项目里存的空间快照（`feishu/space.json`）和现在的规则把它整份重新生成，和 `setup.py feishu --apply` 写的一样，手工改过的内容会被覆盖。`org/decisions.md` 里“插件定下的几处安排”一节例外：它由规则文件的 `plugin_decisions` 生成，这一节还是插件某一版原样写的，`init` 原位换成新写法，文件其余部分一字不动；研究员改过这一节的，文件不动，新写法写进 `org/decisions.md.new`。
- `spec/task.json` 跟着 `init --task` 给的任务文件走。会话改不了它：要改设置，改任务文件再重跑 `init --apply`。
- 21 份角色定义不用来派子智能体。会话认领角色以后，hook 把对应的那份注入会话，当它的工作说明。
- `guard.py` 和 `policy.json` 要成对更新。两个都写成 `.new` 时一起合并，再重跑 `init`。`.claude/hooks/` 下的 hook 脚本共用 `pool.py`，也算一组：其中一个本地改过、新版本写成 `.new` 时，其余几个也写 `.new`，一起换上再重跑 `init`。

## 对照表

| 组织设计 | 在本插件里怎么做 | 依据和局限 |
| --- | --- | --- |
| 项目管理 +2 是研究员平时的入口 | 认领了 pmo-p2 的会话 `PMO-p2-01` | 入口长期运行，上下文会被压缩，所以它每次从台账、状态包和 `route.py pool` 读状态。研究员特殊情况下直接点开其余六个 +2 的会话，谈定的事仍写成决策包交给入口 |
| +2 → +1 → +0 逐级委托 | 入口给各序列 +2 的会话发消息，+2 给本序列 +1 发，+1 给本序列 +0 发。消息首行写抬头，正文在包文件里 | 派发图写在规则文件的 `dispatch` 一节。这是规范：对不上派发图的消息，收方的 hook 只提醒、记日志 |
| 跨序列只在 +2 之间 | +1、+0 要别的序列配合，写进交给上一级的交付包，由本序列 +2 发跨序列的需求包：先交路由查重、登记，拿到工作项 ID 后直接委托对方 +2，之后两个 +2 直接往来。书记员把这类工作项的回执另发一份给路由，`route.py cross` 从派发日志按工作项列出往来 | 1.0.11 及以前每条都经入口转手：一个真实项目一天 1217 条消息里，入口转另一个序列内容的约 108 条，路由 0 条。直连以后入口看路由的协调记录；日志只记每条消息的首行 |
| 书记员是台账和文档唯一的写入方 | meegle 和 lark-cli 的写命令、`ledger.py` 的写子命令只放行唯一认领的书记员会话；其他会话只能加带标签的评论。`ledger.py --apply` 还加文件锁，同一时间只有一个写入 | 所有会话用的是研究员一个飞书账号，飞书分不出是哪个会话，只能靠 hook 分权。hook 是防误操作的护栏：它按命令文本判断，刻意混淆的命令藏得过去，真正的边界是研究员账号的权限 |
| 委托 +1、+0 之前要有工作项 | +2、+1 把草稿交给书记员登记，拿到工作项 ID 再委托。登记请求写了“开工”的，书记员登记后接着确认“开工”这一步 | 排队还没委托的留在“待开工” |
| 会话名和会话标签 | 会话名在开局句里，写作 `Alg-p2-01` 这样的池位名。+0 干活时另有委托消息给的工作名 `Alg-p0-<工作项 ID>`。“负责会话”字段约定记池位名：需求包包头的接收方写了它就记它，没写才记工作名，脚本两个都认 | |
| 并行上限 | 每个序列 +2 一个、+1 最多三个、+0 最多五个会话，入口、路由、书记员各一个。任务文件的 `pool.max_sessions` 是全池的总上限 | 到了上限，`route.py expect` 拒绝预登记 |
| 研究员直接委托某个 +2 | 研究员点开那个会话，它运行 `route.py focus open` 标成“研究员在用”，`route.py pool` 这期间不推荐它 | 空闲 30 分钟后标记自动失效 |
| 不打断正在被研究员用的会话 | 用 `route.py notify` 写进它的收件箱，它下一轮开始时 hook 把未读消息加进上下文 | |
| 研究员在飞书私聊里发消息 | `route.py listen` 订阅机器人收到的私聊，写进 `inbox/feishu.jsonl`，入口下一轮看到 | 要研究员本人在终端里启动。`feishu/ids.json` 里没有研究员的 open_id 时不启动 |
| 没写进台账的决定不算数 | 研究员当面谈定的事写成决策包，渠道写“研究员主动发起”，书记员登记后接着确认“决定”这一步 | 靠规则和入口的收尾步骤保证，hook 拦不住口头决定 |
| 评测协议只读，可改范围只给工程 | hook 按任务文件的路径管编辑工具的写入：`protected_paths` 在池会话里一律拒绝，质量序列的会话和研究员自己的会话弹窗，要研究员确认（bypass 和 dontAsk 模式下也拒绝）；`editable_paths` 照规范只给工程序列，别人改了 hook 提醒。用 rm、mv、cp、重定向、sed -i 这类 shell 命令删改受保护路径，hook 不拦，权限照 Claude Code 自己的检查；规则照旧：只有质量序列能提出修改，改动要研究员确认 | hook 只看编辑工具。shell 命令和脚本自己在里面写文件，要靠运行环境的只读挂载；项目目录以外的评测数据 hook 管不到 |
| 不可逆的事要研究员批准 | 不可逆事项清单（`orgspec/irreversible.json`，生成在 `org/org.md`）是写决策包和判断可逆性的依据：九类，每一类写包括什么、对应哪几条判据。清单里的事要先有研究员批准、所选选项里列了它的决策再做；决策待定期间，包里“冻结的动作”谁都不做，所有池会话每轮看到一行冻结提示。包检查核对选项表：类别要在清单里，任一选项列了类别的决策包必须写不可逆，到期只能等研究员 | hook 不拦清单里的命令，也不按待定决策冻结：权限判断交给 Claude Code 自己的权限检查（研究员 2026-11-18 定），守规矩靠规则、每轮提示和包检查。可逆不可逆由决策包的作者按判据判断，清单是必须写不可逆的下限 |
| 高风险命令 | 项目权限拒绝 lark-cli 的 high-risk-write、带 `--yes` 的命令和登录、配置类命令，`guard.py` 再按风险表复核 | 本机 lark-cli 的版本和风险表对不上时，未知的写命令一律按写处理 |
| 身份 | 知识库、文档、云空间的命令显式带 `--as user`，收发消息带 `--as bot` | |
| 写操作留痕 | 直接调用的写命令由 `audit.py` 记日志，`ledger.py` 自己记 | 都写进 `feishu/write-log.jsonl` |
| 插件自己的脚本 | hook 只信任 `.claude/solo-lab/bin/` 下、内容和 manifest 哈希一致的脚本。改过的脚本里调用飞书命令行，一律按看不见的命令拦下 | 插件目录里的 `setup.py` 不在信任范围内。研究员的会话运行它，hook 读得到文件时会询问，bypass 和 dontAsk 模式下直接拒绝 |
| 跨阶段的记忆 | 各序列 +2 在 `.claude/agent-memory/<角色>/` 记要沿用的标准和判断 | 任务状态以台账和状态包为准 |

## 会话池

- **开池。** 会话按委托的方向一层开一层：做初始化的那个会话照 `setup.py pool` 的清单分批开出七个 +2，每个开出来先用 `detach_session` 移到顶层（和它自己同级），再用 `route.py expect` 预登记；+2 在首轮里开出本序列的 +1，+1 在首轮里开出 +0，入口下面是路由，路由下面是书记员。分批是因为应用有上限：会话自己开出的会话同时最多 5 个在跑，所有序列合在一起算，+2 移到顶层也不分开算；一批下面要开的会话不超过 4 个，默认分 3 批。应用还有一条总数上限：研究员每发一条消息以后，这样开出的会话最多 10 个。所以批再分成轮，一轮下面要开的不超过 8 个，默认 2 轮；一轮开完，做初始化的会话停下，请研究员回一句“继续开池”，再开下一轮。下面两级不归做初始化的会话管，它用 `setup.py pool --wait <秒数> --batch <第几批>` 等一批认领完、首轮都结束，再开下一批；最后用不带 `--batch` 的 `--wait` 等到清单里的会话都认领、书记员的首轮结束，没等到就列出还差谁、该由谁开。桌面端把一个会话嵌在开出它的会话下面，所以侧栏里是 +2、+1、+0 三层。默认 19 个：七个 +2、路由、书记员，外联以外的五个序列各一个 +1 和一个 +0。做初始化的会话开不了会话时走回退档：研究员手工新建七个 +2 会话，各粘贴一句开局句，往下的开法相同。被别的会话的消息叫起来的那一轮，桌面端不让开会话：下一级没开出来，或者以后要“补位”，都要研究员在上一级的会话里亲口说。
- **标题和分区。** 会话标题是 `[<飞书项目空间名>] <会话名>`，任务文件的 `pool.label` 可以另指前缀。会话都归入同名的侧栏分区，不置顶。做初始化的那个会话标题是 `[<名字>] Initialization`，它不是入口。标题只用来看，预登记和认领不依赖它。
- **认领。** 会话靠认领成为某个角色，认领要有许可。许可有两种：开局第一句“认领 <角色>（会话名 <名字>）”，只认 +2；或者开它的会话用 `route.py expect` 做的预登记。研究员的会话可以给任何角色预登记，+2 只能给本序列的 +1、+0，入口只能给路由和书记员。hook 把许可转正成认领，`route.py` 自己不写已转正的认领。认领表在 `.claude/state/pool.json`，`guard.py` 拦对它的编辑。
- **角色说明。** 认领后 hook 把角色定义注入会话；压缩、恢复、清空上下文以后再注入一次，带上未了事项，同一个会话的工作项写在一起（`#1、#2→<会话名>`）。压缩以后注入的内容末尾多一段：手上工作项所属的研究任务 ID 和读状态包的命令 `python3.12 -I .claude/solo-lab/bin/ledger.py status <研究任务 ID>`，命令只写一次。研究任务从本地的登记回执（`packages/sent/`）查，不连飞书；查不到的写怎么找、找不到就跳过，手上没有工作项的写不用读。入口例外：状态包由它维护，这一段不管它手上有没有工作项，都写用 `ledger.py query tasks` 列出没归档的研究任务、逐条读，一条都没有才跳过；它的未了事项只写属于哪几条研究任务。派发记录或回执读不了时，这一段换成一句“没能查出”，压缩摘要照记。各角色说明都有一条：压缩上下文以后、接着干活之前先读所属研究任务的状态包，状态包和手上任务包冲突时以状态包和台账为准。状态包由入口维护，交书记员用 `ledger.py status-block` 整段替换。PostCompact 事件把同一段提示打印出来，并和压缩摘要一起记进 `.claude/logs/compact/`。
- **认身份。** hook 先看调用是不是子智能体，再按会话 ID 找认领，再找许可。按桌面会话 ID 找到的认领，只有原来的会话因为清空上下文而结束、新会话是清空以后开局的，才接到新会话上。从池会话里起的进程带着同一个桌面会话 ID，不算这个角色，没有写权。都没有的是研究员自己的会话，它没有任何角色的写权。
- **工作目录。** 每个会话都在项目目录里开，不开 worktree。hook 在会话开始时记下工作目录，`setup.py check` 核对它等于项目目录。
- **委托。** 给对方的会话发消息，不用 Agent 工具派组织角色。先运行 `route.py pool --role <角色>` 找空闲的会话；没有空闲的就排队，工作项留在台账的“待开工”。消息首行写抬头，比如 `【委托 #2101】Alg-p2-01 → Alg-p1-01：需求包 <路径>`。收方的 hook 把收到的时间记进 `.claude/logs/dispatch.jsonl`，这就是回执。
- **状态。** 每个会话的 hook 维护自己的状态文件：在忙、空闲、后台任务在跑、等研究员批准、失败、离线。`route.py pool` 汇总，`--watch` 每 30 秒刷新，`--recover` 在重启后列出要接着做的事。
- **权限模式。** 全池和研究员的会话用同一类：bypass 和其他模式之间，会话的消息双向被扣下，桌面端弹不出审批框，默认 5 分钟后丢弃，保留期内切回同一类会补送；“每次询问”和 auto 是同一类。命令被拦下时不提升某个会话的权限模式：记进研究员任务清单，研究员在那个会话的窗口里说一句允许、说清是哪条命令，auto 模式放行这一次，或者由他在终端里跑。hook 记下每个会话的模式，`route.py pool` 和 `setup.py check` 标出不同类的。bypass 和 dontAsk 模式下，hook 本该弹窗询问的一律换成拒绝，理由里写“请研究员在自己的终端里运行”。 开池用 auto 模式：四轮现场测试都是 auto 模式，开会话不用研究员点。bypass 模式下，应用对每一次开会话都弹一张确认卡，只有 Deny 和 Allow once，弹在发起的那个会话里，+2 开 +1、+1 开 +0 也一样，默认的 15 个会话要点 15 次；这是应用有意留的确认，hook 放行也跳不过，插件不去绕开。`setup.py pool` 开池前读本会话的模式，是 bypass 就先提醒。

hook 只拦两类事：会损坏数据的，和研究员多半不在时向他提的问题。不可逆事项清单里的命令、删改文件的 shell 命令，hook 都不拦，权限照 Claude Code 自己的检查。其余是规范，`route.py audit` 汇总提醒：

| 哪些会话 | hook 怎么办 | 管什么 |
| --- | --- | --- |
| 任何会话 | 直接拒绝 | 用编辑工具改 `.claude/` 下的 hook、配置、角色定义、认领表和本地决策状态；用编辑工具改评测协议的只读路径，质量序列的会话和研究员自己的会话例外，它们的改动弹窗要研究员确认，bypass 和 dontAsk 模式下也拒绝；high-risk-write 和带 `--yes` 的飞书命令；派发时带 `name`；用 Agent 工具派书记员；不照规定写法的认领、预登记和释放；第二条入口或书记员认领 |
| 研究员的会话询问，别的会话拒绝 | 弹窗或拒绝 | 书记员以外的会话写飞书和台账；在共享工作区里切分支、stash、reset 或 pull；释放认领 |

## 待实测的假设

五轮初始化的现场测试和一次六个流程的测试是在 0.6.0 上做的，1.0.0 在一个真实项目上做过一次初始化，2026-11-15 用探针 hook 测过收尾工具和会话消息，逐项的记录在插件仓库的 `docs/Claude实测记录.md`。下表最后一栏是到 2026-11-15 为止的结果；没验证的，技能里涉及它们的步骤都写了不成立时怎么办。
