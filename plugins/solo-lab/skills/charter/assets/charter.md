# 研究任务单模板

研究任务单是“研究任务”工作项的主文档，一条研究任务回答一个问题。书记员用 `ledger.py register <草稿路径>` 登记：照标题和开头几行建工作项，把全文上传到知识库的“研究任务”节点下，再补上“状态包”和“交接记录”两节。

标题和开头几行是登记脚本的约定，行名和写法照模板，不改名、不挪到正文后面。

## 模板

```markdown
# 研究任务单：<任务名>

- 流程：验证
- 发出方：<序列> +2（<会话名>）
- 关联工作项：待建

## 目标
<一段话：这条任务要回答什么问题，为什么现在做，结果给谁用。点名涉及的数据、评测集、基线和代码版本。>

## 成功标准
<做成了算什么，写成数字或可检查的条件，在出结果之前写下。>

## 范围
- 包含：
- 不做：
- 停止条件：<到什么程度就不再追加投入>

## 资源上限
- 总预算初值：<数字和单位，比如 200 GPU 小时>
- 期限：
- 超出时：<谁叫停；追加预算要研究员决定>
- 执行环境：<待研究员确认；或者写定下它的决策 ID，比如“本机 Docker（决策 #2140）”>
- 计算资源：<待研究员确认；或者写定下它的决策 ID>

## 已知的上下文
<研究员已经知道的代码库、数据、评测脚本和公开数字在哪里，以前试过什么。只写位置和一句说明。>

## 风险和未决事项
<可能让这条任务做不成的事；研究员还没定的事写“待定”，注明谁在什么时候定。>
```

## 标题和开头几行

| 行 | 写法 | 脚本拿它做什么 |
| --- | --- | --- |
| 标题 | `# 研究任务单：<任务名>` | 冒号后面的任务名成为工作项名称；主文档标题是“工作项 <工作项 ID>｜研究任务单：<任务名>” |
| 流程 | `验证` 或 `试探`，只写一个。模板里先写着 `验证`，走试探流程的改成 `试探` | 新建工作项时选流程；空间里没有这个流程名，登记会停下 |
| 发出方 | `<序列> +2（<会话名>）`，比如 `产品 +2（Product-p2-01）`；研究员自己开的写 `研究员` | 序列名填“序列”字段，会话名填“发出方”字段；流程里由发出方负责的步骤，认的就是这个会话。写 `研究员` 的，序列记成项目管理，由发出方负责的步骤只有研究员能提 |
| 关联工作项 | 登记前写 `待建` | 登记后换成新建的工作项 ID；这一行写了别的内容，登记会停下 |
| 来源工作项 | 可选。接着前一条任务开的，在“关联工作项”下面加一行 `- 来源工作项：#<前一条的工作项 ID>` | 填“来源工作项”字段，`ledger.py trace` 沿它往回查 |

这几行都要写在第一个 `## ` 标题之前，每行以 `- ` 开头，行名后面用冒号。

登记前逐行核对一遍：

- 尖括号里的占位都换成了实际内容，标题里的任务名也是。
- “流程”只写了一个，而且就是要走的那个：流程是新建工作项时选定的。
- “发出方”要么以七个序列的名字之一开头、括号里是会话名，要么是 `研究员`。

## 正文怎么填

- 正文各节用 `## ` 标题。“目标”一节必须有：登记时脚本拿它当状态包的简介，路由靠简介判断一条没带工作项 ID 的信息归不归这条任务。所以目标写成一段话，把会被人提到的名字写进去，比如数据集、评测集版本、基线、节点编号。
- 其余各节没有内容写“无”，研究员答不上来的写“待定”，不替他编。
- 一条验证任务只回答一个能被一次冻结的评测回答的问题。写目标时发现有两个问题，拆成两份研究任务单，后一条用“来源工作项”指向前一条。
- 成功标准在出结果之前写下。验证流程第一步完成时要填“成功标准”字段，填的就是这一节；第 4 步研究员签字以后，它和目标一起冻结。具体的阈值和波动估计在第 4 步写进规格，这里写判据的形式和研究员已经确定的数字。
- 项目的第一条验证任务是“复现并测量基线”：成功标准写成和公开数字相差多少以内，后面的任务拿它的结果定阈值。
- 资源上限是初值。验证流程的总预算在第 4 步签字时定下并冻结；试探流程的总预算在第一步就要填，是这次试探的上限。“总预算”字段只收数字，单位写在这里和规格里。
- “执行环境”（本机、Docker、集群这类）和“计算资源”会定下付费运行所依赖的条件，属于不可逆事项的判据 4：写“待研究员确认”，或者写定下它的决策 ID。还没定的，由要用它的 +2 写决策包进决策队列，试探任务也一样；研究任务单里不替研究员限定，比如不写“不上集群”。登记时这两行写了具体内容却没有决策 ID，脚本会打印提示。
- 已知的上下文只记研究员已经知道的东西在哪里。整理文献和已有结果是验证流程第 2 步的事，由算法序列做。

## 试探流程的写法

试探流程用来找方向，不冻结、不签字、不出正式分，产出是值得验证的假设。用同一份模板，有三处不同：

| 栏目 | 试探流程怎么写 |
| --- | --- |
| 流程 | `- 流程：试探` |
| 目标 | 写想弄清什么。登记后第一步要填的“试探问题”取自这里 |
| 成功标准 | 写“无：试探流程不设判据”。要下结论时另开一条验证任务，来源工作项指向这条试探 |

每一步必填什么以飞书空间为准，登记后用 `ledger.py next <工作项 ID>` 看。
