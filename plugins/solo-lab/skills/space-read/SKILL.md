# 读懂空间

插件不内置流程。这个项目有哪些工作项类型、每类怎么走、每一步谁负责、要交什么，都在飞书项目空间里。`space.py snapshot` 把空间的结构读成两份文件：`feishu/space.json` 给脚本用，`feishu/space.md` 给人看。本技能做两件事：把快照读新，再照快照把空间讲清楚。

只想知道一条工作项走到哪一步、还缺什么，不用本技能，跑 `python3.12 -I .claude/solo-lab/bin/ledger.py next <工作项 ID>`。

## 先重读

在项目目录里运行：

```bash
python3.12 -I .claude/solo-lab/bin/space.py snapshot --target .           # 预览：读飞书，不写文件
python3.12 -I .claude/solo-lab/bin/space.py snapshot --target . --apply   # 写入 feishu/space.json 和 feishu/space.md
```

预览只跑只读的 meegle 命令。它打印两样东西：和上一份快照相比的变化，每条以“变化：”开头；各流程的表。照变化决定下一步：

| 预览里看到 | 怎么办 |
| --- | --- |
| 没有“变化：”行，本地已经有快照 | 快照是新的，不用写入，直接讲 |
| 本地还没有快照 | 加 `--apply` 写入 |
| 字段、选项、角色有增减或改名；“流程“…”的节点、负责角色或必填项变了” | 加 `--apply` 写入，再跑约定核对。流程或角色变了的，把变化告诉入口 |
| “状态改名 …” | 加 `--apply` 写入，再跑约定核对，它会报“空间里现在是…，绑定记的是…”。报给入口，请研究员重新绑定；在那以前，按状态查的台账查询用的还是旧名字，查不到东西 |
| “类型“…”没有了（或停用了）” | 先不写入，报给入口：这个类型在空间里被删了，或者被停用了。重新绑定用技能 `solo-lab:space-bind` |

写入以后跑一遍约定核对，它只看本地的快照和绑定，不读飞书：

```bash
python3.12 -I .claude/solo-lab/bin/space.py check --target .
```

最后一行以“通过”结尾就接着讲。列出问题的，报给入口，用技能 `solo-lab:space-bind` 处理。

开池时各会话同时开局，不用每个都重读。`feishu/space.md` 开头写着读取时间，是当天读的就直接照它讲。

命令没跑成时输出以“出错：”开头，退出码是 2：

| 输出 | 怎么办 |
| --- | --- |
| “feishu/ids.json 里没有 project_key：…” | 项目还没绑定空间。报给入口，请研究员照技能 `solo-lab:setup` 绑定 |
| “还没有 feishu/space.json：…” | 本地还没有快照，先跑 `snapshot --target . --apply` |
| “要给 --target <项目目录>” | 加 `--target .` |
| “运行不了 meegle …”“meegle … 失败（退出码 …）：…” | meegle 没装好、登录过期或者没有权限。重试一次，还不行就把原文报给研究员 |

## 再讲清楚

讲的依据是快照，用下面的命令看，或者直接读 `feishu/space.md`：

```bash
python3.12 -I .claude/solo-lab/bin/space.py show --target . flows     # 每个流程一张表：步、节点、负责角色、完成时必填
python3.12 -I .claude/solo-lab/bin/space.py show --target . fields    # 整份结构：流程，加每个类型的角色、状态、新建时必填和字段表
python3.12 -I .claude/solo-lab/bin/space.py show --target . binding   # 约定的槽位各绑到了哪个类型，字段、角色、状态各绑上几个
```

照这个顺序讲：

1. 空间名和快照的读取时间。
2. 在用的类型，每类有哪些流程。停用的类型提一句。
3. 每个流程照表讲：第几步、节点叫什么、谁负责、完成时必填什么。表是脚本读出来的，照它讲，不改节点名，不凭记忆补。
4. 负责角色对应哪个会话，见下表。
5. 每类新建时必填什么。登记草稿之前，这些要能从草稿里读出来。
6. 读不到的部分明说，比如哪个流程还没有工作项。

| 表里的负责角色 | 对应谁 |
| --- | --- |
| 序列名，比如产品、算法、项目管理 | 这个序列的 +2 |
| 发出方 | 工作项的“发出方”字段记的那个会话 |
| 承接方 | 同序列需求是“负责会话”字段记的会话，跨序列需求是承接序列的 +2 |
| 研究员 | 研究员本人，要有他的决定 |
| 书记员 | 书记员，每个流程最后的“归档”由它做 |

完成时必填里有“假设签字”“下一步签字”这类签字字段的步骤，要研究员先批准一条决策，把决策工作项的 ID 填进去。

按听的人挑重点：

| 听的人 | 重点讲 |
| --- | --- |
| 研究员 | 有哪几类工作项，各有几步；哪几步要他决定或签字 |
| 某个序列的 +2 | 负责角色是本序列的步骤，每步完成时必填什么；它发出的需求和它承接的需求，各在哪一步轮到它 |
| +0 | 手上这条需求走哪几步，哪一步归自己，完成时要交什么：下发的需求第一步是“定方案”，方案由它交、发出方确认 |
| 书记员 | 每类新建时必填什么，每个流程的最后一步是归档 |

## 快照里读不到的

- 流程图只能从一条工作项读出来。脚本给每个流程找一条走这个流程的工作项，从它读出节点。这个流程还没有工作项时读不到节点，表的位置写着“这个流程还没有工作项，流程图读不到；登记第一条以后重读。”这时只讲得出这个类型的字段、角色、状态和新建时必填，不拿别处的流程顶替。
- 读到的是那一条工作项的流程图。推进一条具体的工作项，以 `ledger.py next <工作项 ID>` 为准，它现读这条工作项自己的节点。
- 节点进行中时工作项显示哪个状态，快照里没有。状态和节点的对应是空间里的计算规则，命令行读不到；快照只列每个类型有哪些状态。
- 只有名字或系统标识对得上约定的类型读全了。其余类型只记名字，停用的类型单列。
- 快照是读的那一刻的结构。空间配置改了，快照不会跟着变，要重读。
- `org/phases.md` 是绑定时生成的研究任务流程对照，重读快照不更新它。研究任务的流程变了，报给入口，请研究员照技能 `solo-lab:setup` 重跑绑定。

## 模板维护者怎么用

核对一个模板空间合不合约定，不需要项目目录。这条命令只读飞书，什么都不写：

```bash
python3.12 -I <插件目录>/scripts/space.py check --space <空间名、simple_name 或 project_key>
```

退出码 0 是通过，1 是有问题并逐条列出，2 是命令没跑成。流程图要靠工作项才读得到，核对要在每个流程都有一条样例工作项的时候跑。

给模板写结构说明时，先把模板空间读成一份快照文件，再从它生成说明。快照文件里有空间的各种键，放在仓库之外；生成的说明不带任何键：

```bash
python3.12 -I <插件目录>/scripts/space.py export --space <空间名> --out <space.json>
```

```bash
python3.12 -I <插件目录>/scripts/space.py show --snapshot <space.json> structure
```

`<插件目录>` 是插件根目录，也就是本技能目录往上两级。

## 不做的事

- 不改空间配置。本技能只读。
- 读不到的流程不补。照参考模板猜出来的流程，和这个空间可能不一样。
- 不处理绑定。槽位没绑上、名字对不上，用技能 `solo-lab:space-bind`。
