# 更新记录

## 1.1.0（2026-11-21）

符合 `contract_version` 2。在 2.2.0 的模板空间上改：18 处改名，同序列需求的第一个节点改成“定方案”。另发成新模板“Solo-Lab Template v3”，链接换新，给插件 1.1.0 及以后用。2.2.0 的模板（模板中心里叫“Solo-Lab Template v2”）和链接原样保留，给插件 1.0.5 到 1.0.12 用：它们初始化时生成的研究任务单写着“流程：验证”，在这一版建的空间里登记不上。

从这一版起，模板的版本号和插件对齐（研究员 2026-11-21 定）：这一版从插件 1.1.0 起用，所以叫 1.1.0，数字比上一版 2.2.0 小。规则见 [README.md](README.md) 的“版本规则”。

- 研究任务的两个流程改名：“验证”改成“正式实验”，“试探”改成“探索”。
- 六个节点和同名的状态改名，节点 ID 不变：准备上下文改成前期调研（`prep_context`），准备 PRD 和 Eval Set 改成定需求和评测集（`prep_prd_eval`），确定假设条件改成假设评审（`set_hypothesis`），跑 Eval Set 改成执行离线评测（`run_eval`），下一步讨论改成决定下一步（`next_step`），探索流程里的试探改成探索（`probe`）。
- 三个字段改名，对接标识不变：上下文文档改成调研文档（`context_doc`），试探记录改成探索记录（`probe_record`），试探问题改成探索问题（`probe_question`）。
- “去向”字段的选项“转验证”改成“转正式实验”。
- 研究任务这个类型的描述改成“主线：正式实验（九步）或探索”。
- 同序列需求的第一个节点“开工”改成“定方案”，节点 ID 不变（`started`）：负责角色从承接方改成发出方，完成表单必填新加的链接字段“方案”（对接标识 `plan_link`）。状态不动，这个节点进行中仍是“待开工”。插件 1.1.0 起各序列只有 +1 和 +0 两级：下发的需求由承接的 +0 先交方案，发出方 +1 确认这个节点以后才执行。约定里多一个字段槽位和一条方案关，`contract_version` 升到 2。
- 用 2.2.0 建的空间要和 1.1.0 一致，在空间配置里把上面 18 处逐个改名，都在原对象上改，不新建也不删除；再给同序列需求加“方案”字段，照[搭建手册.md](搭建手册.md)第 4 节把第一个节点改成“定方案”。这些改动和插件升到 1.1.0 放在同一次做，做完重新绑定一次（`space.py feishu --target . --live --apply`，由研究员的会话或初始化会话运行）：约定多了一个字段槽位，只重读快照不够。在途的工作项不要点“模板升级”：它们的节点名一直显示旧名字，流程名、状态、字段和选项显示新名字，照常能往下走。

## 2.2.0（2026-11-16）

符合 `contract_version` 1。在 2.1.0 的模板空间上改，另发成新模板“Solo-Lab 科研模版”，链接换新。2.1.0 的模板和链接原样保留，给插件 1.0.4 及以前用。

- 决策新增两个文本字段：“执行方”（研究员或会话名，对接标识 `executor`）和“研究员要做的事”（多行文本，`researcher_action`），都不必填，放在详情页基本信息的末尾。插件 1.0.5 起登记决策时按名字写这两个字段。
- 决策的状态“已决定”改名“待执行”，标识不变。决策走待决定、待执行、归档三个阶段：确认“决定”以后进入待执行，执行完才归档。插件 1.0.4 及以前按名字找“已决定”，用 2.2.0 建的空间绑定不上，所以另发新模板；1.0.5 起两个名字都认。
- 新增公开视图“待定决策”，放在空间置顶：状态为待决定，或者状态为待执行且执行方是研究员；先按紧急程度、再按创建时间排序。
- 决策的默认表格列改成名称、状态、紧急程度、执行方、研究员要做的事、发出方、创建时间、主文档。
- 用 2.1.0 建的空间要和 2.2.0 一致，照[搭建手册.md](搭建手册.md)第 2 节加两个字段，第 4 节把状态“已决定”改名“待执行”，再照第 6 节配详情页、表格列和视图。不改也能用插件 1.0.5，只是没有这个视图和两个字段。补完以后，已经绑定这个空间的项目还要做一步，插件才认得：只加字段和视图、状态没改名的，任何会话重读一次快照（`python3.12 -I .claude/solo-lab/bin/space.py snapshot --target . --apply`）；状态改了名的，研究员的会话重新绑定一次（`setup.py feishu --target <项目目录> --live`，核对后加 `--apply`），它同时重读快照。不做的后果和核对办法见 [README.md](README.md) 的“老空间补到 2.2.0”。

## 2.1.0（2026-11-13）

符合 `contract_version` 1。在 2.0.0 的模板空间上改，模板中心的链接不变。

- 研究任务去掉字段“试过的变体数”，验证流程第 7 步“跑 Eval Set”的完成表单只剩“运行 ID”。这个数只在一类研究里有意义：每个项目的首条任务是复现并测量基线，没有变体可数；也没有脚本或决定用到它。成本看“总预算”和“已用预算”，每个变体的结果和运行 ID 列在交付包里。
- 用 2.0.0 建的空间里这个字段还在，第 7 步仍然要填。要和 2.1.0 一致，在空间配置里把它从“跑 Eval Set”的完成表单里去掉。

## 2.0.0（2026-11-12）

符合 `contract_version` 1。在空白空间里从头搭建，和 1.0.0 没有继承关系。2026-11-12 发布到模板中心，模板名 research_template。

- 五类工作项都用节点流程：研究任务、同序列需求、跨序列需求、决策、反馈。“项目”和“送审”两类不再有。
- 研究任务有两个流程。验证流程九步加归档，第 4 步和第 9 步各要一条研究员批准的决策；试探流程四步，不签字、不出正式分。
- 每个流程以“归档”节点收尾，由书记员确认。
- “阻塞”从状态改成两个字段：阻塞原因、阻塞开始日期。
- 需求上不再有送审包、验收结论、验收包三个字段；决策去掉“默认处理”和“已过期”状态，新增“签字结果”。
- 四类工作项用文本字段“所属研究任务”指向研究任务，取代“所属项目”。
