# 搭建手册：从空白空间搭出模板 v2.1.0

照这份手册在飞书项目里搭出的空间，结构和参考模板相同，能通过插件的约定核对。模板中心的链接用不了的企业，照它自建。每个流程的节点、负责角色和必填项列在[结构.md](结构.md)，这里讲顺序、每样东西怎么配、哪里容易配错。

实测工作量：全程约 2300 次界面动作（点击、输入、拖动、滚动），3.5 小时；其中流程约占一半。

## 搭什么，不搭什么

只配四样：工作项类型、字段、节点流程（含角色和状态）、新建页。视图、详情页的其余布局、表格列、权限、自动化和插件都用飞书的默认值。

顺序从简单到复杂：决策、反馈、同序列需求、跨序列需求、研究任务的试探流程、验证流程。每搭完一个流程，用一条工作项从第一个节点走到“归档”再回滚一次，走通了才搭下一个。

## 1. 空间和类型

1. 用空白模板新建空间。实例数据里的“视图”“工作项实例”都不勾。
2. 新建五个类型，流程模式都选**节点模式**（建好以后改不了），系统标识照填：

| 类型 | 系统标识 |
| --- | --- |
| 决策 | `decision` |
| 反馈 | `feedback` |
| 同序列需求 | `same_seq` |
| 跨序列需求 | `cross_request` |
| 研究任务 | `research_task` |

3. 停用自带的“需求”“缺陷”：空间配置里工作项卡片右上角的菜单，点“禁用”立即生效。“任务”是节点上的子任务类型，停不了，留着不影响。

## 3. 角色

节点的负责角色要先在类型的“角色管理”页建好。只填名称和角色 id，其余用默认值。

| 类型 | 角色（角色 id） |
| --- | --- |
| 决策 | 研究员（`researcher`）、书记员（`scribe`） |
| 反馈 | 项目管理（`pmo`）、书记员（`scribe`） |
| 同序列需求、跨序列需求 | 发出方（`issuer`）、承接方（`assignee`）、书记员（`scribe`） |
| 研究任务 | 产品（`product`）、算法（`alg`）、工程（`rnd`）、基础设施（`infra`）、项目管理（`pmo`）、发出方（`issuer`）、书记员（`scribe`） |

研究任务上不建质量、外联两个角色：两个流程里没有节点由它们负责，它们的活用跨序列需求派。

## 4. 流程

每个流程的节点、节点 ID、负责角色和完成表单的必填字段照[结构.md](结构.md)。配每个节点时：

- 完成方式选“单人确认完成”。新类型自带的第一个节点默认是“自动完成”，要改。
- 负责人选“与角色联动”，再选联动角色。每个节点正好一个角色。
- “节点字段必填”里默认带“负责人”，去掉。不配排期、估分、节点任务和显示条件。
- “完成操作授权角色”保持默认（节点负责人、管理员、创建人）。
- 每个流程的第一个节点 ID 固定是 `started`，改不了；新增节点的节点 ID 照结构表填。最后一个节点是“归档”，节点 ID `archive`，角色是书记员。
- 流程都是直线：一个节点接一个节点，没有并行，也没有按条件出现的节点。

研究任务有两个流程。类型自带的那个在“基本信息”页签改名为“验证”；再新建一个流程叫“试探”，新建时关掉“复用”。其余四个类型各用自带的一个流程。

状态在“状态计算规则”里配，可以在规则的状态下拉里直接创建。规则从上到下匹配，每个节点一条“该节点进行中 → 某状态”，最后一条是“归档节点已完成 → 归档”：

| 流程 | 节点进行中时的状态（依次） | 归档节点已完成 |
| --- | --- | --- |
| 决策 | 决定：待决定；归档：已决定 | 归档 |
| 反馈 | 解析：待解析；归档：已处理 | 归档 |
| 同序列需求 | 开工：待开工；执行：执行中；验收：待验收；归档：已验收 | 归档 |
| 跨序列需求 | 提出：已退回；接单：待接单；执行：执行中；验收：待验收；归档：已验收 | 归档 |
| 研究任务·试探 | 定方向、试探、提出假设：状态和节点同名；归档：已结束 | 归档 |
| 研究任务·验证 | 九个步骤：状态和节点同名；归档：已结束 | 归档 |

状态是类型级的：研究任务的两个流程共用“已结束”“归档”。状态名要和上表一字不差，插件按名字找“待决定”“已决定”“待开工”“执行中”“待验收”“已验收”“已退回”“待接单”“归档”。

## 5. 新建页

新建页和详情页同步：先把字段放进详情页布局，再在字段的“新建页配置”里把“是否必填”设成必填。

| 类型 | 新建时必填 |
| --- | --- |
| 决策 | 序列、发出方、主文档、紧急程度 |
| 反馈 | 主文档 |
| 同序列需求 | 序列、发出方、负责会话、主文档、所属研究任务、关系 |
| 跨序列需求 | 发起序列、承接序列、发出方、主文档、所属研究任务 |
| 研究任务 | 序列、发出方、主文档（流程类型是新建时自带的必选项） |

## 6. 容易配错的地方

- 完成表单里一个分组只放一个字段。把字段拖到已有字段那一行，有时并排、有时插到上面、有时不生效；先点“添加新分组”，再把字段拖进空分组。
- 设完“必填”等两三秒，看到下拉框显示“必填”再点确认。马上确认，这一项可能没设上。
- 选完“与角色联动”等下拉展开再选联动角色，选完看一眼“选择联动角色”那一栏。
- 状态规则的目标值下拉刚展开时选项会跳，紧跟着点会点到下一项（“进行中”点成“已完成”）。每条规则配完读一遍规则文字。
- 字段名相近的（规格和规格版本、运行 ID 和冒烟运行 ID、结论和结论文档），在搜索结果里看清再拖。
- 流程改名的保存按钮要等它亮了再点。保存流程以后新建一条工作项，看状态是不是第一个节点对应的那个。

## 7. 走通和核对

每个流程建一条工作项，逐个节点确认到“归档”，中间回滚一次。要看到这五件事：

1. 缺新建页必填字段的新建被拒绝，不产生工作项。
2. 新建后状态是第一个节点对应的状态，每个节点都有负责角色。
3. 有必填项的节点，缺项时确认被拒绝；填齐后确认成功，状态按规则变化。
4. 回滚要写原因；回滚后状态回到被退回的节点，后面的节点回到未开始，已填的值还在。
5. 确认“归档”后状态是“归档”。

命令行的写法（字段值都传字符串，日期传毫秒时间戳的字符串）：

```bash
meegle workflow get-node --project-key <空间> --work-item-id <ID>
```

```bash
meegle workflow list-state-required --project-key <空间> --work-item-id <ID> --state-key <节点 ID> --mode unfinished
```

```bash
meegle workflow transition --project-key <空间> --work-item-id <ID> --node-id <节点 ID> --action confirm
```

```bash
meegle workflow transition --project-key <空间> --work-item-id <ID> --node-id <节点 ID> --action rollback --rollback-reason <原因>
```

六个流程都走通以后，跑约定核对：

```bash
python3 -I plugins/agent-org/scripts/space.py check --space <空间名>
```

流程图只能从一条工作项读出来，所以核对要在样例工作项还在的时候跑。输出“约定核对：通过”以后，照[README.md](README.md)“改模板”一节把结构快照读下来、重新生成[结构.md](结构.md)，再在网页上删掉样例工作项，然后发布。
